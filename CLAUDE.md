## What it is
Caspien: a systems language for auditable code (ownership storage `owns/ref/raw/auto/static`, no GC, proofs via `match`, `unsafe` for the rest). Four-stage compiler, plain JDK, no dependencies:
1. `ASTGenerator` -> higher-order bytecode (HOB, text). Lex, parse, RPN, tree, imports, dup/generics expansion, type check, emit.
2. `Optimizer` -> HOB passes (folding, inlining, unrolling, dead code, struct unpacking/reordering, `SizeofResolutionPass`...).
3. `LowerOrderGenerator` -> low-order bytecode (LOB): address lowering, register-form, register variables, fusion passes.
4. `Codegen` -> x86-64 asm (`X86Backend`), assembled/linked with gcc/as.
`Compiler.java` orchestrates all four and runs them through a content-addressed stage cache (`CompilerCache.java`, `.cache/`, keys chained like a Merkle tree; `--no-cache`, `--cache-report`, `--clear-cache`; details in `docs/COMPILER_REFERENCE.md`); `toolchain.config` selects target and every optimizer switch. Stdlib in `stdlib/`, examples in `docs/examples/`, tests in `tests/`, benchmarks in `benchmarks/`.

Benchmarks: `--no-cache` always; quick mode reuses other languages' builds from `benchmarks/.build_cache`.
- LEAK CHECK (7 Oct): `run_tests.py` runs every program under `tests/alloc_shim.c` (LD_PRELOAD; `GT_ADDR`/`GT_EXE` from `nm`) and reads the program's own ghost table at exit: a passing program with blocks still registered FAILS (`tests/leak_allow.txt` lists deliberate leakers, empty; `--no-leak-check` skips). Valgrind CANNOT see these leaks (the table keeps every registered block reachable, so they are "still reachable"). - Benchmark VM noise is ~10-30%; use best of 3-5, same-run ratios. `benchmarks/run_all.py` runs all programs: `quick` (default: optimised Caspien only, measured first; other languages killed at the slowest optimised Caspien time and listed as "would have taken longer than optimized Caspien") or `--mode full` (everything, no cutoff; use for published numbers).

## Language facts worth knowing (details in ASTGenerator/CLAUDE.md)
- Every non-`@untyped` struct has a hidden 8-byte `___type` class id at offset 0 (first member in declaration, construction and layout).
- Structs are padded C-like; `sizeof` is symbolic until the Optimizer resolves it.
- `throw`/`try`/`catch(e)`/`?`/`continue` are safe code; functions that throw need `@throws`; every call to one needs try/`?`. Message travels via `gt_error_message` (rbp-16) and `GT_UNWIND MSG`.
- Integers: literals adapt to the slot type; `match x fits T`, `wrap:<T>`, `sat:<T>`; full bitwise builtins (`bits_and/or/xor/not/left/right`), one shift rule (count >= width gives 0 / sign fill).
- `continue` = next iteration in a user `for`/`loop` (`isLoopContinue`; innermost construct wins: a catch body's own `continue` skips its try block, a loop opened inside the catch owns its `continue`, `match @lock` CLOSED retries, OPEN rejects). `for` gets a `@for_cont_N` label before the step only when a `continue` uses it.
- `match @lock` on swap-mutex structs: every CLOSED path ends in `continue|break|return|throw`; lock released on throw unwinds.
- Safe dynarray header is `[len][cap]` (16 bytes). `resize` is amortised: a growth past `cap` reallocs to max(newCount, 2*cap), one that fits only rewrites `len` (no realloc, ghost table untouched), one leaving under cap/4 in use reallocs down to newCount; `clone` gives the copy cap = len. `DynamicArray.pushBack` and `String.appendChar` therefore cost O(1) amortised. Tests `dyn_growth_test` (+ `_check.sh`: realloc count under `tests/alloc_shim.c`, valgrind).
- Stdlib `HashMap<T>` (rewritten 4 Oct): capacity rounded up to a power of two (0 stays 0 = ignores every `set`), grows by doubling at 70% load (an out-of-memory growth is swallowed: `set` carries on in the old table), one control byte per slot beside the 16-byte entries, hash = one multiply + xor-shift (`hashKey`, not `insecure_hashOf`). `String.concat`/`sub` copy in bulk. Tests `hashmap_growth_test`, `string_bulk_test` (+ `hashmap_growth_check.sh`).
- Struct returns use RVO (hidden `$ret_dest`); legal only at `let` RHS, bare-variable assignment RHS, or `return f()`.
- Generic impl methods are checked lazily; `DynamicArray<S>` for a struct uses the `...Ptr` twins.
- `deref(p)`/`clone(p)`, division, float operations (`assume match x : finite`) and `@lock` method calls need a proof (`match`), or `assume match` in an `unsafe assume{` block (any expression allowed, e.g. `assume match Some(p+i)`); `unsafe` relaxes nothing else for them. `deref` is never an assignment target.
- Statement `unsafe` blocks must name exactly the reasons they need: `extern memcopy raw deref clone global loop udyn udyn:owns assume call asm async guard swap file unaudited` (`deref`/`clone` = deref/clone of a `raw` pointer, needed even when proven); missing/extra/bare = error, except `unsafe unaudited{`: the catch-all, written alone, accepted whatever the block needs (and when it needs nothing); the stdlib folder may never use it (compile error; `tests/unaudited_stdlib_check.sh`). Root-level `unsafe{}` declaration blocks stay bare. Compiler-written blocks are exempt (`synthesizedUnsafe`). `CASPIEN_UNSAFE_REPORT` env lists needed tags; `tests/unsafe_tags_migrate.py` retags.
- Stdlib allocation goes through ghost table (`gt_init/gt_register/gt_alive_check/gt_destruct/gt_moved`, forced literal symbol names; `gt_moved` = unregister without free, required wherever `gt_init` is); the table is an open-addressing hash set (O(1) expected; `tests/gt_hash_test.caspien`, model `gt_hash_model.py`); the old linear-scan version lives in `stdlib/gt_linear/` (import its `gt_*.caspien` instead; never mix). `gt_moved` must never shrink/grow the table (`resize` relies on it).
- Recursion only via `@recursive` tail self-call (lowered to a bounded loop). Recursive structs are rejected EXCEPT through a plain nullable `ref` member (`next: ref mut Node`; `TypeChecker.detectStructCycle` skips only `ref` without `some`): a member that refers back to its struct through `ref some`, `owns`, `raw`, `auto` (directly or via other structs) is still an error (`tests/ref_recursive_*_error_test`). Nodes must be owned elsewhere (e.g. a dynarray of `Holder{n: owns mut Node}`, linked with `ref v[i].n`, which needs a proven index); a ref to a dead target is skipped by `match Some`. Test `ref_recursive_test` (+ `.py` model, `_check.sh`). Benchmarks: `*_ref_*` (graph, binarytrees, lru) and `*_refstd` (lru/knucleotide naive with `stdlib/ref/hash_map.caspien`, the chained `ref`-node HashMap; import it INSTEAD of `hash_map.caspien`; tests `hashmap_ref_growth_test`, `stdlib_ref_test`, `perf_codegen_ref_test`, `ref_variants_check.sh`); the ref variants are 5-15x slower (one alive check per `match Some`, a ghost-table probe), see `benchmarks/RESULTS.md`.
- `clone`/growing `resize` of an owning struct with a NULL `owns` leaf is legal (the leaf stays null, `CloneGenerationPass`); a bare generic struct name with an underscore as dynarray element (`Slot_u64`) parses as a base type (`CanonicalType.parse`: a mutability prefix must be `mut|imut|indeterminate`); test `generic_owning_dyn_test` (+ `_check.sh`).

- `@drop func f(r: ref some mut S)` on a struct's cleanup: the generated `__drop_S` calls it with the struct's address just before the owns value is freed (scope end, throw unwind, member, dyn element). One hook per struct, no `@throws`/`@async`; `clone` of any type that reaches a `@drop` struct is an error. Tests `drop_hook_test`, `drop_hook_*_error_test`.
- File system (`stdlib/fs.caspien`, portable layer; OS calls in `fs_linux.caspien` / `fs_windows_gnu.caspien`, chosen by `import "fs_{target}.caspien"`, `{target}` from `ASTGenerator/platform.config` that `Compiler` writes). Static methods `Dir.root/rootRW/rootAny/sub/make/removeFile/removeDir`, `File.open/tempFile/commit/writeText/sync/readAll`; names are single components, symlinks never followed, `Dir`/`File` close via `@drop`. Optional `===fs.config===` section of `toolchain.config` (-> `ASTGenerator/fs.config`, `FsPolicy.java`): `fs-roots: path:rw|r,...` (literal `Dir.root("..")` args checked at compile time through the `@fs_root`/`@fs_root(rw)` decorator; `new RootPath(path)` checks the table at run time, the table is embedded through the lexer constant `__FS_ROOTS`; read-only `Dir`s refuse writes) and `fs-deny-externs` (user externs incl. `@link_name` targets; stdlib exempt). `@fs_unsafe` (`Dir.rootAny`) needs `unsafe file{}`. `--fs-report` prints roots/opens/unsafe uses. Not covered: `unsafe asm`, `call()`, externs off the list. Tests: `fs_check.sh`, `fs_policy_check.sh` (Linux, valgrind), `fs_wine_check.sh` (Windows layer under Wine only; symlink/junction refusal there is NOT testable and real Windows has never run it).

## Component state (verified on Linux; windows_gnu also run under Wine)
- Register-form, register variables (r13/r14/r12 callee-saved + r8-r10 in call-free regions), xmm float temps/variables, float constant pool, indexed addressing, range-end promotion, branch fusion, jump cleanup, strength reduction: always on in code, gated by `toolchain.config` switches.
- `hoist-array-bases` (shipped off; `LoopHoistPass`, details in `LowerOrderGenerator/CLAUDE.md`): in a loop that never writes a safe-dynarray local's slot, the pointer is copied once into a register candidate; a copy that gets no register is undone. `R_LEA` with the 16-byte header displacement now fuses into `R_LDI/R_STI` (always on). Paired gains on the safe programs 3-9% (graph_struct, lru, knucleotide, strings), none slower; tests `loop_hoist_test` (+ `_check.sh`, `loop_hoist_passes_check.sh`). Not done: hoisting the length word, struct-member dynarrays, copy-chains of hidden inline slots (see cause 2).
- `variables-in-alloc-functions` (shipped off): functions with `new`/`resize`/`clone`/wide `DOT` may keep variables in r12-r14; Codegen saves/restores them around those instructions (`@@V1314S@@` marks). Paired gains on safe programs up to 20% (sieve_safe, json_serde_safe), none slower in the first runs; tests `alloc_vars_test`, `alloc_vars_check.sh`, `alloc_vars_passes_check.sh`.
- Callee-saved registers are saved/restored per function (`finishCalleeSaved`).
- Optimizer inliner handles throwing callees, owns-moves, `@lock` leaves; `inline-max-multi-callee-lines` (1000) refuses a >1000-line callee at more than one call site.
- Bounds-check/field-access instruction fusions (always safe to leave on, gated by `fuse-length-compare` / always): `R_BRCM` memory length compare, `R_LDD/R_STD` displacement forms; `variables-in-arg-registers` (shipped off) adds rsi/rdi variable registers (gain only on merkle, -9%). Hidden-slot copy forwarding (naive stdlib path) and `d.backing` hoisting were evaluated and NOT done: displacement fusion cut instructions but binarytrees_naive stayed latency-bound, so no measurable gain.

- **`@pure` / `@pure(rt)` / `@non(deterministic)`: front end IMPLEMENTED 6 Oct** (TypeChecker bans + `tests/pure_*_error_test`, `non_arg_error_test`, `pure_rt_test` (+ `.py` model), `pure_rt_check.sh`; Linux 4-config sweep clean, Windows/Wine not run). NOT done: the rt compile-time evaluator and folding, inferred call-graph non-determinism (rt is closed under checking, so only explicit `@non(deterministic)` is tracked), `--rt-report`, tabulation. Design as settled:
  - Plain `@pure` (changes): NO `unsafe` block of any kind (compiler-synthesized exempt; check stdlib/examples for existing `@pure` + `unsafe` first), NO `match @lock` (acquiring writes the mutex and blocks), no `par`/`await` (threads). Heap allocation (`new`, `dyn`, `resize`, `clone`) stays allowed: allocation is NON-DETERMINISTIC (outcome depends on heap state, out-of-memory is part of program semantics), not a side effect. Existing bans stay (extern, `call`, `throw`, mutable global read, write through pointer).
  - `@non(deterministic)`: marks a function whose result may differ for equal arguments. Built-in non-deterministic primitives: `insecure_rand()`, `new`, `dyn`, `resize`, `clone` (`par`/`await` are banned outright). It POISONS the call graph: anything that calls one is non-deterministic transitively (default: inferred by the compiler, not required to be written; so `@pure` may still call them). Cannot be combined with `@pure(rt)` on one function.
  - `@pure(rt)` (referentially transparent) = `@pure` plus: no reads through pointers, no `static`/global reads at all (not even `imut`), no allocation, callees only `@pure(rt)` (so never anything non-deterministic). Every loop is then a `for` range or `@recursive` bounded loop (no `unsafe loop`, no `@lock`), termination is guaranteed and the ONLY limit on folding an rt call with literal arguments to a constant is a large loop bound / recursion depth (evaluator step budget, e.g. `rt-eval-steps`). An rt call with literal arguments that does not fold is an optimizer gap (`--rt-report` lists it and why).
  - Plan: HOB compile-time evaluator matching runtime semantics exactly (wrap widths, shift rule, division proofs; no libm folding), plus a differential test (evaluator vs binary); tests for every ban (`*_error_test`). Found 5 Oct (type-check probes only): the pre-change `@pure` accepted `unsafe asm`, `memcopy`/`swap` writes through pointer parameters, `unsafe async`/`await`, `match @lock`, `unsafe udyn`/`loop`; README's "unsafe does not lift any of that" must be updated with the change.
- **Design SETTLED 6 Oct (owner), to be implemented later: slab ghost table (`stdlib/gt_slab/`, a third `gt_*` variant beside the hash set and `gt_linear/`) and redundant-`match Some` elision.**
  - Slab variant: one big reserved address region cut into fixed-size slabs (e.g. 64 KiB), each serving ONE size class for small objects; large blocks (dynarray backing, anything over a size limit) stay in the existing hash set. `ref` stays a plain 8-byte pointer, no ABA change (a freed address reused looks alive, as today). `gt_alive_check(p)`: `off = p - region_base`, out of range -> dead; `slab = off >> 16`; `info = directory[slab]` (the directory = a small array, one entry per slab: size class + liveness-bit pointer, like a page table); `idx = (off & 0xFFFF) / size`; alive = that bit. One bit per object, no hashing/probing, same-size nodes contiguous. `gt_register/gt_destruct/gt_moved` set/clear the bit; slots reused through per-class free lists. Needs a `gt_alloc`-style hook because Codegen calls `malloc` directly at `new`/`dyn`/`clone`/`resize` sites (to design: `resize` of small blocks, thread safety of the bits for `par`, size-class table, region size/failure fallback). Do FIRST (to confirm the cause): time the ref graph benchmarks with the alive check compiled out, and with nodes bump-allocated contiguously, plus callgrind cache misses; the slab design is the fix only if the check dominates.
  - `match Some(x)` elision: the alive check runs once per `match Some`, not per deref, so nothing inside a match body is rechecked. Elide a LATER `match Some(x){..}` on the same ref `x` when nothing between the two can invalidate the proof: no call that may reach `gt_destruct` (call-graph analysis), no `resize`/scope-end drop/assignment of the owner, no reassignment of `x`, no `par`/threads in play; the body of the second match is then emitted without the probe. Free optimization even if the current benchmarks do not gain (each BFS neighbour is a different node).

- `clone(p)`: deep copy via generated `__clone_<T>` routines (each owns leaf cloned into a hidden local, registered, then the copy assembled; any failure `GT_DESTRUCT`s the locals and returns null, so no leak). Safe dynarrays clone with `CLONE_DYN` (runtime size) or, when elements are owns pointers, a generated loop. Dynarrays whose elements own memory (owns pointers, or INLINE structs with owns members): `dyn([h1, h2])` copies each element at its full size (`NEW_DYN` stride = pushed bytes / count); scope end drops each element (`DropGlueGenerationPass`); a shrinking `resize` drops the cut-off elements first (`GT_DESTRUCT_TAIL`, emitted only for owns-bearing element types); a growing `resize` replaces the bitwise-copied new slots by deep clones (`CLONE_FILL`; the fill value stays with the caller and every new slot is a clone, an inline fill likewise, never consumed); inline elements are cloned by `__clone_value_T(dst, src)` (RVO-style, returns 1/0; a failure cuts the new array down to the elements made and destructs it). Tests: `dyn_owning_elems_test` (+ `_check.sh`, valgrind), `dyn_owning_oom_check.sh`. An INLINE struct that owns memory (`isInlineOwningStruct`: no storage keyword, some owns member, recursively) is an owned slot like an `owns` local: dropped at scope end (`GT_DESTRUCT name`, expanded by `DropGlueGenerationPass` into `ADDR name; CALL __drop_T`, original line removed; the emitter then nulls each owned leaf), moved by any whole-struct copy (let RHS, assignment, struct-literal field, dyn literal element: `markMovedIfOwned` sets `Token.inlineOwnsStruct`, the source is a moved slot and its owned leaves are nulled), `deref(p)` of one is rejected. `h = f()` (RVO into an existing variable) builds the result in a hidden local, then drops the old members and copies it over. Assigning an inline owning struct through a pointer/index (`bx.h = h2`, `arr[i] = h2`) spills the RHS to a hidden local, then `emitAssignTarget; DUP_TOP; GT_DROP_ADDR T` (DropGlue expands it to `CALL __drop_T`), then stores. A fixed array of inline owning structs (`Holder[2]`, local or member; `isInlineOwningStruct` strips the dims) is an owned slot too: dropped element by element (unrolled `LOOKUP_LHS` chain + `CALL __drop_T`), moved as a whole by a copy, literal elements moved in, `arr[i] = h` drops the old element; reading an element out by value (`let x = arr[i]`) is a compile error (use clone). Clone glue and drop glue address elements by numeric path segments (`name.hs.1.w`, resolved in `AddressLoweringPass.resolveAddress`). Arrays are always built from a full literal (no uninitialised arrays), so there is no null-fill case. Test: `owning_array_test` (+ `_check.sh`). Reading an owning struct out of any indexed element by value (fixed array or dynarray, also `d[i].h`) is a compile error (`markMovedIfOwned`); a pointer member (`let z = bx.h`) is a move (slot `bx.h`, leaves nulled). Test fixtures: `owning_array_element_read_error_test`, `dyn_owning_element_read_error_test`. A `let static` takes only constants, so a static can never own heap memory. A `resize` fill value stays with the caller (every new slot is a clone). `unsafe` dynarrays of owning elements are the programmer's to clean up (tag `udyn:owns`). `tests/clone_oom_check.sh` sweeps allocation failures.
- The emitter hoists every local's `ALLOC` with a pre-pass (`collectHoistedAllocs`) that must mirror what the main emit walk declares (including `for` hidden range variables, catch parameters, nested blocks). Dropping it is a pure refactor with no user-visible gain and a wide blast radius (every HOB), so it is deliberately NOT planned; if a bug ever shows the two walks disagreeing, that is the time. Label pre-passes (try/catch, continue) must stay in any case.
- Passing a struct by value as a plain parameter is rejected by design.
- Ghost table failure: `gt_register` returns bool (false = table could not grow, nothing registered, old buffer kept); `GT_REGISTER` (codegen) then frees the block and leaves null, so every allocation site emits `GT_REGISTER` BEFORE its null check and the ordinary out-of-memory path runs (`new`, `dyn`, `dyn(text)`, `clone`, clone-glue leaves; the pointer clone routine registers its own result so its leaf clones are destructed on failure). `resize` is safe because `gt_moved(old)` frees a slot before `gt_register(new)`. Shrink failures in `gt_destruct`/`gt_moved` keep the old buffer; `gt_init` prints a message and exits. `par`/`await` must be wrapped in `try`/`?` like `new`: the hidden handle gets the same null check after `GT_REGISTER` ("out of memory"), and `@par_call`/`@await_call` return `bool` (false = `pthread_create` failed: handle destructed, "cannot start thread"); test `tests/async_fail_check.sh` (shim `FAILN`, `FAILPTHREAD`). `par_call` detaches the thread it starts (nothing joins a `par` thread), so finished threads are reclaimed; test `tests/par_detach_check.sh` (valgrind). The dynarray clone loops register their new block at creation (so cleanup never needs room in the table; resizes keep it registered). Test: `tests/gt_grow_oom_check.sh` (shim `FAILREALLOC` + `FAILREALLOC_STICKY`, 12 cases). OOM gaps: `new`/`dyn([..])` failing frees owns variables moved into them (`tests/new_oom_check.sh`); a moved-in temporary (call result, e.g. `new T{f= pass(p)}`) is spilled to a hidden `$mvN` local first, so it is freed too. Safe `dyn` blocks are `GT_REGISTER`ed (block start) so scope-end drop frees them; `resize` (RESIZE/URESIZE in codegen) calls `gt_moved(old)` (unregister, no free) + `gt_register(new)` only when the realloc moved the block. An unsafe dynarray is HEADERLESS: the variable holds exactly the malloc'd address (registered; scope end frees it), indexing is plain `base+i*size`, there is no stored length (`len(a, term)` scans), and it never allocates 0 bytes (empty / `resize(a, 0)` get 1). `unsafe dyn(text)` (`NEW_FROM_USTRING`) copies the bytes plus a NUL. A failed `resize` realloc (safe form) leaves the old block intact: the source variable is nulled only after success, and the failure branch `GT_DESTRUCT`s it ("out of memory"); test `tests/resize_oom_check.sh` (shim `FAILREALLOC` + `FAILREALLOC_STICKY`, 5 cases). A `resize` source that is not a plain variable or field path is not freed on failure.
- Safe-args `main`, `String` and `DynamicArray` were checked with valgrind (3 Oct): no leak, no invalid access (`tests/safe_args_check.sh` runs example 08 with arguments; the earlier notes about leaks were stale). A move written with a mutability wrapper (`a = mut b`, `take(mut b)`, `let c = mut b`) now moves `b` (before, it did not, and `make_safe_args` freed each inner argument array too early).
- Float variables (xmm registers) and catch: a call spills them to home slots, but a direct jump into a catch label (inlined throw, failed allocation) is not a call, so `RegVarPromotionPass` puts `R_XSPILL` before every `JMP`/`R_BR*` to a `@catch_` label and the catch entry `R_XRELOAD`s them; the inliner no longer refuses float variables. Test: `tests/float_catch_check.sh`. `auto` cannot point at a dynarray element (resize may move the block): deliberate.
