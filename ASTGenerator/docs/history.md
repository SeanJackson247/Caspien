# ASTGenerator: design history

How the large classes got their current shape: decisions, found-and-fixed bugs, rejected designs, comments that disagreed with the code. Of interest when changing an old decision; the current behaviour is in the reference docs next to this file.

## TypeChecker

## TypeChecker.java, chunk 1 (header, TypeInfo, info classes, Scope, flags, main validation, collectDeclarations)

- `TypeInfo.dynArrayElementType` doc used to claim `baseType` was `"dynarray(" + elementType.canonical() + ")"`. That was stale: `dynArray()` built it from `elementType.baseType` alone, discarding storage. Found by compiling a struct member `items: mut dynarray(owns mut Leaf)` and seeing byte-identical bytecode (`STRUCT_MEMBER items mut_dynarray(Leaf)`) to a plain `dynarray(Leaf)`. Fixed by `dynArrayElementText` (storage embedded, mutability still omitted, keeping the earlier "same element kind is the same type regardless of mut-wrapped vs bare literals" precedent).
- `arrayElementType` added because `checkLookup`'s array case used to strip every element to its bare base type, so `arr[i]` on an array of `owns mut Box` silently resolved to plain `mut_Box`; a pointer-typed array element could never be indexed back out as a pointer. A real bug, fixed, not a new capability.
- `rawPointeeType` added for recursive `raw` pointers (`raw mut raw mut char`), needed for a C-ABI `main` signature; checked three ways that it did not parse without it. Scoped to `raw` only; nested ownership was rejected as unrequested and ill-defined.
- `withMutability` exists because a hand-rolled field-by-field reconstruction in `checkMutabilityOf` silently dropped fields it did not list (found while adding `dynArrayElementType`; would have hit function-pointer types identically). `withStorage` fixes the same bug class in `checkAddressOf`'s final `return`, which used the 4-argument partial constructor: `ref h.backing` lost its `dynArrayElementType`, so `i in (ref h.backing)` failed as "not a range or dynarray". Found while extending `for` to accept a dynarray. `withSome`/`withConst`/`withFloatStates`/`withAtomic` follow the same "with-method rather than constructor parameter" pattern to avoid touching every construction site.
- `isAtomic` is embedded in `canonical()` (unlike `isConst`) so ordinary reads/writes of an atomic need no new bytecode instruction; the type string operand of PUSH/ASSIGN just carries "atomic".
- `canonical()` order for `some` mirrors the annotation order (`owns some mut String`); float states are canonicalised alphabetically regardless of source order.
- `FLOAT_STATE_NAMES`: contextual keywords by design, like `default`.
- `ExternInfo.callConvention`: externs accept decorators because the C/OS ABI boundary is where the right convention matters most.
- `EnumInfo.explicitValues` was originally purely representational (read only by `flattenEnum` validation and `BytecodeEmitter.emitEnum`; "no new powers, just control of what is emitted, not a full-blown numeric type"); it is now also the "guaranteed enum" test for `u64 in EnumName` (`checkGuaranteedEnumMembership`).
- `StructInfo.publicMembers` rule ("container gates its members") was confirmed for impls; for structs it was extended by symmetry, not confirmed.
- `Scope.ownLoopImmutableSlots` is a different mechanism from `constNames` because a loop's source variable is declared outside the loop: marking it const at its declaring scope would make it permanently const.
- `Scope.tryBlockBoundaryScope`/`continue` in a catch body: chosen to resolve the "what is x" ambiguity a plain fallthrough out of a catch would leave (the try body's variables and the catch variable are out of scope after the try block).
- `genericConstructorFuncInfos`: before the third loop in `check()`, generic constructor bodies were silently never checked; the symptom was literal `null` text in emitted bytecode rather than a crash, so it was easy to miss without reading the bytecode.
- `insideThrowingAllocContext` was originally `insideThrowingNewContext`, covering only `new`; renamed and broadened when `dyn`/`resize` became throw-capable (the mechanism was already general; only the name and one `checkTry` gate changed). Confirmed real, not hypothetical, by the stdlib's `String.from`.
- `usesThrow` was added because the per-function `gt_routine`/`GT_UNWIND` prologue is now emitted only when needed (the earlier "simple/complicated set classification" was temporary build scaffolding); a `throw` names the function's `gt_routine` label regardless of `owns`/`ref`/`dyn`/`new` use, so `usesOwnsRefDynNew` alone would leave a dangling label.
- `insideShortCircuitEligiblePosition`: the narrower reading of "top level" for `&&then`/`||then` was chosen deliberately over the widest reading consistent with the user's wording, since the wider one has no sound single-value codegen and no example exercised it.
- RVO destination positions: a `return f()` struct-RVO call is deliberately not supported in this first version (would need different codegen); the simple "bare local" destination was verified end to end against the 4-stage pipeline before implementation. Dotted/indexed destinations left as future work. (Note: the project CLAUDE.md now lists legal positions as let RHS, bare-variable assignment RHS, or `return f()`; the comment's "not return" is stale relative to that, and was dropped from the code comment; check the code before documenting a return position.)
- Pass 1f (overload mangling): two overloads of one top-level func used to emit identically named FUNC_START/CALL pairs (a live gap found by direct testing). The library feature's `signatureSuffix` was reused but only when a name has more than one overload, to leave every existing literal-name comparison untouched.
- `validateMainFunction`: `main` returns `s32` rather than `int`, matching C `int` width and signedness for OS exit codes; a stacked Javadoc for it sat above `findFuncsWithDecorator` (misplaced); moved to the method it describes.
- `safeArgsType`: simplified from `owns some mut dynarray<owns some mut dynarray<mut char>>` to immutable inner dynarrays of immutable chars (a built-in dynarray's own elements cannot be `owns`-tagged, per earlier decision); parsing of the nested type was tested directly.
- `@make_safe_args` requirement is tied to the `safe_args` shape alone, not to `@event_loop` existing.
- `@tick`/`@event_loop`: the first draft required `@event_loop` use "if main is not @event_loop"; corrected to "if main is @with_tick". `main`'s return type was first `owns some owns some mut struct T`, corrected to reuse `@tick`'s return signature. Event-loop body not validated: stdlib may ship different variants per eventuality.
- Dropped as stale: the class comment's statement that mutability checking is entirely a stub (the checker now enforces `const` and loop-immutable slots; type comparisons remain base-type-only).

- `@unpadded`: originally meant to leave a struct unpadded. Once every struct was compiler-padded to natural alignment (`emitStruct`) with no unpadded lowering built, the decorator became a named "not supported yet" error; it stays in `STRUCT_DECORATORS` for that message.
- Interface `@default` methods: first documented as working "for free" (an impl could omit them); that was wrong, because `collectImpl`'s "is missing method" check required every impl to redeclare every interface method. Fixed by `materializeDefaultMethod`. The omission was found by inspecting real bytecode: a method present only in `implInfo.methods` type-checked but was never emitted, since BytecodeEmitter walks the impl token's `childs`; the cloned token is therefore appended to them.
- Interface default bodies are not RPN-converted/tree-built (RpnConverter and TreeBuilder return immediately for `interface`), because nothing needed a checkable body before; hence the re-conversion in `materializeDefaultMethod`.
- Impl decorators: before `IMPL_DECORATORS` nothing on an `impl` was validated; `pub` is its first. "let/static are excempt, globals are not": a root `let static` got its own allowlist rather than reusing function decorators.
- `signatureSuffix` is appended to library mangled names unconditionally, a deliberate departure from the compiler's general gap that two overloads of the same function emit identically named FUNC_START/CALL pairs (a library's full-signature collision rule lets such pairs coexist). Characters outside `[A-Za-z0-9_]` are replaced because types like `owns_mut_dynarray(u64)` produced illegal assembler symbols.
- Libraries: unlimited multiple `extends` (like interfaces, unlike the former single-parent struct cap); collision means full signature, unlike `flattenInterface`'s name-only collision.
- `registerImplMethod`: overloading in bare impls was added later; the first method of a name keeps its original mangled name so non-overloading programs stay byte-identical.
- By-value struct parameters: an earlier version rejected them only above one 8-byte word, on the theory that small plain struct params were legal. Wrong: the by-value form was never legal at any size. The check became unconditional, like the array one. Probes `struct_arg_gt16_probe.caspien` and `struct_arg_16byte_probe.caspien` showed real runtime corruption (wild-pointer write) that this prevents. (Full account in CLAUDE.md.)
- Struct returns: struct was dropped from the "needs storage modifier" return check when return value optimisation (hidden `$ret_dest` in the parent frame) was added; enum and array stayed as before (the feature was built and verified for structs only). Arrays were added to the return rule after structs ("returned by functions but only as pointers").
- `@link_name` was introduced when `sleep` became a reserved keyword: `extern sleep(...)` could no longer parse, while the C library only exports the literal symbol `sleep`.
- Interface-method lock qualifiers: matching is by position because interface conformance is type/position based. Matching `in` vs `within` and `Some(...)` wrapping exactly was a consistency choice, not explicitly specified.
- `@pure` global reads: scoped to mutable globals/statics (an `imut` one cannot change). `@pure(rt)` later banned all global reads. Unsafe code was explicitly given no exemption for purity checks.
- Static-method self rule: `forbidSelfReference` (unconditional recursive) replaced the "if present, must be a pointer" check for static interface signatures, which wrongly assumed a static signature could mention `self`.
- Known scope limit: residual-generic methods are supported for instance methods only (static would need work in `checkStaticMethodCall`).
- Dropped as stale: the comment before the `else` of `validateMethodLocks` described the plain argument-less `@lock` as the `@guard` method decorator; `validateDecorators` now rejects a bare `@lock`, so the comment was replaced by a neutral one. The orphaned `collectImpl` Javadoc sitting above `collectDefaultLockMatchPolicy`, and the `validateOverridesRealizes` Javadoc sitting above `requirePublicInterfaceImpl`, were relocated as short comments on the correct methods.

## Decorator signatures and symbol names
- Bug (fixed by `forceGhostTableFunctionNames`): X86Backend's GT_INIT/GT_ALIVE_CHECK/GT_DESTRUCT/GT_REGISTER opcodes call hardcoded literal symbols, never the mangled name of the decorated function. The stdlib names its functions literally that way, so the mismatch stayed invisible until a stub with another name (e.g. `myInit`) type-checked fine and then failed to link. Fix: force `mangledName` to the decorator name, once after all functions are collected (a late-collected function named `gt_init` must be seen by the collision check). `par_call`/`await_call`/`sleep` call sites already use the real mangled name, so they were never affected.
- `@sleep` signature mirrors C `sleep(unsigned int)`; the old `extern sleep` was renamed `c_sleep` when `sleep` became a keyword.
- `@async` parameter limit (one register-sized parameter) is because the argument travels in the handle's single `value` word; no marshalling convention for more exists or is planned. A range is excluded though `sizeof` might suggest otherwise (it is two words).
- Comment disagreed with code: the `requireAsyncGlueSignature` comment said the glue returns `void` with two parameters; the code requires `bool` and, for `par_call`, a third `raw mut u64` thread-id parameter. Code followed.

## Type annotations
- Aliases were designed as "as if what was written in the type statement was just put in there": splicing happens before parsing, so no separate validation for incomplete alias types is needed.
- Return-type mutability was relaxed later than the original "always explicit" rule (`allowIndeterminateMutability`); the original rule was a hard error that replaced an earlier default, and "indeterminate" reuses the existing literal state instead of adding a fourth spelling.
- Real `raw` recursion ("raw mut raw mut char") was chosen over a limited form (option a), reusing the recursive-span approach of function-pointer return types.
- Float-state modifiers (`finite|infinite|nan`) deliberately stayed contextual identifiers, not new keywords.
- `slice` was removed from the language: it had a chronic, unfixed addressing bug (its `storage` field never resolved to a real address in the optimizer) and a broken write path; it is now rejected at annotation level. A bare incomplete `slice` used to share the "needs indirection" check that bare `range` skips.
- Bug found while auditing dynarray codegen: the explicit-dynarray branch fired for `dynarray(u64)[3]` too, attaching the inner element type to an array TypeInfo, so `isDynArrayType` was true for a fixed array (a member `rows: mut dynarray(mut u64)[2]` indexed as `rows[0]` resolved to a bare `mut_u64`). Fixed with the `arraySuffix.length() == 0` guard.
- Bug found while making the bytecode type text carry element storage (`dynArrayElementText`): an annotated nested dynarray element had null storage while a `dyn([...])`-built one had `owns`, giving a spurious return-type mismatch in `make_safe_args` ("...dynarray(dynarray(char))" vs "...dynarray(owns_dynarray(char))"). Fixed by forcing `owns` in the annotation branch (and an error for any other storage keyword).
- The `ref some` element/member restrictions were added narrowly: a plain `ref some T` parameter/local/return stays legal; fixed-array suffix needs no extra rule (reasoning in the reference).
- The visibility check anchor moved from `at` to `baseTypeTok` for monomorphized generics (their `at` token still carries the template's declaring file); the other half of the fix is in `GenericsExpander.substituteParams`.

## Call-graph and struct checks
- Safe/unsafe: only the originating call site's safety decides whether to check; the check is transitive. Recursion is outlawed except `@recursive` direct recursion; indirect recursion stays banned even for `@recursive`.
- Throws from ghost-table functions: two options were considered (catch-and-handle versus banning); the ban was chosen, then narrowed to "no escaping `throw` reachable", so locally caught `@throws` calls stay legal. Reuses `callEdges` instead of a second call graph.
- Recursive structs: the plain-struct example `struct A{ a:A }` compiled cleanly before this check (a separate pre-existing gap). Checking post-monomorphization; the nullable-`ref` exception was added later at the owner's request (5 Oct) for lists, trees and graphs.
- Resize-in-for-loop: conservative by choice (no alias analysis); same reachability shape as `reachesUnsafe`.
- `auto` checks (`typeHoldsAuto`, `validateNoAutoStructMembers`, `requireNoAutoReturn`, `requireNoAutoContainer`): added after a returned `auto` to a local compiled and dangled; no `auto` return types, struct members, or containers.
- Lock struct rules were added after demos in which a `ref` or a moved owned variable let two threads reach lock-protected data with no lock; a nested `auto` once slipped past the direct-member check, hence the recursive search.

## Control flow and @recursive
- Missing-return check was added because a non-void function falling off the end used to compile silently, returning stack garbage. `containsRealTryCatch` exists because a `try { }` block must contain a real try/catch ("syntax error if there isn't at least one regular try statement in the try block").
- `TryBlockBoundaryMarker` constructor replaced the plain `Scope(scope)` that `checkTry`-style blocks used before `continue` existed.
- Stale comment: the `statementDefinitelyReturns` default-case note mentioned `match`/`elsematch`; `match` is actually handled in the `if`/`match` case (needs a trailing else) and only other constructs reach the default. Also the `lock` case comment said `match @lock` was "not yet implemented"; dropped as stale.
- `@recursive` redesign: the old primitive recursion-count argument was removed; the final argument is now a plain `imut range`, with the base-case requirement retargeted to it. The textual transform to a bounded `for` loop came after the restrictions (within-wrap, return-site-only); shadow locals are declared outside the loop. The language has no `continue` for this lowering (it falls off the block end), though `continue` now exists in catch bodies. Known limitation: no `owns` parameters.
- Base case after the loop: added so that a recursion shrinking its range by one per step, which needs one more call than the initial length to reach its base case, still terminates correctly while the loop stays bounded.

## TypeChecker.java chunk 4: history and provenance

- GT_DESTRUCT was first one flat instruction per owns slot, then changed to cascade into an owned struct's nested owns members, then reverted to flat. Reason: struct-aware recursion belongs to the later bytecode-to-assembly stage, which reads struct definitions and generates the routines; the checker emits one `GT_DESTRUCT` per top-level slot.
- `partlyMovedSlots` / `finishBranchMerge` were added because a slot moved on only some paths was dropped from the destruct list entirely, so the not-moved path leaked.
- "Moved in any branch means moved" (use-after-move) was first described wrongly and then corrected to the current union rule; the pre-scan for loops (`collectLoopMoves`) is a cross-iteration fix: before it, a move on one iteration was not a use-after-move on the next. Its overload gap (only single-overload names) is a known, accepted gap, not silent.
- `checkNoCodeAfterTerminalStatement`: `return` used to allow dead code after it (found by direct testing: it compiled and was even emitted). It reuses `statementDefinitelyReturns` instead of a narrower return/throw test, so exhaustive if chains and break-free loops count as well.
- `loop` in safe code: decided that a bare `loop{}` is unbounded by construction and so needs `unsafe`; `@event_loop` functions get one exemption (a privilege of that function kind, not a loosening).
- `continue` started as the way to fall through a `try { }` block from a catch body ("same as `catch(e){}` but more explicit"; without an enclosing try it is a syntax error); later extended to next-iteration in `for`/`loop` and to the retry of a CLOSED `match @lock` case.
- `unsafe`/`safe` nesting rule: unsafe inside safe is an error, safe inside unsafe is permitted.
- Instanceof narrowing: the match statement originally did not change types ("only cast and as can do that"); a later round found, by direct test, that `match b instanceof Sub{ b.subOnlyField }` still failed with "struct 'Base' has no member named 'subOnlyField'", and reused the variable-shadowing mechanism that the since-removed `cast x as Y{...}` used. `implements` proofs are deliberately not narrowed.
- `requireNewTypeAssertion` ("redundant match is a compiler error in safe code") is not a lexical check: it tries the match and compares the new proofs with the active ones. The enum case form is exempt. It had to learn about stale alive proofs (`ProofKills.hasEvents`) so re-matching to renew a proof is not rejected.
- Case matches (enum, float, interface `.enum`) are lowered to if chains only after full checking, because "it can't convert it and then type check it": match blocks may assert type information the checker needs to see. Enum match originally made no type assertions at all ("nothing to do with this information at this stage").
- Bug found and fixed in the float and enum lowering: building a per-case condition with a shallow `new Token(type, text, line, file)` copy silently dropped `.left/.right`, so a compound condition such as `obj.field` crashed with a NullPointerException once more than one case needed its own copy (never caught earlier because every tested condition was a bare variable). The fix reuses `conditionExpr` itself in all cases.
- Float match: `FLOAT_CHECK` chains are canonicalised alphabetically in the bytecode regardless of source order; `default` is not accepted at all; a state excluded by the type's modifier (e.g. `nan` on a finite-only type) is an error rather than merely unnecessary.
- `x != 0` match condition: first emitted a meaningless `GT_ALIVE_CHECK` on the comparison's bool result when treated as a bare expression; and `someS64Var != 0` was wrongly rejected as `mut_s64` vs `indeterminate_u64` because a bare literal is typed u64. Both fixed by the dedicated case with hand-set types. `!= 0` is only sufficient for unsigned divisors because of `TYPE_MIN / -1`; `> 0` was added for that reason.
- `is base` was retargeted from the removed `@recurse`/`recurse` type to plain `range` ("still need to check the base case first, it's just now done on a range").
- `match x{..}` (bare value, alive proof with no target) was removed; `match Some(x){..}` replaced it with unchanged bytecode, and `Some()` was made a generally available builtin.
- `into` (write-legalizing bounds proof) was added beside `in`; `within` is a legal match condition under the `in` kind; `match Some(i) in/into x` and `for match Some(i) in/into x` are sugar over the two nested proofs. A plain `for i into arr` is rejected on purpose (ambiguity: it would silently grant nothing).
- For loops: the loop variable and source are immutable in the body in every for form. The `mut ref` wrap for dynarray sources was missed on a first pass and caught by the "mutability is indeterminate" error. An earlier draft of the `mut` wrapping around `.start` hit the forbidden imut-to-mut transition before `.start/.end` were made `indeterminate`.
- `for` over an `unsafe dynarray` is banned outright (no known length).
- Generic bounds are enforced at instantiation sites only because the monomorphize-then-typecheck design never checks an unbound template body.
- The `structImplementsInterface` comment described walking a struct's `extends` ancestry (and its `implementsNames` not being flattened); struct `extends` is gone and the code only walks interface `extends` plus `implsByConcreteType`. The standalone-impl branch was added after a real miss (the `@guard` fixtures implement interfaces only through standalone impls; `isGuardType` already had to read the same map).
- `if`/`elseif` condition type check: `if someStructValue{..}` used to compile and emit a bare, meaningless CMP; fixed to allow bool or numeric (C-style) and reject everything else.
- `assume match`: the field-variant and float-state forms were added so `assume match x.field : V` can satisfy `@lock(match ..)` qualifiers and `assume match x : finite` can satisfy float operations; the swap-access marking avoids requiring the `swap` tag for it.
- Dropped as stale: a comment saying "(planned next)" for the synthesized interface-method dispatcher case bodies; the `cast x as Y{..}` references (statement removed).
- Disagreement between comment and code: the comment at the `unsafe` block listed the proof-preserving tags as `memcopy, raw, deref, clone, global, loop, atomic, guard, assume`; the code uses `NON_FREEING_UNSAFE_TAGS`, which is authoritative. (CLAUDE.md lists the same set without `guard`.)

- Returning `owns some`: an earlier attempt treated a direct `new` as automatically `some`. That was reverted as unsound (malloc can fail). The accepted route is a runtime `match Some` proof active at the return.
- Struct RVO: shipped as a narrow slice first (fresh literal, then readable value chains such as `arr[i]`, then `return foo()` tail-forwarding as the third legal destination). `return arr[i]` was added on request, on the reasoning that it is just following a pointer like `self.point`. Confirmed by experiment that `let p = mut arr[1]` on an array of structs already compiled and ran before the restriction was loosened.
- `throw`: originally one whole-function `gt_routine` listed every owns local the function ever declared (conservative, one shared label). Replaced by per-throw-site unwinding resolved at compile time, as precise as `return`. `throw` was once `unsafe`-only; it is now safe code.
- `throw` inside ghost-table functions: found by building the case; the bytecode named a label that was never emitted, so the check was added.
- A throw out of an OPEN `match @lock` case used to leave the lock held forever; `unlockOnExit` fixed that for throw (and for calls that may unwind).
- `try`: first built as structural parse/type check only (lowering to bytecode deliberately came later). Extended to wrap `new` (making `new` return `owns some` and demanding the same wrapping), then `dyn`/`resize` (and `clone`) which are ordinary CALL-shaped nodes. Nested allocations needed the `insideThrowingAllocContext` flag because try/catch cannot be written around an inner expression.
- The catch body's "after label" idea was dropped in favour of requiring the catch body to terminate (return/throw, later also `continue`), which removed the question of where a finished catch body continues.
- Catch parameter: the comment said `e` has the plain `static imut string` type and is "not yet given a runtime value"; the code now registers it in `activeCatchTries` and treats a bare `e` as the caught error (stack_trace.md 3.6). Trust the code.
- Expression-position `try` passes `insideLoop=false`; a stray `break` in such a catch is a known narrow gap (unchanged).
- `let` bound with `static`: a global/`let static` initialiser calling a function, or using `new`, was previously not rejected by the type checker (it only failed later needing `@gt_init`); `new` rejection was added.
- Atomics: an outright ban on `=` to an atomic target was tried first and broke the synthesized lock-release write, so it was narrowed to the `swap` RHS shapes. Compound assignment and `++`/`--` on atomics were previously accepted as a multi-step sequence while claiming atomicity; they are now rejected outright.
- `requireStaticMutable` was first implemented as `mut` only; found to block concrete `imut` statics and string-literal statics, then widened to any concrete mutability (the old CLAUDE.md "Known gaps" entry for this was resolved).
- `'null'` against a `some`-bound `let`: this path validates by hand and bypassed the `typesCompatible` rule; found only by testing that path directly and fixed there separately.
- `slotKeyOf` supporting `x[i]`: a pre-existing gap that had never been supported; added so element-alive proofs from `Some(..) in/into` can be matched.
- `requireMutable` LOOKUP branch: a first single-level version missed `p.arr[0]`; fixed by recursing through the same call. The `@pure` pointer check there is unconditional, `unsafe` is no exemption.
- A fresh `let` clearing `movedSlots`: found by testing a loop with no cross-iteration hazard whose body redeclares a name that the cross-loop pre-scan had seeded as moved.
- Template literal floats are rejected for now rather than guessing a format.
- Dropped as stale: the doc comment on `markMovedIfOwned` was orphaned above `requireNotMovedAlready`'s Javadoc (two Javadocs in a row); a short Javadoc was moved to the method it described.

## TypeChecker.java chunk 6 (builtin/method call checking, match @lock lowering, array literals)

- `sleep` call: an earlier design considered an ordinary `CALL`; the decision was a dedicated `SLEEP sleep_call duration` instruction. Emission routing is flag-only; every check (arity, types, `@sleep` existing) is unchanged either way.
- `match Some(x)` replaced the old bare form `match x{...}`; `Some()` was made a generally available builtin (like `instanceof`/`implements`/`in`) rather than match-only.
- `insecure_rand`: decided not unsafe (its limitation is self documenting by name), allowed in `@pure` (pure = side-effect free, not referentially transparent), bound to C `rand()`; handled on its own path, not as an exemption from the extern rules.
- `sizeof`: arrays give their base element type's size; mutability is exempt from size; result is an indeterminate u64. The original size rule was "a plain sum of member sizes, ignoring alignment/padding, flagged for later review"; the code now estimates 8 (hidden `___type`) + members and leaves the real size to `SizeofResolutionPass` (the comment's "plain sum" was stale, code trusted).
- `len` of an unsafe dynarray: first rejected outright (no length), later given a terminator form `len(arr, '\0')` that is itself unsafe.
- `range`: used to return a slice pairing the range with the container's origin; the slice type was removed from the language, so it now returns the plain range, which is all any caller used.
- `clone(p)` accepts any storage (not only an existing `owns`). `memcopy` was first specified as `memcopy(raw any, u64, any pointer)` returning void; corrected to generic over the destination's base type (`raw u8`), return type mirroring the destination; decision "not to introduce a new type".
- `call()` is unsafe-only but fully checked (not an unchecked call); banned in `@pure`.
- `dyn`/`resize` were originally non-throwing (only `new` threw); changed so safe `dyn` and `resize` need the same try/catch as `new`. The unsafe forms were deliberately left alone (many fixtures use `unsafe dyn` unwrapped) and an unsafe `resize` is rejected inside `try`.
- `resize` was changed to take ownership of the dynarray and return a new owns (an eventual realloc can return a new address); both variants. `resize` with an unsafe dynarray has no fill: possible uninitialised memory is accepted because it is unsafe-only.
- Fixed bug in `checkDynBuiltinCoreInner`: it used to re-derive the element type with a second `resolveExprType` over the elements, which re-ran the VARREF move check and rejected `dyn([a, b])` (two fresh owns pointers) with "use of 'a' after its ownership was moved". It now reuses `fixedArrayType.arrayElementType`. Known pre-existing gap noted then: `dyn([a, a])` (same owns pointer twice in one literal) is not rejected by `checkArrayLiteral` (its move-marking loop adds to `movedSlots` without checking it); not touched by that fix. Unclear whether still true.
- Method-call design: not "full object orientation": receiver is not injected as an argument; zero run-time dispatch (project ethos). "TypeName.method" needed its own path because routing it through the instance path failed with "use of undeclared variable". Instance/static mix-ups got specific errors rather than the generic "no method".
- Visibility rules for methods: public is accessible anywhere; private only from the same file/impl; a non-public impl hides all its methods outside its file.
- Method call without RVO support: the caller never passed the hidden destination and the callee wrote through garbage (segfault) before `markStructRvoMethodCall` existed.
- Per-call-site destruct lists replaced an older whole-function conservative list.
- `match @lock`: original bug: neither case body's Scope was a loop-boundary scope, so a user `break` inside could only reach an outer loop, never the implicit spin loop; fixed with one extra wrapping Scope. ## BytecodeEmitter.java, chunk 1 (header through collectHoistedAllocsFromStatement): history

- **Spec ambiguities resolved at the start.** The spec's example showed only a lone `if`, whose literal shape (jump to the chain's final end label) would skip later elseif/else branches; the emitter jumps to the next branch's label instead (a strict generalisation). `++` and compound assignment had no bytecode shapes; they were desugared to existing primitives instead of adding opcodes. (Fuller reasoning was kept in the top-level CLAUDE.md.)
- **Try/catch staging.** The original idea was a standalone `TRY <label>` line; it was replaced by redirecting the call-site staging triple of the wrapped call ("the TRY eats the next two instructions"). One-shot `pendingTryCatchLabel` set around the wrapped call, consumed by the next staging write.
- **Ghost-table duplicates.** Decision: GT instructions are not generated inside the ghost-table functions, and calls made from them must reach "__" duplicates "all the way down", so reachable functions are emitted twice from the same checked tree. `call()` is banned in the reachable set the way it is in `@pure`. The decorated-function list grew over time (comments said "up to four"; the code now lists seven: init, alive_check, destruct, register, moved, ref_id, ref_resolve).
- **String pool.** Strings are pooled by content ("a real string pool, not one id per occurrence"), hoisted to the very top of the output ahead of GLOBAL lines; char literals deliberately stay inline.
- **Globals** are emitted before any FUNC_START, through the same folding as local statics.
- **Struct padding round.** Padding was first left to later stages (`AddressLoweringPass`/`SizeCalculator` summed members and ignored alignment, flagged in a standing "worthy of review" comment); the owner then asked for padding in the HOB (compiler, not optimizer). `@unpadded` was rejected as unsupported. The layout size/align table was deliberately duplicated rather than reusing TypeChecker's private `PRIMITIVE_SIZE`, matching the precedent that each stage keeps its own sizing table.
- **Static structs and `___type`.** The static-initializer path once iterated only `structInfo.members` and never emitted `name.___type`, so a static struct's class id was uninitialised (right only when the id happened to be 0). Fixed by emitting it first, with the same `@untyped` exemption. Later: padding gaps also had to be emitted as `name.$padN` lines, because the backend places dotted lines at the running size sum and every member after a gap was read at the wrong offset (a `bool` followed by a `u64`).
- **`atomic` wrapper in static initializers.** `let static x = mut atomic <literal>` fell through to `literalValueOf`'s default branch and folded to the text "atomic", corrupting every atomic global/static. Found by compiling a probe; fixed by treating `atomic` as a transparent wrapper.
- **Negative float static constants** crashed with `NumberFormatException` in `parseLong`; fixed by negating the text.
- **Enum formats.** The owner decided "only change the format if the values are explicit"; range-valued enums got their own third format `V a..b`. (An old comment spells the mnemonic `ENUM_DEF`; the code emits `ENUM`, trusted.)
- **ARG vs ALLOC.** An earlier compiler-side version of "ARG-to-ALLOC lowering" was judged wrong from the start; it moved into the optimizer (`ArgToAllocLoweringPass`). The emitter only prints `ARG name type`, right after `RETURNS` (so textually before `gt_routine_address`), and the optimizer places the allocation.
- **RVO.** `$ret_dest` follows the precedent set by the `for` loop's hidden range variable (names with `$` cannot be written by users). `ArgToAllocLoweringPass` needed no change.
- **ALLOC hoisting.** The owner wanted "static alloc, then Alloc, with the unwinding variable first, then the rest; no routines mixed in with allocs", ideally one stack-pointer adjustment eventually. This turned `emitBlock`/`emitPreLoopInit`/`emitForLoop` into init-only emitters and split the gt_routine prologue into `emitGtRoutineAlloc` and `emitGtRoutineBody`. A try/catch under `x = try ...`, under `let x = try ...`, and a bare try/catch with nested lets were once never hoisted at all (the keyword switch only saw KEYWORD statements); `tryNodeOf` fixed all three together. (The pre-pass/emit-walk duplication is documented as deliberately kept in the project CLAUDE.md.)
- **gt_routine prologue gating.** Originally unconditional in every non-main function. The owner then pointed out the scaffolding is needed only if the final unit has `GT_INIT` (owns/ref/dyn/new) or uses `throw` (a THROW names its function's `gt_routine` label); both halves share one gate. Later, per-throw-site / per-call-site unwinding superseded the whole-function label for throwing programs; the old shape is kept untouched for programs that use owns/ref/dyn/new but never throw.
- **gt_error_message slot.** Added as a second secret variable ("a secret address variable, and a secret message variable"), gated on `usesThrow()` only; X86Backend implements the propagation (not merely a documented contract).
- **Null-after-destruct** (`emitDestructList`) came out of an ownership-model leak audit: a loop-body owns local shares one hoisted slot, so a destructed slot stayed stale (non-null) into the next iteration, and a later blind re-destruct of a reused address would corrupt live data. Applied to every destruct site, not only loops.
- **Same-name locals.** Sibling-scope reuse of a name with different types is allowed (shared slot) except when a type needs drop glue; the drop-glue pass maps name -> type once, so two types under one name dropped via the wrong layout (a catch parameter `e` plus an owning local `e` holding a DynamicArray leaked its elements; an owned Node and Holder dropped through the wrong layout).
- **Safe-args main wrapper** is synthesized directly as bytecode because nothing about it was ever source for TypeChecker to validate; it follows the same RETURNS/ARG/ALLOC ordering and true-main treatment as an ordinary entry point.
- **`sizeof` in statics.** Added after "let static n = sizeof(Struct)" needed a folded value; `STRUCT_PIN` exists so the member-reordering pass cannot change a size that was already baked into a data line.
- **Known gaps stated in the comments.** Enum-variant defaults in static folding were left as a follow-up ("no example covers that shape"); a reference to an existing global from a LOCAL static's initializer is structurally blocked (see CLAUDE.md "Known gaps").
- **Dropped as stale.** Class header called this "Stage 7 (final stage of the first deliverable)" with "assembly generation explicitly out of scope"; the compiler now continues through Optimizer, LowerOrderGenerator and Codegen. Several "up to four" gt-function remarks were out of date (see above). The "ARG ... textually BEFORE gt_routine_address while the frame layout needs parameters AFTER it" note is kept in ref.md only as the ARG lowering responsibility.

## Instruction-shape decisions
- `DEREF` used to carry no operand. Found as a real gap: it is a copy and needs the pointee width, but the previous `PUSH pointer` line only describes the 8-byte pointer, and the project avoids recovering information from neighbouring lines. `DEREF` now carries `op.resolvedType`, which `checkDerefBuiltin` was already setting but codegen never read.
- `CLONE` used to be emitted bare, the only operand-bearing mnemonic with no type annotation. It now carries argument and result types (the shape `NEG`/`NOT`/`DEREF` use) so AddressLoweringPass can size the pointee.
- `range` once had a real `RANGE` instruction. Retired: the length turned out to be known at compile time for string literals and fixed arrays (it was just being thrown away before codegen), so those fold to two PUSHes like `sizeof`/`len`; dynarrays reuse `LEN`.
- `bits_*` builtins: the exact shape was not specified, so it copies the nearest case (binary operator with operand-type annotations) rather than the unary builtins.
- `memcopy`: no dedicated shape was specified; follows the "push every argument, one instruction naming the operand types" shape.
- `NEW_DYN` / `NEW_UDYN` and `RESIZE` / `URESIZE`: an earlier version reused plain `NEW` for `dyn([..])`; split because safe and unsafe dynarrays have different allocation shapes (header or not) and resize forms carry different information (fill value or none). Same reasoning as the `LOOKUP` split into `LOOKUP_ARRAY`/`LOOKUP_DYN`.
- `dyn`/`resize` became throwing in their safe forms (owner decision: "new throws, but dyn and resize dont, they need to use the same pattern as new"); the unsafe forms were deliberately left non-throwing. The check was factored out of `emitNew` into `emitAllocFailureCheck`. At first it deliberately did not register with the ghost table; later `GT_REGISTER` was added before the check for safe `dyn`/`clone` (a failed registration frees and nulls so the OOM path runs).
- `insecure_rand()` is `rand()` through the shared call machinery (owner request), with no registered `ExternInfo`.
- `sizeof` of a struct became symbolic `SIZEOF` (resolved by `SizeofResolutionPass`) because the final layout is only known after the Optimizer.
- Call arguments: the register index used to be the per-argument loop index. Changed to a running counter (a range maps to two registers), then `ArgCounters` added bank awareness (int/float, SysV independent vs win64 shared) once float arguments existed.
- The null-out of a moved owns argument was moved to right after the value is captured and before the call ("I need to null it out before the function is called, not after"), so a throw in the callee cannot see the owner still set.
- By-value slice arguments (three words) and slice construction arguments used to be handled in `emitArgTransfer`; removed with the slice type.
- `PROMOTE_F32_TO_F64` and `VARARGS_XMM_COUNT` were added to fix `printf("%f", ..)` always printing 0.000000 for f32 variadic arguments; win64's float-in-both-registers duplication was added later as a separate, win64-only rule that happens to share the precondition (so it reuses the same boolean).
- `par`/`await`: used to be `PAR_CALL`/`AWAIT_CALL` mnemonics (substituted for CALL in `emitCall`). Replaced by the full desugaring in `emitAsyncCall`; the `emitCall` substitution is gone.
- The async handle local is allocated inline instead of hoisted with the other ALLOCs. Accepted, documented deviation: a par/await can appear anywhere in an expression, and extending the hoisting collector to scan arbitrary expressions was out of scope. Correctness does not depend on it (frame offsets come from ALLOC textual order). The `new ctor(..)` hidden local `$new_ctor_tmp` follows the same deviation.
- `new ctor(..)`: a struct-RVO call never pushes a result, so it constructs into a hidden local and pushes that.
- `new` originally lacked the ghost-table registration entirely: a fresh `new Point{..}` was silently unregistered and always read as not alive. `GT_REGISTER` was added right after `NEW`, mirroring `GT_INIT`/`GT_ALIVE_CHECK`/`GT_DESTRUCT` (same `requireGhostTableFunctionPresent` gate, no operand). Then `new` became throwing ("if it gets back NULL from the malloc, it throws"): `DUP_TOP` was reused for the null test; the null branch is deliberately a local `JMP`, not a replica of `emitThrow`'s unwinding ending.
- `emitAs`: the old single size-only `CAST` was replaced by `SEXT`/`ZEXT` ("cast just being instances where the compiler can unambiguously do it"). A `mut`/`imut` right-hand side of `as` used to get a zero-instruction branch; removed as dead code when the parser stopped accepting it.
- `emitStructInstantiate` once emitted a `NEW` instruction carrying member names to allow literal order to differ from declaration order; replaced by the value-type model (members pushed in declaration/layout order). Padding became `STACK_LOCK n` after the layout gained C-like padding. The hidden class id push was added at this choke point so `new X{..}` and bare `X{..}` stay in sync ("@untyped are exempt").
- `emitDot`: originally every `.` chain compiled to one `PUSH` of the dotted name; a pointer segment or LOOKUP/call base produced wrong/malformed output (`PUSH LOOKUP.x`), found against real bytecode, hence `isQualifiedNameableDot` and the DOT / DOT_LHS+DEREF split by storage.
- `escapeForBytecode` handled only three escapes; a `'\0'` char literal (needed for a bounds-safe `charAt` in the generic String class) leaked one raw NUL byte into the text bytecode. Found by inspecting emitted bytes; all lexer escapes are handled now.
- `emitLookup`: a scalar element read of a fixed array used to push the whole array then pick one element (O(array) per read; n-body did ~30 per pair); now address + `LOOKUP_LHS` + `DEREF`.

## Parser.java, first chunk (header, class doc, decorators, generics, call/lookup, keyword-block gathering)

- Class doc: the old header listed a pass order (nest, splitIntoLines, mergeLet, collapseImports, removeWhitespace, insertCallLookup, gatherKeywordBlocks) and said shunting-yard RPN, tree building, import resolution and type checking were "NOT yet implemented". Dropped as stale: `parse()` also runs template-string gathering, decorator stripping, `&&then` merging and generic collapsing, and the later stages exist.
- `?catch`: the "most recently encountered `?catch`" rule (rather than lexically scoped) was a deliberate choice, matching the spec's literal wording as closely as possible. The declared body is stored raw and cloned/gathered per use, modelled on how TypeChecker keeps the `impl default match @lock` policy template. A nested `?catch`/`?EXPR` inside a `?catch` block was flagged as a known, deliberately unaddressed gap (see ref.md).
- Only the first `?` per line is expanded; a second nested one was deliberately left unsupported rather than silently mishandled.
- `?catch` declaration is checked before the `try` scan because `catch` alone would otherwise be rejected as "'catch' without a preceding 'try'".
- Template strings: whitespace stripping inside `${...}` was added in `gatherTemplateStringsDeep` because the one gap found by testing was `${A + B}` reaching RpnConverter/TreeBuilder with WHITESPACE tokens. Patching every later pass individually was rejected (most could never matter for a compile-time-only expression). The CALL-marker walk into `${...}` was added so `${f()}` gives the dedicated compile-time-constant error instead of a raw `toRpn` parse error.
- `splitIntoLines` originally broke after any `{`; restricted to lines that start with a block-header keyword so struct-literal instantiations (`let point = Point{...}`) are not truncated after the opening brace.
- Decorators: parsed as "if a line starts with `@` it is a decorator till the end of the line". `@pub{}` (group several struct fields as public) was added as its own shape handled in `stripDecoratorsDeep` instead of extending `parseDecoratorLine`, which rejects a trailing `{`.
- `isDecoratorWord`: found and fixed when adding `par` as a statement-level keyword broke the pre-existing `@par` loop decorator and `@dont(par)` argument, which only expected a plain VARREF. Decorator words now accept VARREF or KEYWORD.
- `@lock(match ...)`: the enum style (`self.x : X`, with `X` also a `|` variant chain) was the original struct-level feature and later also usable on a method; the "in" style was added as a second qualifier shape (no mixing with the enum style). `within` accepted as an alternative to `in` per clause (and `into` appears in the code) and `Some(i)` wrapping was added to match the bare-match/for-match forms. The comment mentions only `in`/`within`; the code also accepts `into`.
- `@lock(match ...)` had two stacked Javadocs on `parseLockMatchQualifier` (the older enum-only one and the newer two-shape one); merged.
- `&&then`/`||then`: lazy chain evaluation operator; early design decision was that `&& then` and `&&then` are both just operators until BytecodeEmitter expands them. Not reserved as a keyword to avoid breaking variables named `then`; the `a && then` ambiguity is an accepted trade-off. The pass must run before CALL insertion.
- Generic instantiation: the colon form (`List:<u64>`) is required inside function bodies to avoid ambiguity with `<` comparison; headers use the bare form.
- Type-parameter bounds (`func f<T: SomeInterface>`) added as a grammar extension; single bare interface name only, no generic-interface bound and no `|`-chained bounds ("only ever asked for, only ever needed").
- `static func ...` header skip in `insertCallLookupInFlat` was added after `origin(` in `static func origin() mut u64{...}` got a spurious CALL marker that broke `gatherFunc`.
- Chained indexing (`grid[1][1]`): previously failed with "unexpected token '[', expected an operator" from RpnConverter - a pure parse-error gap (TypeChecker.checkLookup and the 2D array addressing fix were already correct). The earlier workaround ("bind the intermediate row to a `let` first") was only covering for this missing LOOKUP marker case.
- String literal as LOOKUP target was added for the bounds-checking default (only a direct literal has a compile-time-known length).
- `sleep` CALL marker added so `sleep(...)` reaches `TypeChecker.checkCall` in the ordinary shape.
- `unsafe`/`safe` blocks at root or inside functions were an explicit requirement; `assume match` follows the "wherever a match statement is valid" rule, with the block made optional.
- `ASM` has no `requireRoot` ("both roots and functions"), unlike the other declaration keywords.
- Dropped as stale/noise: the `gatherKeywordBlocks` Javadoc's list described only if/loop/func/struct/enum (the code handles many more; the ref.md section lists them from the code); `Parser`-level `confirmed directly` quotes.

## Parser.java chunk 2 (gather* methods) -- history
- `catch` originally could be written without a parameter; it now mandatorily takes exactly one bare untyped name (`catch{...}` is a parse error). The name was first parsed and checked at the higher levels with no runtime meaning in lowering yet ("parse and check correctly first, wire the semantics later", the same approach the `throw` message string took); the catch parameter later became the caught error (see CLAUDE.md, Stack traces).
- `try ... catch` restriction (nothing after the closing `}` on the line) was kept explicit to avoid silently mis-parsing shapes nothing downstream handles.
- The `?catch` body is parsed raw and deep-cloned per use site because gathering/type checking mutate tokens; a first use site would otherwise corrupt later ones. Precedent: the impl default lock-match policy template.
- `match` chains (`elsematch`, `else`) were requested as a mirror of `if` chains; `gatherMatchChain` duplicates ~15 lines of `gatherIfChain` on purpose (a shared version would need many parameters).
- Case-match `|`-chained labels came from the f32 state-modifier syntax (`|` chaining) and were generalised to all case labels. Cases separated by commas/semicolons/nothing were requested.
- Lock syntax history: `lock EXPR{...}` (with `@guard`) and `lock match EXPR{...}` and `match lock EXPR{...}` are all removed; only `match @lock` remains, with errors pointing at the new spelling. The `@` token keeps `match lock{...}` an ordinary match.
- `CLOSED:default[(args)]` is wrapped as an ordinary expression statement rather than a new Token field, so RpnConverter/TreeBuilder needed no changes.
- Extern decorators: `@call_convention` is accepted on `extern` because that is the real C/OS ABI boundary; other decorators are rejected in TypeChecker, not here.
- Struct `extends` was removed (composition + interfaces only); `library` still uses `extends TypeName;` statements (same extraction as interface).
- Enums: the nested-hierarchy grammar (variants as ranges of indices: start = pre-order index, end = last index in block) and range-valued variants (`HIGH:100..2000`) were added; `:` and `=` are both accepted after a variant name.
- Constructors: a `$`-prefixed synthetic name (like `$ret_dest`) was found not to work: it failed in the assembler because function names are emitted as symbols (`$` = immediate sigil, "operand size mismatch for `call'"), hence `__ctor__`. Generic constructors were added later by wrapping the func in an `impl`-shaped token instead of adding top-level dispatch cases to GenericsExpander.
- Static methods in impl: decorators on `static` lines were silently lost until `gatheredMethod.decorators` was copied from the line's first token.
- Dropped as stale: the comment before `isCaseMatchBody` (the older, pre-`|` description) duplicated by the newer one; the orphaned javadocs before `isLockStatementStart` (describing `gatherLockStatement`) and before `isDefaultLockMatchImplStart` were misplaced and are now attached to the right methods.
