# TypeChecker

Reference notes for `TypeChecker.java` (design, formats and rules). Design history is in [history.md](history.md).

## Design decisions

Covers: class-level rules of TypeChecker (stage 6).

- The checker runs over the import-resolved, tree-built program. Type equality is base-type only everywhere it compares types (arithmetic, comparisons, call-argument matching, duplicate-signature detection, return-type matching); storage and mutability are ignored in those comparisons. Reason given in the source: `let` has no type annotation, so every local gets its type from RHS inference, and every literal is `imut` by the literal-typing table; demanding exact mutability would reject nearly every realistic call or expression for reasons unrelated to types. Full mutability semantics were described as future work (the class comment calls mutability checking a stub; later code does enforce `const` and loop-immutable slots, see `Scope`).
- Canonical type strings (e.g. `raw_imut_string`, `imut_u64`, `imut_void`) are still built and stored in every token's `.resolvedType`, matching the bytecode-stage format; only the comparisons are base-type-only.
- `compiler.config` (`CompilerConfig`) is loaded once up front and is required (hard fail if absent). The checker validates every `@call_convention(name)` argument against the live set of declared conventions, resolves the convention of every func/extern/function-pointer type (default `config.defaultConvention`), and hands the config to BytecodeEmitter via `getConfig` so it reads each convention's argument-register count instead of a constant.

## Built-in names and sizes

Covers: `BUILTIN_NAMES`, `FLOAT_STATE_NAMES`, `PRIMITIVE_SIZE`, `POINTER_SIZE`.

- `BUILTIN_NAMES` are reserved and cannot be shadowed by a user function name (sizeof, len, range, deref, clone, call, the `bits_*` builtins, memcopy, dyn, resize, Some, insecure_rand, wrap, sat).
- `finite`, `infinite`, `nan` are not lexer keywords; they are recognised contextually (type-annotation position before `f32`, or the case labels of a match on an f32), like `default`.
- `PRIMITIVE_SIZE` (used only by `sizeof`): integer widths from `INTEGER_WIDTH`, f32 4, f64 8, `bool` and `char` assumed 1 byte (the C-style convention the string type follows; flagged as an assumption in the source). `POINTER_SIZE` is assumed 8 (64-bit) for every pointer of any storage or pointee.
- Unary minus on an unsigned type promotes to the matching signed type (`UNSIGNED_TO_SIGNED`). `INTEGER_WIDTH` drives `as`: widening-only casts within one signedness family. Types annotated as `pointerLikeBaseTypes` (`string`) must carry a storage modifier.

## Type model

Covers: `TypeInfo` fields, factories, with-methods, `canonical()`.

- `TypeInfo` is package-visible so BytecodeEmitter can reuse resolved type info. Fields: `storage` (nullable), `mutability` (`mut`/`imut`/`indeterminate`, null for the `null` literal), `baseType` (always the real, fully resolved representation, never an alias name).
- `aliasName`: the alias used at this reference. A nominal tag used only by exact-match comparisons (`typesCompatible`, `sameSignature`); every structural check and `canonical()` use `baseType`.
- Function pointers: `funcPtrParamTypes`, `funcPtrReturnType`, `funcPtrDecorators` are kept as real objects and never re-derived by parsing the `func(params)returnType` text in `baseType`. `baseType` excludes decorators; `typesCompatible` applies "a decorated function may satisfy an undecorated slot, never the reverse" as a subset check on the decorator set. `funcPtrCallConvention` is the pointer type's own resolved convention (part of the signature, used for all calls); INVOKE reads it from the pointer's static type because the target is unknown at compile time. Never null on a function-pointer TypeInfo (`funcPointer()` falls back to the config default), null on all others.
- `dynArrayElementType`: set only for a safe `dynarray(T)`; structural uses (element type for `[]`, resize fill value, dyn construction) read it directly instead of re-parsing `baseType`. The one exception is a type-annotation-only nested dynarray, where no such field exists and `parseDynArrayElementText` re-parses.
- `unsafeDynArrayElementType`: set only for `unsafe dynarray(T)`; a separate field (not a flag on the safe one) so `isDynArrayType(t)` (`t.dynArrayElementType != null`) keeps excluding the unsafe variant in every existing use (checkIn, resize, len, checkLookup, for-loop), with no risk of granting it bounds-checked privileges. `baseType` is `unsafe_dynarray(` + element text + `)`, a distinct string, which makes the two types mutually non-coercible through the existing exact-match checks with no extra code.
- `dynArrayElementText(elementType)`: the element text embedded in a dynarray `baseType` is the element's storage keyword (`owns`/`ref`/`raw`/`static`/`auto`) joined with `_` to its base type, if it has storage; mutability is deliberately left out (two dynarrays holding the same kind of element are the same type whether built from `mut`-wrapped or bare literals). A dynarray of plain values is unaffected. `parseDynArrayElementText` is the exact inverse; `DYN_ARRAY_ELEMENT_STORAGE_KEYWORDS` is the shared list so the two cannot drift.
- `arrayElementType`: set only for a fixed array built from a real value (`checkArrayLiteral`), not from an array-type annotation (which cannot express per-element storage; see `resolveTypeAnnotationRaw`'s array suffix handling). It is the fixed-array counterpart of `dynArrayElementType`: `checkLookup` returns the element with its storage (so `arr[i]` on an array of `owns mut Box` gives a pointer, not a storage-less `mut_Box`). `baseType` embeds only the element base type, as for dynarrays; the field changes nothing about `canonical()`/`typesCompatible` of the array type itself.
- `rawPointeeType`: set when a `raw` type's target is itself a full type annotation (`raw mut raw mut char`, needed for the C-ABI `main` signature). Scoped to `raw` only; nested ownership (`owns mut owns mut Foo`) has no obvious meaning and is not supported. `baseType` embeds the pointee's full recursive `canonical()` (its mutability is part of a pointer type's identity: `raw mut raw mut char` differs from `raw mut raw imut char`), so `canonical()` needs no special case.
- `isSome`: explicitly annotated `some` (non-null); meaningful only with `owns`/`ref`/`raw`/`static` storage (`auto` is non-null already; a no-storage value has no null question). Defaults false in every constructor and is set through `withSome(true)`: the project pattern is "add a with-method rather than a constructor parameter" (also `withMutability`, `withStorage`, `withConst`, `withFloatStates`, `withAtomic`). Every with-method copies all fields, including the literal-tracking ones, so none is dropped.
- `floatStates`: null = unconstrained; otherwise a proper non-empty subset of {finite, infinite, nan} (never all three: using all three is a syntax error, write the bare type). A `TreeSet` so iteration (hence the canonical string) is always alphabetical regardless of source order; validated where built; meaningful only on an f32/f64 base type.
- `isConst`: parameter or struct-member `const` ("const is always the leftmost thing" in an annotation; the local `let const` case is `Token.isConst`). A param/member `const` cannot be assigned, except in the one-true-constructor (OTC) pattern. Never affects `baseType`/`canonical()` (whether a slot can be reassigned is an assignment-site question).
- Literal tracking (integer tightening part 1): `literalValue` (BigInteger) holds the exact value of an integer literal (or a negated / `mut`/`imut`-wrapped one), default type `u64` (`s64` when negated); when the context demands a narrower or signed type and the value fits, the literal simply is that type (`typesCompatible`, `adaptLiteral`), after which its node is retagged and the field is gone. Not part of `canonical()`. Non-final so with-methods can carry it. `floatLiteral` (bare float literal, adapts to f32 or f64, f32 when unconstrained), `floatArrayLiteral` (array literal of float literals adapts as a whole), `literalElements` (array literal whose elements are all integer literals; adapts to a `T[n]` slot, e.g. `let:<mut u8[3]> s = mut [1, 2, 200]`).
- `isAtomic`: true when built by the `atomic` prefix operator (`checkAtomicWrapper`; atomic modifier only on types supported by atomic instructions, e.g. `atomic '!'`). `typesCompatible` ignores it (atomic and plain values of one base type interoperate), but `canonical()` embeds it, so PUSH/ASSIGN type-string operands carry the distinction with no new bytecode instruction.
- `canonical()` order: `storage_` then `some_` then `mutability_` then `atomic_` then float states joined with `|` (alphabetical) then `@decorator_` per function-pointer decorator (sorted; `@call_convention(name)` shows the resolved convention, other decorators bare), then `baseType`. Aliases never appear (no aliases in the bytecode).
- Factories: `funcPointer` (storage `static`), `dynArray` (always `owns`: heap-allocated, same ownership/GT_DESTRUCT machinery), `array` (`elemType[N]`), `rawPointer`, `unsafeDynArray` (always `owns`). `withMutability` is the one correct way to implement `mut X`/`imut X` wrapping (`checkMutabilityOf`); `withStorage` serves `checkAddressOf` (`raw x`/`ref x`/`auto x`/`static x`).

## Declaration tables

Covers: `StructInfo`, `EnumInfo`, `FuncInfo`, `ExternInfo`, `AsmInfo`, `InterfaceInfo`, `RawMethodSig`, `ImplInfo`, `LibraryInfo`.

- `StructInfo`: `members` is the final member set (a struct has no ancestors) filled by the flatten pass; `rawMemberLines` and `flattened` are the flatten pass's input and memo/cycle marker; `implementsNames` is a compile-time contract checked once all impls are collected. `classId` is the struct's value in the flat auto-generated `Class` enum (`generateClassHierarchyEnums`), the hidden `___type` first field populated by BytecodeEmitter `emitStruct`/`emitInstantiate` at every construction site; null for `@untyped`. `lockFieldName`/`lockVariants` come from `@lock(match self.x : X)` on a struct (x is always freely readable, every other member needs the proof). `swapFieldName` is the single `swap`-tagged mutex member: a `mut atomic`, plain, exactly-two-variant (`OPEN`/`CLOSED`) enum validated by `validateSwapMutexField`; if `lockFieldName` is also set the two must name the same field, which makes the existing "discriminant is freely readable" carve-out cover it. `defaultLockMatchPolicy`: see "Default lock-match policy".
- `EnumInfo`: `isNonExhaustive` (`@non_exhaustive` enum must end with `default`). `explicitValues`: positive integer discriminants, null unless the enum uses them at all; when non-null same length and order as `variants` (no partial mixing); read by `flattenEnum` validation, `BytecodeEmitter.emitEnum` and `checkGuaranteedEnumMembership` (the test for "u64 in EnumName"). `explicitRangeStarts`/`explicitRangeEnds`: a range-valued enum stores unique inclusive `[start, end]` pairs per variant; mutually exclusive with `explicitValues`, same no-partial-mixing rule, and not fungible with u64 enums because it compiles to a range. `isRangeValued()` tests this.
- `FuncInfo`: `mangledName` defaults to `name`; impl-method names are a naming-convention matter for CALL. `declOrder` (root-list position, impl method uses its impl's) supports the globals "cannot be referenced before declaration" check. `safetyTag` is `unsafe`/`safe`/`indeterminate` from the enclosing wrapper, set by collectFunc/collectImpl. `isExported` from `export foo` (BytecodeEmitter emits EXPORT in FUNC_START; never true for impl methods). `callConvention` resolved, never null after buildFuncInfo. `isAsync` (`@async`): such a function is invoked only through `par`/`await`, and `par`/`await` accept only `@async` functions (both directions enforced in checkCall). `isThrows` (`@throws`): required on, and only on, a function whose body contains `throw`; every call needs try/catch (`requireThrowsWrapping`). `sawThrow` is set when a `throw` is checked, so checkFunctionBody rejects `@throws` without any throw (mirror of "throw requires @throws"). `isPublic` + `enclosingImpl`/`enclosingLibrary` (back-pointers for visibility checks; the library is the one that declared the function, never one reached via `extends`). `eventLoopSafeLoopCount` counts bare `loop{}` statements already exempted in an `@event_loop` function (privileged: exactly one `loop{}` internally while staying safe). `ownsLocalTypes`: every owns-typed local across all scopes (name to type), so BytecodeEmitter can null a slot after its scope-end GT_DESTRUCT (needed for loop-body locals; see `emitDestructList`) without threading types through `Token.destructOnExit`. `mainArgShape`: null, `c_args` (`(imut s32, raw mut raw mut char)`) or `safe_args`; set only for the real `main` (`validateMainFunction`), read by `validateTickEventLoop` and BytecodeEmitter (whether a synthesized C-ABI wrapper is needed). `isConstructor`/`constructorConcreteName`: for `impl constructor for Name(...) self {...}` (collectFunc), read by checkInstantiate's OTC gate and checkNew/checkCall error messages.
- `ExternInfo`: `extern printf(static imut string,...) void`; a signature the linked assembly provides. No body, no `mangledName` (bytecode symbol is the bare name; C has no mangling), no overloading (`externs` is a name-keyed map; collectFunc/collectExtern cross-check namespaces). `linkName` is the real symbol (`@link_name(realName)` else `name`; see `validateDecoratorArgShape`). Parameters are unnamed (types only; never referenced from an expression). `hasVarargs`: trailing `...` allows any number of further unchecked arguments (not indeterminate). `callConvention`: externs accept decorators so the C/OS ABI boundary can name the right convention.
- `AsmInfo`: `ASM name { ... }` or `ASM name "path"`; opaque assembly never inspected beyond the `ASM_END` reservation check (done by the lexer for the block form, here for the file form). `rawText` is the final content for either form. `name` is null for an unnamed declaration, which is not referenceable and self-emits at its declaration point (collectRootAsm / checkStatement's `ASM` case).
- `InterfaceInfo`/`RawMethodSig`: raw (unresolved; `self` not yet concrete) method signatures. `methods` is the final flattened set (own plus extended interfaces, name-collision-checked); `ownMethods` is kept until the flatten pass consumes it. `isPublic` gates the interface itself only (every interface method is public). `RawMethodSig.isDefault`: from `@default func ...{...}`; `defaultBodyTok` is the interface's gathered func token, deep-cloned for each impl that omits the method (`collectImpl`, `materializeDefaultMethod`; overriding is optional). `decorators` (e.g. `@lock`/`@unlock` on `@guard` interface methods) are validated against the implementing method like `@overrides`/`@realizes`. `isStatic`: static signatures live in the same maps as instance ones (a clash of names is still a real collision), the flag keeps conformance checking and dispatch strictly separate.
- `ImplInfo`: `impl Iface for Concrete{...}` (interfaceName set) or `impl Concrete{...}` (null). `staticMethods` is a separate map from `methods` so that `TypeName.method(...)` is never reachable through an instance and instance methods never through the type, enforced structurally by which map dispatch looks in. Overloading: `methodOverloads`/`staticMethodOverloads` list every method by bare name in declaration order including the first; a second same-named method with a different signature is stored in `methods`/`staticMethods` under the key `name#signature` (so existing `.values()` walks still see it) and appended to the list. Only a bare `impl` may overload; an interface impl cannot. Look up through `candidates(name, isStatic)`, which falls back to the plain map. `isPublic` is an outer gate, checked in addition to each method's own `isPublic`; a `@pub` impl does not make its un-`@pub` methods public (they stay reachable only from within the impl). `safetyTag` lets a call-site-triggered generic-method instantiation be checked with the impl's own safety context.
- `LibraryInfo`: a library is a collection of functions dispatched by bare library name (`Math.sin(10.2)`), closest to a static-method-only impl with no struct, no instance, no `self`; same privacy rules as an impl; `extends` is unlimited (like interface extends, unlike a struct's single parent). `ownFunctions` maps name to all overloads declared directly (overloading is by full signature, name plus parameter types, unlike an impl); `functions` is the flattened set (collision-checked by full signature) built by `flattenLibrary`. `isPublic` mirrors `ImplInfo.isPublic` (`requireLibraryVisibility`).

## Visibility

Covers: `@pub` on structs, funcs, impls, libraries, interfaces, globals.

- Everything is private by default; `@pub` marks structs, enums, funcs, impls, libraries, interfaces and root-level globals. A private declaration is not nameable outside its declaring file.
- Containers gate their members: `StructInfo.isPublic` gates the struct regardless of member visibility; `StructInfo.publicMembers` come from a `@pub{}` block (private otherwise) and matter only when the struct is public (inferred by symmetry with the impl rule; not stated for structs). If an impl is not public, none of its methods can be reached outside its file; method funcs are gated by both `FuncInfo.isPublic` and `ImplInfo.isPublic`; a plain top-level func has just its own gate. Interface members are all public; the interface itself can be private. A library has the same rules as an impl.
- `StructInfo.memberDeclFile` records each member's original declaring file, propagated like `publicMembers`, so a private member's file-locality check is correct when reached through a struct declared in a different file than the member's origin.
- Globals: private by default (`publicGlobals`); a function-local `let static` is exempt (lexical scoping already governs it); the declaring file comes from `globalRhsByName.get(name).file`.

## Default lock-match policy

Covers: `DefaultLockMatchPolicy`, `StructInfo.defaultLockMatchPolicy`.

`impl default match @lock MyMutex{ CLOSED:(tries:imut u64,...) =>{...} }` declares a reusable, parameterized backoff/retry policy for the CLOSED case of `match @lock`, used as `CLOSED:default` or `CLOSED:default(args...)`. At most one per struct. It is stored as raw, ungathered tokens (as `Parser.gatherFunc` stashes a paramsTok/body): `rawParamsTok` is the `(` DELINEATOR token, whose first parameter is always the automatic per-iteration `tries` counter and is never supplied by the call site; `rawBodyLines` are the parser's `blockTok.childs`, never passed through gatherKeywordBlocks/RPN/tree-build. The template is never checked or lowered itself because its `break` must target whichever spin loop a use site generates. Each use site gets a deep-cloned copy that is gathered, RPN-converted, tree-built and then type-checked by `checkLockMatchStatement`'s default-policy handling.

## Generic impl methods

Covers: `ImplInfo.genericMethodTemplates`, `genericMethodInstances`, `unavailableGenericMethods`.

- A method token that `GenericsExpander` tagged with a non-null `Token.typeParams` (impl-level type parameters of its own, not consumed matching the target struct's generics) is held in `genericMethodTemplates` by name, not registered in `methods`/`staticMethods`: it is not callable until a call site supplies an explicit `:<U>` type argument (`checkGenericMethodCall`), when `instantiateGenericMethod` materializes a concrete FuncInfo into `genericMethodInstances`, keyed `methodName<arg1,arg2>` (same shape as GenericsExpander's memo key). The identical call at two sites reuses one instance.
- `unavailableGenericMethods` (key `Concrete.method`, or `__ctor__Concrete` for constructors): methods/constructors dropped from a generic impl instantiation because their signature is illegal for the chosen type argument (buildFuncInfo throws `DeferredSignatureException`, e.g. by-value struct parameter). They are never registered, checked or emitted; a call with no match gets the stored reasons appended to its "no match" error (`recordUnavailable`, `unavailableNote`).

## Generic constructors

Covers: `genericConstructorFuncInfos`, the third body-checking loop in `check()`.

A generic constructor's FuncInfo is registered by `collectImpl`'s `isConstructorDecl` branch straight into the shared `functions` overload map, not into any `ImplInfo`'s `methods`/`staticMethods`. `check()`'s two original body-checking loops (root `func` tokens, impl methods) therefore never reach it, so its body would never be `checkFunctionBody`'d and expression nodes inside (e.g. a nested `Slice:<T>{...}` OTC literal) would keep a null `resolvedType`, which BytecodeEmitter then prints as the literal text `null` in bytecode (`PUSH origin null`, `ASSIGN mut_Slice_u64 null mut_Slice_u64`) rather than crashing. `check()` runs a third loop over `genericConstructorFuncInfos` for this reason.

## Unsafe block tags

Covers: `UNSAFE_TAGS`, `NON_FREEING_UNSAFE_TAGS`, `UnsafeBlockRecord`, `SplitInfo`, `unsafeBypass`, `unsafeTagsNeeded`, `udynTag`.

- A statement-level `unsafe` block must name the reasons it needs (`unsafe deref extern{`), each matching one rule that otherwise needs a proof or is refused in safe code. Tags: extern, memcopy, raw, deref, clone, global, loop, udyn, udyn:owns, assume, call, asm, async, atomic, file, unaudited. `unaudited` is the catch-all: written alone, accepted whatever the block needs, says nothing about why; the stdlib may never use it.
- `NON_FREEING_UNSAFE_TAGS` (memcopy, raw, deref, clone, global, loop, atomic, assume) cannot free memory by themselves; a block with only these keeps alive proofs (see the `unsafe` statement case).
- `UnsafeBlockRecord` holds, per written block, the declared tags and the tags actually used (unioned over every check, e.g. per generic instantiation). `unsafeBypass(scope, tag)` is called wherever `unsafe` lets something through that safe code would refuse or demand a proof for: it returns true in unsafe context and records `tag` on the nearest enclosing tagged block (via `Scope.unsafeBlock`). Call it only when the bypass is really exercised (proof missing, or the operation is the unsafe one), so a declared-but-unneeded tag can be flagged.
- For `--fix unsafe-split`, the record also keeps per direct child statement (by position) its source line, whether it is a bare `assume match`, and the tags it needed (`noteChild`/`use`), plus `unattributed` tags used while no child was being checked. `unsafeSplitInfo()` exports them as `SplitInfo`. `unsafeTagsNeeded()` (for `--audit`) returns tags needed per `absolute file:line`.
- `udynTag`: an operation on an unsafe dynarray needs `udyn:owns` when its elements own memory (the programmer destructs them by hand), else `udyn`.
- Ownership helpers used by ProofKills and drop/clone glue: `typeOwnsMemory` (owns pointer, dynarray, or inline struct with such a member), `pointeeOf` (struct a `ref` points at; null means any destroying event ends the proof), `destroyedTypes`/`collectDestroyed` (types an object can contain by ownership; null = unknown), `isInlineOwningStruct` (no storage keyword, owns memory through some member), `stripArrayDims` (`Holder[2][3]` to `Holder`: a fixed array of inline owning structs is an owned slot too), `elementTextOwnsMemory` (dynarray element text such as `Holder`, `owns_some_mut_World`).

## Scope

Covers: `Scope` and its constructors.

Each constructor copies the parent's inherited fields and overrides some:
- `vars`, `staticNames` (`let static`, needed by checkAddressOf's `static` case), `constNames` (`let const`, local counterpart of `TypeInfo.isConst`, consulted by `isConstName` through parent scopes), `localAsmNames` (function-local ASM names, lexical, added only once the declaration is checked, unlike the whole-function-visible root registry).
- `ownLoopImmutableSlots`/`isLoopImmutable`: slot keys (variable names or simple `a.b` paths) unassignable for the dynamic extent of a `for`/`for match` loop body: the loop variable and its source expression ("both i and arr are immutable within a for loop"). Different from `constNames`: those are consulted only at the declaring scope and are permanent; this is checked at every scope of the chain, because the loop's source variable is declared outside the loop and must be immutable only for its duration.
- `movedSlots`: slots (variable or `a.b` path) currently holding a moved-away owns value, shared by reference across all scopes of one function (moves are not lexically scoped: a move in a nested `if` is visible after it). A constructor with `movedSlotsOverride` gives an isolated copy for branch checking.
- `currentSafety`: `unsafe`/`safe`/`indeterminate`, inherited, overridden by a nested `unsafe`/`safe` block. `unsafeBlock`: the tagged unsafe block the scope sits in. `transparent` (`unsafe`/`safe` blocks are permission markers, not scopes): `declare` forwards to the parent, `declScope()` finds the nearest real scope.
- `activeMatchPatterns`: proven `MatchPattern`s, inherited and extended on entering a match (immutable, never popped; leaving the block means using a scope that lacks them); `ProofKills.stamp` is called on the extended list. `suspendsSelfRecursion`: true inside the required `match RANGE_PARAM is base{...}` of a `@recursive` function; checkCall/checkMethodCall reject self-calls there; a plain `else` branch gets none of the match body's proof privileges.
- `ownsDeclaredHere`: owns slots declared directly in this scope, in order, not inherited (destruction is per block); filled by checkAssign's `let` branch and by checkFunctionBody for owns parameters (in the function root scope). `functionRootScope` (itself at the root): where a `return`'s destruct walk stops; values preserved by `return` are not destructed. `loopBoundaryScope`: innermost loop body (null outside); a `break` walks up to and including it; reset by each nested loop, unchanged through `if`. `tryBlockBoundaryScope`: same shape for `try { }`; a `continue` inside a `catch(e){}` body (an explicit form of the plain catch fallthrough) destructs/unlocks up to it and jumps just past the try block's closing brace (the fallthrough point; whatever the try body declared, including the catch variable, is already out of scope there).
- `insideDynArrayForLoopBody`: true in the body of `for i in dynarrayExpr{...}` (not plain `loop` or range-sourced `for`): the dynarray may not be resized, even indirectly through another function. Inherited like `currentSafety`, but can only be turned on by nested code.
- `activeLockReleases`: already type-checked synthesized unlock/release calls owed on exit, in acquisition order, inherited and extended (copy-and-append) by a `lock EXPR{...}` body or `match @lock` OPEN body. `return` reads the whole list (a lock is function-bound); `break` the suffix beyond the loop boundary's list.
- A dedicated `TryBlockBoundaryMarker` type exists only to give the try-block constructor a signature distinct from `Scope(Scope, boolean, boolean)` (erasure would collide).

## Whole-program flags

Covers: `usesOwnsRefDynNew`, `usesThrow`, `ghostTableFunctions`, `eventLoopFunc`.

- `usesOwnsRefDynNew`: syntactic-presence flag over the final generics-expanded tree, set the instant any `owns`/`ref` storage modifier (in any type annotation: parameter, return type, struct member, function-pointer signature, bound-type `let`), a `new` expression, or a `dyn(...)` call is encountered, whether or not the function is ever called. Read once by BytecodeEmitter at the real entry point (see `emitFunc` dundering) to require `GT_INIT` before any expression of main; whole-program, never per function.
- `usesThrow`: set when any `throw` is type-checked (`checkThrow`); `usesThrow()` also returns true when stack tracing is on (`TraceConfig.usesTrace`) because tracing needs the throw-style frame layout in every function. `BytecodeEmitter.emitGtRoutinePrologue` emits the per-function `gt_routine`/`GT_UNWIND` machinery only when needed; a `throw` instruction (`THROW string_id label`) always names its function's `gt_routine` label, so the prologue condition is `usesOwnsRefDynNew || usesThrow()`, otherwise a program using only `throw` would point at an unemitted label.
- `ghostTableFunctions`: at most one function in the compilation unit per ghost-table decorator (`@gt_init`, `@gt_alive_check`, `@gt_destruct`, `@gt_register`, ...), filled by `validateGhostTableDecoratorSignatures` while functions are collected; `getGhostTableFunction(name)` returns it or null. A ghost-table instruction (GT_DESTRUCT, GT_ALIVE_CHECK) requires the decorated function to exist, enforced where the instruction is emitted.
- `eventLoopFunc`: null unless `main` is `@with_tick`; set once by `validateTickEventLoop`; BytecodeEmitter dunders `main` in favour of it.

## Checker context flags

Covers: `insideThrowingAllocContext`, `insideCatchBody`, `catchEnclosingLoopBoundary`, `userLoopScopes`, `lockClosedLoopScope`, `breakCountsAsTerminator`, `insideShortCircuitEligiblePosition`, `insideStructRvoDestinationPosition`, `insideConstructorBodyForStruct`, `directReturnExprNode`.

- `insideThrowingAllocContext`: true while checking anything under a `try new/dyn/resize ... catch(e){...}` wrapper. A throwing allocation's operand can contain nested throwing allocations (e.g. `new String{chars= new DynamicArray{...}}`, real in `String.from`), and `checkTry` wraps only one direct `new`/`dyn`/`resize`/CALL node (a `try...catch` always ends its line, so no second `try...catch` can be written around the inner one), so a per-token `insideTry` flag (still used by `requireThrowsWrapping` for a wrapped CALL) cannot reach nested nodes. The context flag covers the whole recursive descent; one source-level `try...catch` covers every allocation failure at any depth. In bytecode this falls out because `emitNew` and the `dyn`/`resize` null checks read `pendingTryCatchLabel`, which stays set for the whole nested `emitExpr` descent of `emitTryGuardedCall`.
- `insideCatchBody`: true in a `catch(e){}` body, the only place `continue` (try-block-exiting sense) is legal; saved/restored around the one call site (`checkTry`) rather than threaded as a parameter; narrower than Scope's lexical fields because it asks "am I lexically in a catch body", independent of any scope's ancestry. `catchEnclosingLoopBoundary`: the innermost loop boundary when the catch body started; a `continue` whose loop boundary is still that one belongs to the catch (skip past the try block), one inside a loop opened within the catch belongs to that loop. `userLoopScopes`: loop-body scopes of user-written `for`/`loop` (not the synthesized `match @lock` spin loop): the only scopes a loop `continue` may target.
- `lockClosedLoopScope`: spin-loop scope of the `match @lock` CLOSED case being checked (null elsewhere and for OPEN); a `continue` directly inside retries the acquire; save/restored around each `match @lock`. `lockRetryContinuesSeen` counts such retry continues. `breakCountsAsTerminator` is true only while `closedCaseTerminates` runs, making `statementDefinitelyReturns` count `break` as a terminator: every path of a CLOSED body must end in continue / return / throw / break.
- `insideShortCircuitEligiblePosition` (lazy chain evaluation, `&&then`/`||then`; "only work at the top level of an expression in a conditional (if or else if)"): single-shot, true only for the next `resolveExprType` call. Consumed (read, then reset to false) at the top of `resolveOperatorType`, the choke point every operator-shaped node passes through, and passed to `checkLogical` as a parameter (reading it inside checkLogical would be too late). Set true in `checkIfChain` around the condition's first `resolveExprType`, and in `checkLogical` around each operand only when the op is itself `&&then`/`||then`. So "top level" means the root condition or reached from it through further `&&then`/`||then` nodes only. A then-node under `!`, a call argument, a comparison operand, a `match`, or as an operand of plain `&&`/`||` is rejected: eager `&&`/`||` evaluates both sides into one value, while a then-node has no value form (it lowers only to a jump cascade, `BytecodeEmitter.emitShortCircuit`). This is a deliberately narrower reading of "top level" than the user's wording allows, because the wider one has no sound single-value codegen and the user's examples never exercise it.
- `insideStructRvoDestinationPosition` (Return Value Optimization: a function returning a struct by value writes through a hidden struct pointer in the parent frame): single-shot like the previous flag, same consumption point; a separate flag for a separate restriction. True in exactly two places, both in `checkAssign`: around a plain (non-`static`) `let` RHS, and around a plain `=` RHS whose left side is a bare variable. Not set for a `return` (comment as written; unclear, project notes list `return f()` as legal today): forwarding the function's own hidden destination into another call would need different codegen (no local destination to take the address of), not implemented; a struct-RVO call anywhere else (argument, struct-literal field, nested sub-expression) is rejected by `checkCall`'s generic "not one of the two legal positions" error. Keeping the destination to a whole bare local means the caller codegen is always "take this local's address and pass it" (`BytecodeEmitter.emitStructRvoAssign`). Dotted or indexed destinations (`p.field = f()`, array element) are a possible future extension.
- `insideConstructorBodyForStruct`: the struct whose constructor body is being checked (set unconditionally by `checkFunctionBody` around a constructor body; no save/restore because functions never nest, as with `pendingOptionalCatchParamName`'s reset). Read by `checkInstantiate`'s one-true-constructor (OTC) gate: once a struct declares any constructor (`hasConstructors`), its bare `StructName{...}` literal is illegal everywhere except inside a constructor of that struct (on the stack or via `new`); other structs' constructors and ordinary functions cannot use it.
- `directReturnExprNode`: set by `checkReturn` while resolving its expression to the exact node that is the sole expression of the `return`; identity-compared (never by shape) against `CALL` nodes at each self-call site deep in `resolveExprType`, to tell a bare tail self-call (legal for `@recursive`) from one nested in a larger expression (`requireRecursiveCallReturnSiteOnly`). Nested calls never touch it, so no further bookkeeping is needed.

## Entry point and pass order

Covers: `check()`, `flattenRootLines`, `FlatDecl`, `rootLinesRef`.

- `flattenRootLines` recurses into root-level `unsafe`/`safe` wrapper tokens (their contents are ordinary gathered root lines) and returns `FlatDecl`s (the declaration line plus its enclosing safety context); every pass iterates this instead of `rootLines`. An `unsafe` inside `safe` is a compile error (checked structurally on discovery); `safe` inside `unsafe` is allowed. An unsafe or safe block can appear at the root or in a func.
- `rootLinesRef` is the same list object `check(...)` received; BytecodeEmitter's top-level emit walks that identical list (Main passes the same `expanded` object to both), so root tokens appended during checking (par's synthesized `AsyncHandle_T` struct/impl, `getOrCreateAsyncHandleType`) are visible to emission.
- `check` order: `collectDeclarations`, `forceGhostTableFunctionNames`, `validateGenericBounds`, then `checkFunctionBody` for root funcs, impl methods and static methods, library functions, and generic constructors (the last via `genericConstructorFuncInfos`); then `checkSafetyCallGraph`, `checkDynArrayForLoopResizeSafety`, `checkNoRecursion`, `validateNoThrowReachableFromGhostTableFunctions`, `validateNoAutoReturns`, `validateNoRefSomeStructMembers`, `validateNoAutoStructMembers`, `validateNoRecursiveStructs`, `validateNoPointersInLockStructs`, `validateMainFunction`, `validateUnsafeBlockTags`.
- `checkProofKills` collects every defined function (top-level, impl methods, static methods, generic method instances, library functions) plus extern link names and names, for `ProofKills.check`.

## main, @tick, @event_loop, @make_safe_args

Covers: `validateMainFunction`, `validateAndResolveMainArgShape`, `safeArgsType`, `validateMakeSafeArgs`, `validateTickEventLoop`, `requireOwnsSomeMutStruct`, `findFuncsWithDecorator`.

- `validateMainFunction` runs once at the end of `check`, over the final import-flattened `functions` map (a whole-compilation-unit, not per-file, requirement): there must be exactly one `main`. Allowed return types: `imut s32`, `imut bool`, `void` (unless `@with_tick`). The return type is `s32`, not `int`, deliberately: it must match what the OS expects as an exit code, i.e. C's 32-bit signed `int` on every mainstream platform, which `s32` already is (no new type needed).
- Argument shapes (`validateAndResolveMainArgShape` returns null / `c_args` / `safe_args`): none; the C-ABI `(imut s32, raw mut raw mut char)` (argc/argv; `int` mapped to `s32`); or the safe wrapped shape `safeArgsType()`.
- `safeArgsType()`: `owns some mut dynarray(imut dynarray(imut char))`: an owned outer dynarray of plain, immutable inner dynarrays of immutable chars (a built-in dynarray's elements can never themselves be `owns`-tagged; only the whole dynarray as a unit can). The nested `dynarray(dynarray(char))` type was tested to parse and type-check since nothing else exercised it.
- `@make_safe_args`: required exactly once if and only if `main` uses `safe_args` (tied to `main.mainArgShape`, not to whether `@event_loop` exists: something must be able to call it, whether a compiler-synthesized wrapper or the stdlib event-loop body); at most one otherwise. Required signature `func(argc: imut s32, argv: raw mut raw mut char)` returning `safeArgsType()`. It copies the real arguments (neither parameter is `owns`, so nothing is moved out of the caller's argc/argv); the copying is its own implementation and is not verified.
- `@with_tick`, `@tick`, `@event_loop` (found by decorator via `findFuncsWithDecorator`, not by name): `@tick` and `@event_loop` may appear only when `main` is `@with_tick`, and then each is required exactly once. `@tick` takes exactly one parameter and returns the same type: `owns some mut` of a concrete struct (`requireOwnsSomeMutStruct`; a real struct name the programmer writes, no new generic syntax; returns the struct name for the "same T" comparison). `main` then returns that same struct (the signature is taken from `@tick`). `@event_loop` is the real entry point (the function `main` is dundered to): with no `main` args it takes none; with args it takes `(imut s32, raw mut raw mut char)` so raw C-ABI arguments are wired through; it returns `imut s32`, `imut bool` or `void` (a `main` signature that does not return a pointer). Only its signature is validated, not its body: different event-loop stdlib variants per eventuality are the programmer's choice (as with `@gt_destruct`). The result is stored in `eventLoopFunc`.

## collectDeclarations passes

Covers: `collectDeclarations` pass 1a..1f.

- 1a: register structs, enums, interfaces, libraries (name only), aliases (`type`), consts raw: own content captured, nothing cross-referenced yet, because one struct/interface may extend another declared later. Globals are skipped here (pass 1a.8).
- 1a.5: flatten every struct's members and interface's methods, recursively resolving `extends` chains (memoized, circular-inheritance detected). Must finish before impls are validated (an impl checks its interface's flattened set) and before globals (an initializer may construct a struct literal).
- 1a.6: record each func/impl/library position (and each impl/library method's, which share the impl's) in `pendingDeclOrder`; collectFunc/collectImpl set `FuncInfo.declOrder` from it. Needed because a function body is checked in pass 2 when every global already exists in `globals`, so map membership alone cannot enforce "cannot be referenced before declaration" for function bodies.
- 1a.7: externs, before func/impl collection, so an ordinary func with a colliding name is caught at its own declaration site (collectFunc checks `externs`).
- 1a.8: globals in strict file order: each initializer is checked against only the globals registered so far, which gives "cannot be referenced before declaration" for global-to-global references naturally; references from function bodies use the explicit `declOrder` comparison (VARREF case in `resolveExprTypeInner`).
- 1b: func, impl, `impl_default_lock_match`, library collection. 1b.5: flatten library `extends` chains (needs each library's resolved function set for its full-signature collision check, so it cannot be done in 1a.5).
- 1c: each struct's `implements` clause is a compile-time contract; a matching `impl X for Y{...}` must exist (`checkImplementsContract`). 1c-bis: `generateClassHierarchyEnums` (flat `Class` enum over non-`@untyped` structs, sets `classId`) then `generateEnumForEnums` ("enum for X" interface-implementer membership enums); must run after all impls are collected and `implsByConcreteType` is populated, and in that order. 1c-ter: `generateInterfaceDispatchers` (one dispatcher per interface/method pair) after `generateEnumForEnums` (needs each interface's `$enum_for_X` list) and after impl validation, so every implementer has a callable method to dispatch to.
- 1d: `export` statements, each referencing an already-collected, unambiguous, non-generic top-level func (so after 1b; "ambiguous -- C has no overloading" is checked in `collectExport`).
- 1e: root-level ASM declarations and `asm_name;` invocations together in strict file order: a root-level invocation may reference only a name declared earlier in the walk (forward reference rejected, matching the globals rule). A function body's reference to a root ASM is unconditional (all root ASMs exist before any body is checked; the same asymmetry as globals), handled in checkStatement/resolveExprTypeInner.
- 1f: overloaded plain top-level functions are disambiguated at the bytecode level (previously two overloads emitted identically named FUNC_START/CALL pairs): `mangledName = name + "__sig_" + signatureSuffix(paramTypes)`, reusing the library mechanism, but only when a name has more than one overload. Unmangled single-overload names mean nothing that compares a mangled name against a literal needs to change: `main` has one overload (its three signatures differ only in return type, and two zero-parameter same-name functions are already a duplicate error), each `@gt_*` decorator is limited to one function (registerGhostTableFunction), `@tick`/`@event_loop` are required exactly once, and `export` requires exactly one overload (collectExport already ran). Impl methods are never overloaded within one impl block this way and live in a different map, so are unaffected.
- Other tables: `aliasRawTargets` (aliases resolved lazily per usage via `resolveTypeAnnotation`/`expandAliases`, so an unused alias is never validated); `constExprs`/`constResolvedValues`/`constsBeingEvaluated` (`const NAME EXPR` is pure compile-time textual substitution: the expression root is stored unevaluated, consts are forward-declarable, so evaluation is lazy on first reference with memoization and cycle detection like flattenStruct/flattenInterface); `globals`, `globalDeclOrder`, `globalOrder` (stable GLOBAL emission order), `globalRhsByName`; `rootAsms`/`lookupAsmName` (scope chain first, then root); `exportedNames` (a second export of a name, or of overloads sharing a bare name, is an error; checked against this set before the target overload is resolved); `structDeclOrder` (declaration order for the Class/ClassID hierarchy and every `enum for` list); `externs`, `libraries` (name space shared with structs/enums/interfaces, cross-checked by registerLibraryName); `forVarCounter` (unique hidden range-binding variable names for `for` desugaring).

## Top-level declaration collection
Covers: `collectRootAsmDeclaration`, `collectRootAsmInvocation`, `collectGlobal`, `requireTopLevelDecl`, `registerAlias`, `registerConst`, `registerLibraryName`, `registerStructLike`.

- Root `ASM` declarations and bare `asm_name;` invocations require `unsafe`. An unnamed ASM is never registered (BytecodeEmitter reads `t.resolvedAsmContent` and emits it directly); a named one goes into `rootAsms`. An invocation of an unknown name (or used before its declaration) is an error.
- `let static NAME = ...` at the root:
  - the RHS obeys the same static-instantiation rules as a local static: compile-time constants only (`checkNoRuntimeConstructs`) and the same mutability requirement (`requireStaticMutable`);
  - unlike a local static (which resolves in a fully empty scope that rejects every variable reference), a global's initializer may reference an *earlier* global. This works by resolving through a synthetic `FuncInfo` that carries only the global's own `declOrder`, so the ordinary VARREF-fallback-to-globals path rejects any global at or after this position ("cannot be referenced before declaration"), the same rule a function body gets;
  - an explicit type bound (`let static:<mut f64> g = mut 0.5`) is checked and literal-adapted like a local's (`resolveAndValidateTypeBound`);
  - an atomic RHS keeps `isAtomic` only for a direct atomic declaration (`isDirectAtomicDeclaration`); merely reading an atomic value strips it;
  - a plain `let` (non-static) at the root is an error; allowed decorators: `GLOBAL_DECORATORS` (`pub`).
- `requireTopLevelDecl`: a root line must be exactly one token. A bare VARREF line is let through unconditionally (it can only be an ASM invocation; `collectAsmInvocations` validates the name and gives an ASM-specific message). Otherwise the keyword must be one of struct, enum, func, interface, impl, impl_default_lock_match, library, type, extern, export, ASM, const.
- `type NAME <target>`: stores the raw target token span in `aliasRawTargets`. Collision-checked against the struct/enum/interface/library namespace. Globals are not registered yet at that point, so `collectGlobal` checks `aliasRawTargets` from its own side (two-sided check, so the order in the file does not matter).
- `const NAME EXPR`: registered raw in `constExprs` (expression tree from `t.childs.get(0)`) and never evaluated at registration: consts are forward-declarable (`const A B` before `const B 5` is fine); evaluation is lazy, on first reference (`resolveConstValue`). Collision-checked against struct/enum/interface/type/library here; func/global collision is checked from their side against `constExprs` (same two-sided pattern as `registerAlias`/`registerStructLike`).
- Library names share the struct/enum/interface namespace. Registration is raw (name, extends, decorators); the library's functions are built later in `collectLibrary` (pass 1b), once structs/interfaces are flattened (parameter/return types may refer to either). Structs may be registered raw first because one may extend/refer to another declared later.
- `@unpadded` on a struct is recognised but rejected with a specific "not supported yet" error: every struct is padded to its natural alignment by `emitStruct` and no unpadded lowering exists. It stays in `STRUCT_DECORATORS` so the user gets this named rejection instead of the generic "not a decorator" one (same "recognised but not yet supported" shape used for a few other reserved names).
- `checkImplementsContract`: every `implements I` on a struct needs a matching `impl I for S{...}` somewhere in the compilation unit.

## Struct flattening and @lock clauses
Covers: `flattenStruct`, `validateSwapMutexField`, `validateLockEnumClause`.

- A struct has only its own members (struct inheritance does not exist). At most one member may be `swap`-tagged.
- The `swap` member must be an enum-typed atomic, a plain enum with exactly two variants named `OPEN` and `CLOSED` (mandatory names; this is what lets `checkLockMatchStatement` build acquire/release `ATOMIC_SWAP` calls against fixed names with no configuration).
- A struct-level `@lock(match self.x : X)` is validated at the end of `flattenStruct`, after the struct's members are known (not during collection, when member types are unresolved):
  - the field exists, is enum-typed, and every named variant is a variant of that enum (`validateLockEnumClause`, shared with the method-level form);
  - the first user-declared member (the hidden `___type` is not in `info.members`) must be the lock field;
  - if the struct also has a `swap` member, the decorator must name that same field (the plain `imut` discriminant flavour and the `mut`+`atomic`+`swap` flavour are never mixed). Then the existing carve-out "the discriminant field is always freely readable" covers the swap field with no extra exemption.

## Method-level @lock
Covers: `validateMethodLocks`, `validateLockInClause`, `requireIdenticalLocks`, `describeLockMismatch`, `filterQualifiedLockDecorators`.

- `@lock(match ...)` may qualify any method of an impl, an impl for an interface, or an interface signature. A method may carry several; each is validated, and later required at every call site, independently. Only meaningful for a struct receiver (an enum has no `self.x2` to lock). The plain argument-less `@lock` method decorator is gone (see Decorators).
- `@lock(match x in self.x2)` / `within`: `x` is an `imut` parameter of the method; `x2` a member. The clause is checked against the exact rules of `checkIn` (left: plain `u64` or range; right: range or dynarray) or, for `within`, `checkWithin` (left and right both range). The rule set is chosen per clause by `d.lockInOperators`.
- `@lock(match Some(i) in self.x)`: the same index-bounds-plus-element-alive sugar as the bare-match and for-match forms; `self.field` must be a dynarray of pointer-typed elements (the requirement `checkSomeIndexBoundsCondition` enforces for the other two forms).
- Interface conformance: an interface method's qualified `@lock(match ...)` clauses must be repeated exactly, in order, by every implementing method. "In"-style clauses are matched by parameter *position*, not name (interface conformance is type/position based; `validateExactSignatureMatch` never compares parameter names). Exact matching also covers: the same field, the same operator (`in` vs `within`: they grant the same proof but are a different written contract), and the same `Some(...)` wrapping (no superset/subset: a plain `in` implementation never satisfies a `Some`-wrapped interface clause or vice versa).

## Enums
Covers: `collectEnum`.

- Duplicate variant names are errors. An enum is plain, u64-valued (explicit values) or range-valued (explicit ranges), never a mix of the last two. No partial mixing within a form: either every variant has an explicit value/range or none does. Duplicate explicit values or identical ranges are errors; a range whose start exceeds its end is an error. `@non_exhaustive` is the only enum decorator. An interface cannot be implemented for an enum.

## Interfaces
Covers: `registerInterface`, `validateInterfaceMethodDecorators`, `forbidSelfReference(In)`, `flattenInterface`, `validateSelfIsPointer`, `checkSelfStorageInTypeTokens`.

- `interface Name{ method(params) ret; ... }`: each signature is kept raw (`RawMethodSig`) because `self` is not a concrete type yet; only validated structurally. Full resolution is per implementation, in `collectImpl`.
- Every `self` occurrence in a signature must carry a storage modifier (owns/ref/raw/auto/static): `self` is always a pointer.
- Methods with a body (parsed via full `func` syntax, `Parser.gatherInterface`) must be labelled `@default`; a signature-only method may not be. `@overrides`/`@realizes` never decorate an interface's own declaration (they belong to impl methods).
- `self` cannot be used at all (signature or body) in a `@default` method or in a static method/signature: neither is dispatched on an instance to substitute a concrete `self` into. This is an unconditional recursive rejection (`forbidSelfReference`), not the "if present, it must be a pointer" check.
- Interface members are all public.
- `flattenInterface`: `extends` has no cap (an interface can extend many). Every extended interface's flattened set is merged in, then the own methods; a name collision (via two parents, or parent plus own) is an error; cycles are an error.

## Impl collection
Covers: `collectImpl`, `collectDefaultLockMatchPolicy`, `substituteSelfInPlace`, `substituteSelfCopy`.

- `impl Interface for Concrete{...}` or `impl Concrete{...}`. An interface cannot be implemented for an enum. An interface impl must match the interface's method set exactly (no more, no less; omitting a `@default` method is allowed). A method whose name and full signature is ambiguous across impls of the same concrete type (two interfaces, a bare impl plus an interface impl, or two bare impls) is a declaration-time error ("cannot be resolved at the call site"). At most one bare impl block per type; at most one impl of each interface per type.
- Mangled names (used for CALL, never for signature/type matching; interface/impl membership is a naming convention only): `Concrete__Interface_method` for an interface impl, `Concrete_method` for a bare one; static methods get `static_` spliced in so an instance and a static method of the same name cannot collide at the bytecode level.
- `self` is replaced by the concrete type name in place (params and return tokens) before `buildFuncInfo`.
- A bare impl may not use `@default`, `@overrides` or `@realizes`.
- Residual-generic methods (the method has its own type parameters, tagged by GenericsExpander): held back in `implInfo.genericMethodTemplates`, instantiated on demand by a call site's explicit `:<U>`; their tokens are removed from `t.childs` after the loop (BytecodeEmitter's `impl` case walks `t.childs` and would otherwise find no FuncInfo). Only instance methods may be residual-generic (a static one would need parallel handling in `checkStaticMethodCall`). Such a name may not clash with an interface method name.
- Generic constructors (`impl<T> constructor for Concrete<T>(...) self {...}`): `Parser.gatherConstructorImpl` wraps them in an impl-shaped token so GenericsExpander's impl-template machinery can instantiate them. After monomorphization `methodTok.sub.get(0).text` is `__ctor__<mangledStructName>` and `constructorConcreteName` names the mangled struct. They are registered like a non-generic constructor in `collectFunc` (ordinary overloaded `FuncInfo` under the shared `functions` map, not `implInfo.methods`: a constructor is only called as `Concrete(...)` / `new Concrete(...)`), but left in `t.childs`: BytecodeEmitter's `impl` case still walks it to emit bodies and special-cases `isConstructorDecl` to find the FuncInfo with `findFuncInfo`. An impl made only of constructors is not a "bare impl block" for the one-bare-impl rule (several may sit beside each other and beside a real bare impl).
- A method that throws `DeferredSignatureException` (by-value struct parameter after generic instantiation) is dropped and remembered (`recordUnavailable`); if every method of the impl is unavailable the impl is skipped.
- `impl default match @lock S{ CLOSED:(tries:imut u64,...)=>{...} }`: registers a reusable CLOSED-case backoff/retry policy for a swap-tagged mutex struct (`DefaultLockMatchPolicy`). Validated once, eagerly, in Pass 1b (after every struct is flattened): the struct must exist and have a swap field; at most one policy per struct; the parameter list needs at least one parameter whose first is exactly `imut u64` (the automatic per-iteration `tries` counter, never supplied by a `CLOSED:default(...)` call site). Only the parameter shape is checked; the body is cloned and checked at each real use site (checking it unbound to a spin loop would give its `break` nothing to target).

## Default interface methods
Covers: `materializeDefaultMethod`, `deepCloneCheckedTree`.

- An impl may omit a `@default` method. `materializeDefaultMethod` then creates a callable entry: the interface's `defaultBodyTok` is deep-cloned once per impl (one default may be inherited by many types, each needing its own Token tree), wrapped in a `LINE` token and run through a fresh `RpnConverter`/`TreeBuilder` (RpnConverter and TreeBuilder return immediately on `interface` tokens, so the stored body is still in the gathered, pre-RPN, pre-tree shape; the same fix-up is used for `impl default match @lock` policy bodies at their use site, `substituteDefaultLockMatchPolicyIfPresent`).
- None of the user-impl validations apply (labelling, exact signature match, `@pub`): it is the interface's own signature and body by construction. The method is forced public (it must be, to satisfy the interface, and a `@default` source need not carry `@pub`). Self substitution still runs (harmless no-op, a default cannot mention `self`). Mangled name `Concrete__Interface_method`, method locks validated.
- The cloned Token is appended to the impl token's `childs`: BytecodeEmitter's `impl` case walks those (matching FuncInfo purely by Token identity), never `implInfo.methods`/`staticMethods`.
- `deepCloneCheckedTree` clones a gathered/RPN-converted/tree-built, not yet type-checked tree: same state GenericsExpander clones for monomorphization; copied here because that one is private. It deliberately does not use `Token.deepCloneRaw()` (narrower field set, for raw pre-gather tokens).

## Libraries
Covers: `collectLibrary`, `flattenLibrary`, `mergeLibraryOverloads`, `requireLibraryVisibility`, `checkLibraryCall`, `signatureSuffix`.

- A library's functions are built like plain top-level functions (never like impl methods): no `self`, and `forbidSelfReference` is applied. `@default/@overrides/@realizes` are rejected. Overloading is by full signature (name plus parameter types), a deliberate departure from `collectFunc`/`collectImpl`'s no-overloading rule.
- Library function mangled name: `Lib_name__sig_<signatureSuffix>`, always (never only when an overload exists), so same-named differently-parameterized functions cannot collide at FUNC_START/CALL. `signatureSuffix` maps every character outside `[A-Za-z0-9_]` to `_` (a type like `owns_mut_dynarray(u64)` is not a legal assembler symbol).
- `flattenLibrary`: unlimited `extends`; a collision means the full signature, so a same-name, different-parameter pair inherited from two libraries coexists; an identical signature from two extended libraries (or parent plus own) is an error; cycles are an error. Functions are inherited by reference (the same `FuncInfo`), so calling through a child library still targets the originally-declaring library's mangled name.
- Visibility mirrors `checkImplMethodVisibility`'s two-layer gate with "library" for "impl": first the declaring library (`candidate.enclosingLibrary`, not whichever library name the call used, e.g. a child via `extends`) must be `@pub` or in the same file; then the function itself must be public or called from a function of that same library.
- `checkLibraryCall` (`Math.sin(10.2)`): structurally identical to `checkStaticMethodCall` (overload search ordered by `orderByLiteralExactness`, CallEdge, purity and recursion bookkeeping) except no ImplInfo, visibility via `requireLibraryVisibility`, no guard-lock discipline (no receiver) and no `requireMethodLockProofs` (a library function has no enclosing struct/interface to lock; its decorator set is `LIBRARY_DECORATORS` = `pub`, while the function itself validates against `FUNC_ALL_DECORATORS`). Per call site it stores the precise destruct list (`op.destructOnExit`, `op.unlockOnExit`, see `checkThrow`; BytecodeEmitter uses it only when the program uses `throw`). A call to the function itself from inside its own base-case match block is an error ("loses its recursive privileges"); `@recursive` self calls go through `requireRecursiveCallReturnSiteOnly` / `requireRecursiveCallWithinProof`.

## Impl method overloading
Covers: `registerImplMethod`.

- A bare impl accepts a second same-named method (instance and static tracked separately) when its parameter signature differs (`sameSignature`: base type plus alias per parameter) from every registered one. The new method gets mangled name `<first mangled>__sig_<signature>` and the map key `name#signature`; the FIRST method of a name keeps its original mangled name so a program without overloads emits byte-identical bytecode. An interface impl cannot overload (an interface method is identified by name alone): a duplicate keeps the old error.

## Interface-impl conformance checks
Covers: `validateOverridesRealizes`, `requirePublicInterfaceImpl`, `validateExactSignatureMatch`.

- Every method of an interface impl carries exactly one of `@overrides` (the interface method is `@default`: replaces an implementation) or `@realizes` (the interface method is a plain signature: fulfils a promise). Both on one method, the wrong one for the interface method, or neither is an error.
- Every method satisfying an interface (an impl method or a materialized `@default`) must be `@pub`.
- `validateExactSignatureMatch`: parameter count, each parameter's canonical type and the return type must equal the interface's (after `self` substitution); parameter names are never compared.

## Global and static state access
Covers: `isSwapLockStructType`, `isDirectAtomicDeclaration`, `requireSharedStateOrUnsafe`, `requirePureDoesNotReadMutableStatic`.

- In safe code, a global or static local may be touched only if it is a struct with a `swap`-tagged atomic mutex field (`isSwapLockStructType`, reached through `match @lock`, whether or not the struct also has a struct-level `@lock(...)`) or an atomic primitive accessed from `unsafe atomic{}`; anything else needs `unsafe global`. An atomic is one atomic step per access but whether a program built from such steps is right cannot be checked, so every access is an audited `unsafe atomic` use.
- A plain `let` may read an already-atomic global and silently strip `isAtomic` (the local is an ordinary non-atomic value); a new atomic can only be declared as a global / `let static` (`isDirectAtomicDeclaration`: optional mut/imut wrappers around the `atomic` prefix operator).
- Purity: see next section.

## Purity
Covers: `isPureFunc`, `isPureRtFunc`, `pureKind`, `requireNotPure`, `requireNotPureRt`, `requirePureRtNoPointer`, `requirePureCalleeIfPure`, `requirePureDoesNotReadMutableStatic`.

- `requireNotPure`: what plain `@pure` (and so `@pure(rt)`) may not do (unsafe code, `match @lock`, threads); compiler-synthesized unsafe blocks never reach it.
- `requireNotPureRt`: what only `@pure(rt)` may not do: allocation, randomness, reading through a pointer (plain `@pure` may: those are non-deterministic, not side effects).
- `requirePureRtNoPointer`: an `@pure(rt)` function never holds a `ref/raw/owns/auto/static` typed value or a dynarray.
- Reading globals/statics: `@pure(rt)` may read none; plain `@pure` may not read *mutable* ones (an `imut` global cannot change, so it threatens no purity). Unsafe code is not exempt (checked unconditionally, never gated on `scope.currentSafety`).
- `requirePureCalleeIfPure` is a per-edge rule, not transitive/reachability based (unlike `checkSafetyCallGraph`): a `@pure` caller may only call `@pure`; a `@pure(rt)` caller only `@pure(rt)` (the error mentions `@non(deterministic)` when that is why). Unsafe is no exemption.
- `@pure(rt)` plus `@non(deterministic)` on one function is an error (in `validateDecorators`).

## Decorators
Covers: `validateDecorators`, `validateDecoratorArgShape`, `resolveCallConvention`, the `*_DECORATORS` sets.

- `validateDecorators` rejects names that are not reserved decorators and names not allowed in the context (`allowedNames`); then argument shape. `@dont(X)` takes exactly one argument (par/unroll/inline) and is valid exactly where X is valid.
- Allowlists: struct `unpadded untyped pub lock`; enum `non_exhaustive`; interface/impl/library/global `pub`; extern `call_convention link_name`; loops `par unroll`; functions `FUNC_BASE_DECORATORS` (+ `default overrides realizes` for `FUNC_ALL_DECORATORS`, validated per context).
- Arg shapes: `call_convention(name)` exactly one bare name, accepted set read live from `compiler.config`; `link_name(sym)` exactly one bare word; `pure` nothing or `rt`; `non` exactly `deterministic`; `fs_root` nothing or `rw`; `unroll` nothing or a factor 2..64; `reads`/`writes` one or more of all/self/others/globals; everything else takes none.
- `@link_name(realCName)`: an extern's declared name and linked symbol are otherwise identical (externs are never mangled). It exists for when the C symbol cannot be spelled as a Caspien identifier, e.g. once `sleep` became a reserved keyword: `extern c_sleep(...)` with `@link_name(sleep)` links to the real `sleep`. A bare word (not a string), like the keyword-tolerant `@dont(par)` argument: a separate name namespace.
- A bare `@lock` method decorator was removed (it belonged to `@guard`); write `@lock(match self.field : VARIANT)` or `@lock(match x in self.field)`.
- `resolveCallConvention`: `@call_convention(name)` else the configured default; shared by func and extern collection (function-pointer types have their own inline parser, `parseInlineCallConventionArg`).
- `@drop` (`requireDropHookShape`): marks a struct's cleanup function; the drop glue calls it with the struct's address just before the owns value is freed. One parameter `ref some mut S` for a struct S, returns void, not `@throws`/`@async`; one hook per struct (`dropHookOwners`). `typeReachesDropHook` follows type text, struct members and dynarray elements.

## Externs and exports
Covers: `collectExtern`, `parseExternParamList`, `collectExport`, `checkFsPolicyAtCall`, `printFsReport`.

- `extern name(types) ret`: signature only, no body, no type parameters (no generic externs: C has no monomorphization), no overloading (C has no mangling). Own namespace `externs`, cross-checked against `functions` both ways. Accepts `@call_convention` and `@link_name` only. Parameters are bare types (no `name :`); a final `...` is varargs and illegal anywhere else. Same by-pointer-only return rule as functions (struct/enum/array need a storage modifier). Built-in names (sizeof/len/range/deref/clone) are reserved.
- `fs-deny-externs` (fs.config): an extern whose name or link name is denied is a compile error, except in stdlib files (`isStdlibFile`: under `../stdlib` of the ASTGenerator working directory).
- `checkFsPolicyAtCall`: a call to a static method with `@fs_root` needs a string-literal path checked against fs-roots (read-only unless `@fs_root(rw)`); a computed path must go through `Root.check(path)` or `unsafe file{ Dir.rootAny(path) }`. `@fs_unsafe` callees need `unsafe file`. Each opened literal / unsafe use is recorded for `--fs-report` (roots, denied externs, opens; not covered: `unsafe asm`, `call(...)` pointers, externs off the list, libc functions the stdlib links).
- `export foo`: foo must be a declared, overload-free (C has none), non-generic top-level function (impl methods are naturally excluded, they are not in `functions`); exported once; sets `isExported`.

## Function signature rules (collectFunc, buildFuncInfo)
Covers: `collectFunc`, `registerConstructorFuncInfo`, `buildFuncInfo`.

- `@default/@overrides/@realizes` are invalid on a plain function. Built-in names are reserved as function names. A function may not share a name with an extern or a const; overloads are by `sameSignature`.
- Constructors (`impl constructor for C(...) self {...}`): name is the shared `$`-prefixed synthetic key and the return type is the concrete struct by value, both baked in at parse time; registered as an ordinary overload. `registerConstructorFuncInfo` (shared by `collectFunc` and `collectImpl`) checks the struct exists and the return type is `C` by value, sets `isConstructor`, `constructorConcreteName`, and `isPublic = true` (constructors are callable wherever the struct is visible).
- Return types: an enum or array return needs a storage modifier (pointer only). A plain struct return is legal (return value optimisation, see `isStructByValueReturn`, `checkCall`'s struct-RVO eligibility check, `BytecodeEmitter.emitFuncUnderName`'s hidden leading `$ret_dest` parameter).
- Parameters: an array parameter needs a storage modifier. A by-value struct parameter is illegal at ANY size (never legal by design; the size is irrelevant, and every real struct is at least 16 bytes anyway because of the hidden `___type` word, so a size-based reading would reject the same programs). In a monomorphized generic (`t.fromGenericInstance`) a by-value struct `T` parameter instead throws `DeferredSignatureException`: the method is unavailable for that T, an error only if called.
- `@async` functions get `requireAsyncParamShape`; ghost-table decorator signatures are checked last (`validateGhostTableDecoratorSignatures`).

## Decorator signature checks
Covers: `validateGhostTableDecoratorSignatures`, `requireGhostTableSignature`, `requireGtRefSignature`, `requireAsyncGlueSignature`, `requireSleepSignature`, `requireAsyncParamShape`, `registerGhostTableFunction`, `forceGhostTableFunctionNames`, `sameSignature`.

- These decorators tag user-written functions that the bytecode-to-assembler stage calls. Only each function's own signature is validated, never its behavior.
- At most ONE function per decorator in the whole compilation unit (imports included; one TypeChecker instance sees every file). `registerGhostTableFunction`'s map is a plain "one function per decorator name" registry and is shared by the gt_*, `par_call`, `await_call` and `sleep` decorators.
- Required shapes (a `raw u8` parameter may be `mut` or `imut`):

  | decorator | parameters | return |
  |---|---|---|
  | `@gt_init` | none | `void` |
  | `@gt_alive_check`, `@gt_register` | one `raw u8` | `bool` |
  | `@gt_destruct`, `@gt_moved` | one `raw u8` | `void` |
  | `@gt_ref_id` | `ptr: raw u8` | `u64` |
  | `@gt_ref_resolve` | `id: u64` | `raw u8` |
  | `@par_call` | `fn: raw u8` (trampoline pointer), `handle: raw u8`, `tid: raw mut u64` (receives the thread id, or null) | `bool` (true = thread started) |
  | `@await_call` | `fn: raw u8`, `handle: raw u8` | `bool` |
  | `@sleep` | one plain `u64` (either mutability, no storage) | plain `u64` (the unslept remainder, as C `sleep(unsigned int)`) |

  The trampoline pointer and handle are plain `raw u8` because the bytecode has no distinct function-pointer value type once reduced to an address.
- `@sleep` replaced the old `extern sleep(mut u64) mut u64` (now `c_sleep`; `sleep` became a reserved keyword).
- Symbol names: `GT_INIT`/`GT_ALIVE_CHECK`/`GT_DESTRUCT`/`GT_REGISTER` (and the moved/ref hooks) compile to calls of the LITERAL symbol `gt_init`, `gt_alive_check`, ... (X86Backend `emitCallByName`), so `forceGhostTableFunctionNames` sets each decorated function's `mangledName` to the decorator name (`gt_init`, `gt_alive_check`, `gt_destruct`, `gt_register`, `gt_moved`, `gt_ref_id`, `gt_ref_resolve`). It runs once, after every function of the unit (imports flattened) is collected, because a separate function literally named e.g. `gt_init` may not yet be collected when a decorated function is registered. If such a separate function exists the compiler reports a collision error (rename one of them).
- `par_call`, `await_call` and `sleep` are NOT name-forced: their call sites (`BytecodeEmitter.emitAsyncCall`, `checkSleepCall` via `getGhostTableFunction(..).mangledName`) use the real mangled name.
- `@async` functions (`requireAsyncParamShape`): at most one parameter, which must fit one machine register (<= 8 bytes): any pointer/`raw` storage, or one of `u8 u16 u32 u64 s8 s16 s32 s64 bool char`. The argument is packed into the compiler-made handle's `value` field (`getOrCreateAsyncHandleType`) for the pthread entry point (`void*(void*)`); there is exactly one machine word there. A range (two words) and a struct are excluded.
- `sameSignature` (duplicate-overload test): same parameter count, equal base types and equal `aliasName`s. Parameters aliased differently are nominally distinct overloads (`func f(x:u8)` and `func f(x:byte)` may coexist).

## Name:type groups and swap members
Covers: `parseParamList`, `parseNameTypeGroup`, `parseNameTypeGroupsFrom`, `splitIntoRawGroups`, `parseOneNameType`, `resolveSwapMemberType`.

- A flat token list is split on `,` and stray TERMINATOR tokens into `name : type...` groups (a `(` parameter list written over several lines contains terminators, since `(` contents are not line-split earlier). `splitIntoRawGroups` does not resolve types; interface method signature validation uses it because `self` is not a type at declaration time (it only checks whether `self` and a storage modifier are present).
- `swap` is accepted only for struct members (`parseNameTypeGroup`, never parameter lists). It always lexes as an OPERATOR (the infix atomic read-modify-write operator), never a KEYWORD, so it cannot collide with a member name; it is stripped before the `name : type` shape check.
- A `swap` member's type must start with the `atomic` keyword (`swap flag: atomic mut MutexState`): a type-annotation position scoped to this one context (`atomic` is rejected everywhere else), then the rest resolves as an ordinary annotation and `TypeInfo.withAtomic(true)` is applied. The remainder must be concretely `mut` and carry no storage modifier.

## Type annotation resolution
Covers: `resolveTypeAnnotation` (both overloads), `expandAliases`, `checkTypeNameVisibility`, `requireModifierOrder`, `resolveTypeAnnotationRaw`, `checkNotRefSomeElement`, `parseInlineCallConventionArg`, `parseRangeAnnotationArgs`, `rangeAnnotationBoundDescriptor`, `splitTopLevelArgGroups`, `isKnownType`.

- Aliases: `type` aliases are expanded by textual substitution of their raw declaration tokens at the base-type position, chained through further aliases with cycle detection ("circular type alias involving ..."), BEFORE `resolveTypeAnnotationRaw` parses. Because the parse itself is unchanged, duplicate-modifier errors, the pointer-required check, array suffixes and incomplete-type errors fire identically for usage-site, spliced and mixed tokens. Only the first VARREF counts as the base type; later tokens (array suffixes) pass through. The OUTERMOST alias name is kept as `TypeInfo.aliasName`, a nominal tag used only by exact-match checks (`typesCompatible`, `sameSignature`); structural uses read `baseType`, which is the fully expanded representation.
- `allowIndeterminateMutability` is true only where a function's OWN return type is resolved: an ordinary func / impl method (`buildFuncInfo`), an `extern` (`parseExternDecl`) and an interface method's declared signature. Recursive resolutions inside `resolveTypeAnnotationRaw` (function-pointer nested param/return types, a nested `raw` pointee) always pass false.
- Mutability: every annotation needs an explicit `mut` or `imut` ("mutability is never inferred or defaulted here"), everywhere (parameters, members, interface signatures, locals), except `void` and an allowed return type. An allowed return type with no mutability gets the string `"indeterminate"` (the same state a bare literal has before `mut`/`imut` wraps it). `void` gets `"imut"` so it equals the canonical form of an omitted return type (`new TypeInfo(null, "imut", "void")`).
- Visibility: a struct or interface named in an annotation must be `@pub` or declared in the same file; enums, primitives, generic type parameters and unresolved names are ignored. The check is anchored to the token the base type was read from (`baseTypeTok`), not the generic `at` anchor: for a monomorphized generic function `at` still carries the template's declaring file (see `GenericsExpander.substituteParams`). Falls back to `at` for composite base types (range/dynarray/function pointer).
- Modifier order: `const`, then storage (rank 1), then `some` (rank 2), then mutability (rank 3), then the base type: `const owns some imut T`. `const` is stripped first (leftmost, strictly positional; a `let`'s constancy is `Token.isConst`, an earlier parse-time flag). Only ranks of modifiers actually present are compared (a type may have no presence or constancy modifier).
- `some` is its own flag, not a storage. It needs `owns`/`ref`/`raw`/`static` storage: never a plain inline value (no null question) and never `auto` (always non-null).
- Any annotation that writes `owns` or `ref` sets `usesOwnsRefDynNew` (syntactic presence, not actual use).
- A second `raw` starts a complete nested annotation (`raw mut raw mut char`), resolved by recursion into the same method (like the return-type span of `func(...)`), giving `rawPointeeType` and `baseType = rawPointeeType.canonical()`.
- Inline decorator `@name` inside a function-pointer annotation (`static @pure func(u64,u64) void`): recognized directly (decorators normally attach to a statement line). Optional `(args)`: only `@call_convention(name)` carries a value, a single bare name (no string) that must be declared in `compiler.config`'s calling conventions; the default is `config.defaultConvention`.
- Function pointer: `func(P1,P2,...) R`; the return type is everything after the parameter list. Storage must be `static` (a function is not an inline value) and mutability is mandatory.
- Float states: `finite`, `infinite`, `nan`, chainable with `|` (`f32` and `f64` only). They are contextual identifiers, not keywords (like `default` in an enum match). A VARREF is a state modifier only when more tokens follow; as the last token it is the base type. Repeats, a repeated modifier chain and a chain naming every state are errors (write the bare type).
- `unsafe dynarray(T)` and `dynarray(T)`: the element type must be spelled out (no bare/incomplete form; a dynarray's element type is never opaque). `ref some` is rejected as an element type (`checkNotRefSomeElement`, only at those two element-type sites; struct members are covered by `validateNoRefSomeStructMembers`, which runs post-collection because a member's TypeInfo does not pass through the element path).
- Fixed arrays: `T[N]` with a single integer literal, repeatable (`u64[5][10]`). There is deliberately no fixed-array-specific `ref some` restriction: a fixed array is always an inline address-of-first-element layout (`buildFuncInfo` rejects a storage-less array in return/param position), no TypeInfo means "one pointer to N elements", so it is exactly as lifetime-bound as whatever contains it (local, parameter, member, dynarray element, each separately checked).
- `slice` is no longer a type: rejected at annotation level with a dedicated message, bare or complete.
- Ranges: `range(a,b)` with each bound an integer literal or a bare identifier (descriptor `imut_<name>`, imut assumed), the same shape `rangeBoundDescriptor` uses for expression ranges; a range takes what it knows at construction into its type and cannot see into variables. A bare `range` is legal WITHOUT storage as an ordinary by-value type (two u64 bounds, known or not to the compiler).
- Pointer-like base types (`string`, and every interface, which has no fixed layout) require a storage modifier; a struct/enum may be a pointer (storage given) or an inline value (no storage). Array storage rules depend on context and are enforced by callers.
- Dynarray annotations: the annotation produces `TypeInfo("owns", ..)` carrying `dynArrayElementType` (or `unsafeDynArrayElementType`, or `rawPointeeType` for nested raw), because the generic constructor does not carry those fields. Storage is forced to `owns` (a dynarray is inherently heap-owned); another written storage keyword is an error. This branch fires only for a bare, un-arrayed `dynarray(T)`: for `dynarray(T)[3]` (an array OF dynarrays) the ordinary constructor builds the type.
- `isKnownType`: numeric types, `bool char string void null`, structs, enums, interfaces.

## Whole-program call-graph checks
Covers: `CallEdge`, `ThrowSite`, `checkSafetyCallGraph`, `checkNoRecursion`, `detectIndirectCycle`, `validateNoThrowReachableFromGhostTableFunctions`, `checkDynArrayForLoopResizeSafety`, `reachesUnsafe`, `reachesResize`.

All run after every function body is checked, so every call edge is recorded.
- `CallEdge` records caller, callee, the call site's effective safety (`Scope.currentSafety`) and whether it sits in a `for i in dynarrayExpr{}` body. `call()` targets are runtime function-pointer values and are never recorded.
- Safe-to-unsafe: for each edge whose own safety is "safe" (nested `safe{}` or the function's root tag), the callee must not be declared `unsafe` nor transitively reach an `unsafe` function through any calls (the safety of intermediate sites is irrelevant). `reachesUnsafe` memoizes and breaks cycles conservatively (a cycle with no unsafe function reaches none).
- Recursion: a self-edge needs `@recursive`; any indirect cycle is an error even for `@recursive` functions (DFS with an on-stack set; self-edges skipped, checked separately). `call()` is presumed unable to call recursive code, which holds because it creates no edges.
- Throws in ghost-table functions: no `throw` may be reachable (transitively, via `callEdges`) from any gt_* decorated function (the seven gt_* decorators). Calling an `@throws` function and catching it locally is fine; only a `throw` statement (in a reachable function body or in a reachable catch block) that could escape is banned. A `throw` directly inside a gt-decorated function is a more specific earlier error from `checkThrow`; this pass reports the "reachable but not itself one of them" case. It mirrors `BytecodeEmitter.gtReachableMangledNames`.
- Resize in dynarray `for` loops: a call, from the body of `for i in dynarrayExpr{}`, to any function that calls `resize` directly (`funcsCallingResizeDirectly`) or transitively is an error, even if it would resize a different dynarray (no alias analysis; conservative). The direct `resize(...)` case is rejected in `checkResizeBuiltin`.

## Recursive structs
Covers: `validateNoRecursiveStructs`, `detectStructCycle`.
- Cycles of any length are rejected (`struct A{ a:A }`, through pointers, indirectly), checked after monomorphization on each concrete struct's flattened `members` map. Every member is an edge regardless of storage (plain, owns, ref some, raw, auto, static); an array member is unwrapped to its element type. DFS with an on-stack set, same shape as `detectIndirectCycle`.
- Exception: a plain nullable `ref` member (storage `ref`, not `some`) is not an edge, so a struct may hold `ref` links to its own type (lists, trees, graphs): a borrow never owns, drops or clones what it points at.

## Lock struct rules
Covers: `assignsInsideSwapLockStruct`, `declaredTypeIncludingGlobals`, `requireFreshIntoSwapLock`, `containsMoveSource`, `validateNoPointersInLockStructs`, `findLockForbiddenPointer`.
- `assignsInsideSwapLockStruct(target)`: walks `.` and `LOOKUP` steps; true when some step reads a member of a struct that has a `swap` mutex field (`swapFieldName`). `declaredTypeIncludingGlobals` resolves the holder type, including globals.
- An owning value assigned/passed into a swap-lock struct must be fresh: `null`, `new ...`, `dyn(...)` or `clone(...)` (looking through parentheses, `mut`/`imut` wrappers and a non-block `try`), with no owned variable moved in (`containsMoveSource` looks for `isOwnershipMoveSource` anywhere in the expression). A moved variable could have had `ref`s taken before the move (ids stay valid), and a thread using such a ref would reach the data without the lock. Copy an existing value in with `clone(x)`.
- `@lock` structs may not contain `ref` or `auto` anywhere: members, nested structs, fixed and dynamic arrays, behind `owns` members, and in every struct implementing an interface-typed member's interface (whole-program search of `implsByConcreteType`). A reference taken out of the lock would reach data the lock does not protect. Runs after all structs are flattened (nested structs may be declared later); `visiting` guards recursion. ## Control-flow termination checks
Covers: `checkFunctionBodyInner`, `definitelyReturns`, `statementDefinitelyReturns`, `containsBreak`, `statementContainsBreak`, `containsRealTryCatch`, `statementContainsRealTryCatch`, `checkTryBlock`.
- `checkFunctionBodyInner`: owns parameters are registered on the function's ROOT scope (obligation to destruct unless moved, discharged wherever the function exits); `ref some` parameters enter `ProofKills` as implicitly alive. `@throws` is required exactly when the body contains a validated `throw` (`func.sawThrow`, set by `checkThrow` after all its checks): "decorated '@throws' but its body contains no 'throw'" otherwise. A non-void function whose body can fall off the end errors ("not every path ... ends in a 'return'"). The natural end of a function destructs everything still live up to and including the root scope (`destructOnExit = collectNaturalEndDestruct`), unlike a loop's natural end. `@recursive` lowering runs last, after all restrictions, on the original shape (the same "validate the real construct, lower for bytecode shape afterwards" discipline as `lowerEnumMatchToIfChain`/`lowerFloatMatchToIfChain`).
- `definitelyReturns` is conservative: it looks for the first statement that definitely terminates; blank lines (a lowered match case body can have one) are skipped. Terminating statements: `return`, `throw`, `break` only while `breakCountsAsTerminator` (checking a `match @lock` CLOSED case, `closedCaseTerminates`: break = give up without the lock), `continue` (legal only in a catch body, jumps past the enclosing try-block), an `if`/`match` chain (linked via `.right`) that ends in a plain trailing `else` (empty `.sub`) with every branch definitely returning (a `match` without `else` is never enough: its condition is a runtime question), a `loop` with no `break` in its own body (nested loops' breaks do not count), `unsafe`/`safe`/`lock` blocks (unconditional, propagate from the body), and a plain `try { }` block (`isTryBlock`; a throwing `try EXPR catch` statement falls through to false). Everything else returns false.
- `containsBreak`: any `break` at any depth except inside a nested `loop`; descends if/match chains, unsafe/safe/lock and plain try-blocks (a throwing try/catch's catch body is not reached by a loop-enclosing break).
- `containsRealTryCatch`: true if a real throwing `try EXPR catch(e){}` (`!isTryBlock`) appears anywhere, including as a let/assignment RHS (the `=` operator's right operand through `mut`/`imut`, as `BytecodeEmitter.tryNodeOf` unwraps), in `return ?f(x)` / `return try f(x) catch(e){..}`, and inside if/match/loop/for/unsafe/safe/lock/`assume{}` blocks and nested try-blocks. Broader than the two walks above because it is a plain "appears anywhere" search.
- `checkTryBlock`: `try { ... }` is a plain lexical block (told apart from the throwing form by `Token.isTryBlock`, set by Parser's pre-scan); it is a syntax error unless it contains at least one real try/catch (any depth). It is checked like `unsafe`/`safe` minus the safety override: a child Scope using `TryBlockBoundaryMarker.MARK` (so a nested `continue` resolves its target via `scope.tryBlockBoundaryScope`, the same shape as a loop body scope for `break`), `checkLinesInScope`, and an ordinary natural-end destruct list.

## @recursive functions
Covers: `validateRecursiveFuncRequirements`, `isRequiredBaseCaseMatch`, `requireRecursiveCallReturnSiteOnly`, `requireRecursiveCallWithinProof`, `lowerRecursiveFunctionToLoop`.
- Signature: the FINAL parameter must be a plain `imut range` (identified by position, any name). The first statement after any leading `let static` lines must be `match PARAM is base{...}` on that parameter; ANY other statement before it is an error. Both are structural checks run before the body is type-checked (`isRequiredBaseCaseMatch` checks shape only; `checkMatchCondition` later confirms the range type).
- Return site: a self-call may only be the sole expression of a bare `return` (`return foo(...)`), never bound to a variable first and never nested. Checked by node identity against `directReturnExprNode` (set by `checkReturn` while resolving its expression): any wrapper puts a different node there. Sets `op.isRecursiveTailCallSite`. Together with `checkNoCodeAfterTerminalStatement`, the call is the last statement of its block, so a plain reassignment already acts as `continue` (falling off the end of the block in the lowered `for`).
- Within proof: every self-call needs its range argument (`imut`) to be proven a subrange by an active `match x within RANGEPARAM{}` pattern (`kind "in"`, `slotKey` = argument, `rightSlotKey` = the range parameter). Absolute rule, no `unsafe` bypass; fires regardless of `scope.currentSafety`. A self-call inside the base-case branch is barred separately (`scope.suspendsSelfRecursion`). Reuses the already-resolved `argTypes` from overload matching.
- `lowerRecursiveFunctionToLoop` rewrites the validated body into `for __recur_i in __recur_range{...}`:
  - leading `let static`s stay first; one SHADOW local per parameter (`let p = p`, same type and mutability) is declared once OUTSIDE the loop, so every already-resolved reference in the reused body keeps its type; the body is relocated wholesale, not re-resolved;
  - `__recur_range_start`/`__recur_range_end` are copied from the range parameter's `.start`/`.end` and `__recur_range = start..end` drives the loop;
  - each return site flagged `isRecursiveTailCallSite` becomes a plain reassignment of the shadows; these nodes bypass `requireMutable` by setting `.resolvedType` directly (sound because the value was already type-checked against the parameter slot at the self-call);
  - the loop header is validated by `checkForLoop` against an empty body, then the already-validated body is swapped in (re-checking it would reject the reassignment of imut shadows);
  - the loop runs (initial range length) times, but a recursion shrinking by one per step needs one more call to reach its base case; every step strictly shrinks the range ('within' is a strict-subrange proof), so after the loop the range is empty and the base case holds. A clone of the base-case block (`deepCloneChecked`, taken before the return sites are rewritten) is therefore appended after the loop.
- Scope limitation: an `owns`-typed parameter is not supported by the lowering (no GT_DESTRUCT/ownership bookkeeping through the loop).

## Recursive tail-call lowering

Covers: `replaceRecursiveReturnsInLines`, `buildTailCallReplacementLines`, `buildCheckedLetAssign`, `wrapAsCheckedLine`.

- `replaceRecursiveReturnsInLines` walks every nested statement list (an `if`/`match` chain through its `.right` links, the per-case bodies of a case-match, `for`/`loop`/`unsafe`/`safe` bodies, `assume match{}` blocks) and replaces each `return` whose sole expression is marked `isRecursiveTailCallSite`. Only the terminal `return` is replaced; the surrounding structure is untouched. Any number of call sites is allowed; each is found and replaced independently.
- `return SELFCALL(a0, a1, ..)` becomes: first one ordinary, fully checked `let __recur_tmpN = argN` per argument (all new values are evaluated before any parameter changes, the same semantics as an ordinary call; a later argument may refer to an earlier parameter that is about to be overwritten), then one hand-built, unchecked `paramN = __recur_tmpN` per parameter. The second step cannot go through ordinary validation (see `lowerRecursiveFunctionToLoop`).
- The generated lines are wrapped in `LINE` tokens (same shape as `Parser.wrapAsLine`); every statement-list walker relies on `lineTok.childs.get(0)` being the statement.

## Static let placement

Covers: `validateStaticLetPlacement`, `staticLetTokenOf`.

`let static` is only legal as a leading run of statements at the top of the function body (any order among themselves, nothing else before or between them), never inside a nested block. The scan only sees the function's own top-level statement list; a `static let` in an `if`/`loop`/`for` body lives in a separate childs list and is invisible to it, which is why `checkAssign`'s static branch re-checks `staticApproved` itself instead of trusting that reaching it implies a valid position.

## Scope exit: destruct and unlock lists

Covers: `collectOwnsToDestruct`, `collectLockReleasesToBoundary`, `collectNaturalEndDestruct`, `checkLines`, `checkLinesAsLoopBody`.

- `collectOwnsToDestruct(from, boundary, preservedSlotKey)` walks from `from` up to and including `boundary`, innermost scope first and within a scope the most recently declared slot first (the order `GT_DESTRUCT` must run in). It skips slots already moved (unless partly moved, see below) and `preservedSlotKey` (the slot a `return` returns).
- Exactly one `GT_DESTRUCT` is emitted per top-level owns slot, nothing about its contents. Recursing into a struct's own owns members at destruct time is the job of the later stage that reads struct definitions (drop glue), not of this checker.
- `collectLockReleasesToBoundary(from, boundary)`: the lock-release calls owed within the span, in reverse acquisition order (LIFO). `Scope.activeLockReleases` is an immutable list extended by copy (like `activeMatchPatterns`), so the span is the suffix beyond what `boundary` already had.
- `collectNaturalEndDestruct(lines, from, boundary)` returns an empty list when the block's last statement is literally `return` or `break` (the natural-end list would be dead, duplicate bytecode). Only that simple case is detected, not full reachability (an `if` whose every branch returns still gets a dead list).
- `checkLinesAsLoopBody` is used only for a loop's own body (`loop` / desugared `for`): its scope becomes the new innermost loop boundary that `break` destructs up to, it is registered in `userLoopScopes`, and `ProofKills.enterLoop/exitLoop` bracket the check. `isDynArrayForLoopBody` is true only for a `for i in dynarrayExpr{}` body (see `Scope.insideDynArrayForLoopBody`).
- A block's natural end is not a function/loop boundary, so only that block's own locals are destructed there (if branches, match branches, `unsafe`/`safe` blocks, case bodies). A loop body's destruct list is emitted at the bottom of the body and runs every iteration, so a fresh `let owns` next iteration never overwrites an undestructed value.

## Branch merge and partly-moved slots

Covers: `partlyMovedSlots`, `finishBranchMerge`, `chainHasElse`, `checkIfChain`.

- A value is considered moved if it moved in ANY branch (use-after-move rule). Each branch is checked against its own copy of the pre-branch moved set (the `if` condition itself is checked against the shared set, since it runs before branching); the shared set is then replaced by the union of the branches.
- `finishBranchMerge(preState, union, survivors, implicitPath)`: `survivors` are the moved sets of branches that fall through (a branch that always returns/throws/breaks never reaches the merge; `closedCaseTerminates` decides); `implicitPath` adds the "no branch taken" path of a chain without a final else (`!chainHasElse`). A slot in the union that is not in the intersection of all reaching paths goes into `partlyMovedSlots`.
- A partly moved slot stays "moved" for the use-after-move check, but `collectOwnsToDestruct` still emits its scope-exit destruct: a move nulls the slot, so the destruct frees the block on the paths that did not move it and is a no-op on the paths that did. Without this the not-moved path leaked.
- `chainHasElse` is true if the last branch of the `.right` chain has an empty `.sub` (no condition).

## Unreachable code

Covers: `checkNoCodeAfterTerminalStatement`, `checkLinesInScope`.

- `checkLinesInScope` is the shared entry point for every block (function body, if/elseif/else branch, loop body, unsafe/safe block) and calls `checkNoCodeAfterTerminalStatement` once per block.
- Uses `statementDefinitelyReturns`, which also recognises an if/elseif/.../else chain whose every branch returns and a break-free `loop`; any of these makes the following statement in the same list an error ("unreachable code", reported at the next non-blank line). An `if` with no matching `else` whose branches only sometimes return does NOT make later code unreachable. Blank lines (`childs.isEmpty()`) are skipped.
- `assume match expr;` without a block ("holds for the rest of the scope") is handled in `checkLinesInScope`'s loop: the local `scope` is replaced by a new nested `Scope` (parented to the old one) whose `activeMatchPatterns` is extended with the assumption's proofs. It cannot go through `checkStatement`, which returns void and cannot change what its caller sees next.
- When `scope.unsafeBlock` is set (a written `unsafe` block), each direct child statement is attributed to the block record (`noteChild`) and `cur` is reset afterwards.

## Loop move pre-scan

Covers: `collectLoopMoves`, `collectMovesInNode`, `lookupDeclaredTypeStructurally`.

Movement on one iteration is a use-after-move on the next. Before the one real pass over a loop body, a purely structural scan (Scope/StructInfo lookups against already-declared types, no expression resolution) finds which already-in-scope `owns` slots the body moves anywhere (`let x = owner`, `owner2 = owner`, argument to an `owns` parameter) and seeds the moved set with them. The single real pass then sees any use, anywhere in the body, of something the body eventually moves. Deliberately narrow: a call argument counts only if the function name has exactly one overload (resolving overloads would need full expression resolution); an ambiguous overloaded call is a documented gap. `lookupDeclaredTypeStructurally` also serves `checkAddressOf`'s `ref` validation; it handles parentheses, variables, `a.b` member chains and `x[i]` element types (so `ref x[i].member` can see an `owns` member).

## Statement dispatch

Covers: `checkStatement` (cases loop, for, match, lock, assume, unsafe/safe, return, throw, try, break, continue, yield, ASM, expression statement).

- **`loop`**: a bare `loop{}` is unbounded by construction, so it is checked like `raw`/`extern`: it needs `unsafe` (`unsafeBypass(scope, "loop")`). Exception: a function decorated `@event_loop` may use `loop{}` exactly once in safe code (`func.eventLoopSafeLoopCount`). The exemption is spent only when it was the reason the check passed (a `loop{}` already inside `unsafe` does not use it up); a second bare `loop{}` in the same function still needs `unsafe`. Loop moves are pre-scanned (`collectLoopMoves`), then the body is checked with `checkLinesAsLoopBody`; `destructOnExit` is the natural-end list.
- **`for`**: `@par` loops are banned in `@pure` functions; see "For loop desugaring".
- **`match @lock`** (`lock` keyword with `isCaseMatch`): validated on the real construct by `checkLockMatchStatement`, then lowered in place into a loop.
- **`assume`**: only the block form reaches `checkStatement` (the no-block form is in `checkLinesInScope`); a nested Scope carries the extra proofs.
- **`unsafe` / `safe` blocks**: `unsafe` inside `safe` is an error, `safe` inside `unsafe` is fine (the root-level case is `flattenRootLines`). The block scope is `transparent`. An `unsafe` block (not compiler-synthesized) is banned in `@pure` functions. After an `unsafe` block, `ProofKills.kill` ends all proofs active before it, unless the block's tags are all in `NON_FREEING_UNSAFE_TAGS` (tags that cannot free anything by themselves, because the checker sees every `resize`, owns assignment and call inside as its own event: `memcopy raw deref clone global loop atomic guard assume` in the comment's list, the constant is authoritative). Tags `extern call asm udyn udyn:owns async file unaudited`, or no tag list, may free and still end every proof. Uses inside the block remain the programmer's responsibility.
- **`try`**: two shapes share the `try` keyword (`Token.isTryBlock`): a plain `try { .. }` lexical block and the bare statement `try foo() catch(e){..}` (its value, if any, is discarded like a bare call statement). The expression form `let x = try foo() catch{..}` goes through `resolveExprTypeInner`'s `try` case instead, where `insideLoop` cannot always be threaded.
- **`break`**: needs `insideLoop`; `destructOnExit` and `unlockOnExit` run up to `scope.loopBoundaryScope`.
- **`continue`** (checked in this order; innermost construct wins): (1) a user-written `for`/`loop` that is not shadowed by a catch body opened inside the same loop (`insideCatchBody && loopBoundaryScope == catchEnclosingLoopBoundary` means the continue belongs to the catch) -> `isLoopContinue`, same unwinding as `break` but jumps to the loop step (for) or start (loop); (2) directly in the CLOSED case of a `match @lock` (not inside a catch body or nested loop) -> `isLockRetryContinue`, jump back to the spin loop start, no lock is held, only owns locals declared inside the CLOSED body are destructed (`lockRetryContinuesSeen++`); (3) inside a catch body: the catch must itself lie inside an enclosing `try { .. }` block (`scope.tryBlockBoundaryScope`), otherwise there is nowhere well-defined to jump and it is an error; it unwinds to that try boundary; (4) anywhere else: error.
- **`yield`**: bare keyword, no arguments (the optional `yield()` call syntax is normalised by RpnConverter), emits `YIELD`, no restriction on where it appears (not even requiring `@async`).
- **`ASM`**: see "ASM declarations". A bare identifier statement that names a known ASM invokes it (needs `unsafe asm`); this check comes before ordinary variable resolution, since ASM names have their own namespace and no collision is validated, so a variable with the same name loses.
- Anything else: an expression statement (or a `let` surfaced as its `=` root) -> `resolveExprType`.

## ASM declarations

Covers: `checkAsmDeclaration`, `resolveAsmRawText`, `validateNoAsmEndMarker`.

- `ASM name { ... }` or `ASM name "path"` as a statement inside a function needs `unsafe asm`. Unnamed: the content is stashed on the statement token (`resolvedAsmContent`) and emitted in place (it can never be referenced). Named: registered in the current scope only (`localAsmNames`, lexical scoping like a local `let`; shadowing an outer scope is fine, redeclaring in the same scope is an error).
- Exactly one of `asmBlockText` / `asmFilePath` is set (`Parser.gatherAsm`). Block text was already validated by `Lexer.scanAsmBlock` (including brace balance and a stray `ASM_END`). The file form is read relative to the declaring file's directory (the same convention `ImportResolver` uses), recorded in `DepsLog`, and scanned for a stray `ASM_END` only (no braces to balance in a whole file; EOF is the end).
- `validateNoAsmEndMarker` is a standalone, simplified copy of the lexer's string/comment-aware `ASM_END` scan (strings with `"`, `` ` `` or `'`, `//` and `/* */` comments skipped), kept separate because the lexer's machinery expects to scan the compiler's own source stream mid-tokenize.

## Unsafe block tags

Covers: `recordUnsafeBlock`, `validateUnsafeBlockTags`.

- Each statement-level `unsafe` block (not compiler-synthesized) has an `UnsafeBlockRecord` keyed `file:line:tags`. Tag words must be in `UNSAFE_TAGS`, may not repeat, and `unsafe unaudited` must stand alone (it stands for every tag) and is not allowed in the standard library (`isStdlibFile`).
- After the whole program is checked, `validateUnsafeBlockTags` requires each block to name exactly the reasons it needs: a bare `unsafe{}` (error: says what it needs), a needed but unwritten reason, and a written but unneeded reason are all errors. A block containing `unaudited` is skipped (vouches for everything).
- Env `CASPIEN_UNSAFE_REPORT=<file>`: the needed tags of every block are appended there (`file TAB line TAB tags`), nothing is reported or rejected, and unknown tags are tolerated. The migration helper `tests/unsafe_tags_migrate.py` reads it.

## Assume match

Covers: `checkAssumeMatchCondition`, `checkAssumeFieldVariant`.

- `assume match EXPR` is allowed only in `unsafe` code (`unsafeBypass(scope, "assume")`) and reuses `checkMatchCondition` (the same grammar and proof machinery as an ordinary match) with `assumeKeyMode` set. Being inside `unsafe` is the statement's precondition, not an exemption from it.
- The enum-style `x.field : VARIANT[|VARIANT]` form (`stmt.assumeFieldVariants != null`) is handled by `checkAssumeFieldVariant`, because it never could be built as an ordinary expression tree node (see `Token.assumeFieldVariants`). `stmt.sub.get(0)` is the already-built `x.field` access tree; the variants are plain strings from the parser. It records an `enum_field_variants` pattern (so it can satisfy an `@lock(match self.x : X)` qualifier's proof at a call site); the access is marked `isCompilerSynthesizedSwapAccess` since nothing is read or written at run time (no `swap` tag needed).
- Float-state form: `assume match x : finite` / `finite|infinite` checks the names against the type's allowed states and records the same `float_state` proof a real `match x{ finite:{..} .. }` case body has; it never runs.

## Match chains

Covers: `checkMatchChain`, `narrowInstanceofSlots`, `requireNewTypeAssertion`, `matchPatternsEqual`, `checkMatchCondition`, `checkSomeIndexBoundsCondition`, `boundsTargetSlotOf`, `boundsTargetExprOf`.

- **Chains**: `match / elsematch / else` keep each branch's own condition check and proof scoping (`activeMatchPatterns`, base-case suspension) and use the same union move-tracking as `checkIfChain`. A bare `else` branch has no condition, proves nothing and gets no special proof privileges.
- **Instanceof narrowing** (`narrowInstanceofSlots`, also used by `checkEnumForMatch`): for every `instanceof` proof whose slot is a plain local variable (never a "."-chain or lookup), the variable is shadowed inside the branch scope by a copy of its TypeInfo whose baseType is the proven struct, as if narrowed by hand. `implements` proofs are NOT narrowed (the right side is an interface, no single concrete type).
- **Redundancy** (`requireNewTypeAssertion`, safe code only): a match/elsematch branch must add at least one proof not already in `scope.activeMatchPatterns` ("this 'match' asserts nothing new"). The test is whether the proofs give the type system new assurances, not whether the variables are related: `Some(x)` inside `x instanceof X`, or `x instanceof Y` inside `x instanceof X`, are fine. An alive proof that has seen possibly destroying events since it was made (`ProofKills.hasEvents`) is stale, so re-matching it is allowed (that is how it is renewed). Not applied to `unsafe` scopes, to empty pattern lists, to bare `else`, or to enum case matches.
- **Condition grammar** (`checkMatchCondition`): `left instanceof right`, `left implements right`, `left in right`, `left into right`, `left within right`, `left fits T`, `x != 0` / `x > 0`, `r is base`, `Some(x)`, `Some(i) in/into x`, chained with `and` (which has no `resolveExprType` case; result type set to bool here). Anything else, including a bare value expression, is the error listing these forms and suggesting `match Some(...)`.
  - `x != 0` / `x > 0` on an integer (variable, or any keyed expression in `assume` mode) records a `nonzero` proof, which makes `/ % /= %=` legal in safe code. It never falls through to the generic "alive" case (an alive check on the comparison's bool result is meaningless). A literal 0 fits every integer type, but `resolveExprType` types it u64 and `checkComparison` needs equal base types, so the comparison's types are set by hand (literal coerced to the left type). `!= 0` is recorded only for an unsigned left side (a signed divisor could still be -1, and `TYPE_MIN / -1` traps like division by zero); `> 0` always suffices. Non-integer left side falls back to ordinary comparison checking.
  - `in` records an `in` proof (bounds); `u64 in GuaranteedEnum` and `u64 in string` are never valid match conditions (nothing a proof could attach to). `into` is checked by calling `checkIn` by hand (not in the generic dispatch) and recorded as `into`: it grants everything `in` does (`isProvenInBounds` accepts it) plus the write proof `isProvenWritable` alone consults, for the same exact (index, target) pair (`arr[i] = ..` works, `arr[i+1] = ..` does not). `within` is checked via `checkWithin` and recorded under the plain `in` kind so every consumer treats it identically.
  - `fits`: left must be a plain (storage-less) integer, right an integer type name, left a trackable slot; sets `fitsSourceBase/fitsTargetBase` and records a `fits` proof so `x as u8` (narrowing or sign change) is legal in the branch; a later write to x kills it.
  - `is base` (reserved form, not a general `is` operator, retargeted from the removed `recurse` type to `range`): left must be a range, right literally `base`; base means the range is empty, tested at run time by `IS_BASE`. Records `is_base`; a branch with exactly that one pattern is a base-case match (`isBaseCaseMatch`, suspends the recursion check).
  - `Some(x)`: the bytecode is a plain `GT_ALIVE_CHECK`; `resolveExprType` dispatches to `checkSomeBuiltin` (generally available) and this adds an `alive` proof for x's slot (`someProofKey`, `onId = someOnRef`). `ProofKills.suppressReads` is raised around the resolve because the alive check itself reads the pointer, and that read is what renews the proof.
- **`Some(i) in/into x` sugar** (`checkSomeIndexBoundsCondition`) = `match i in/into x{ match Some(x[i]){..} }`: grants the index bounds proof and the element-alive proof for `x[i]` in one condition. `i` must be a bare variable or a "."-chain (a slot is needed for both proofs). The bounds check is `checkIn` on a synthetic node; guaranteed enums are rejected. The element proof is a throwaway `LOOKUP` node on `boundsTargetExprOf(x)` (unwraps `range(origin)` to `origin`, like `boundsTargetSlotOf` for the slot key), checked in a scope that already holds the bounds proof so its `isProvenInBounds` gate passes; the element type must have storage (be a pointer). `someOnRef` / `onId` mark a plain nullable `ref` element (proof is an id). The lookup is stored in `node.someIndexElementExpr` so BytecodeEmitter emits the `GT_ALIVE_CHECK` directly. Also used by `for match Some(i) in/into` (checkForLoop) and the `@lock(match Some(i) in/into self.field)` qualifier.

## Float and enum case matches

Covers: `checkCaseMatch`, `checkEnumMatch`, `lowerEnumMatchToIfChain`, `checkFloatMatch`, `lowerFloatMatchToIfChain`, `isEnumForMatchCondition`, `checkEnumForMatch`, `lowerEnumForMatchToIfChain`, `labelsText`.

- `checkCaseMatch` dispatches on the condition: `x instanceof P.enum` / `x implements I.enum` (detected structurally first, because `resolveExprType` would reject `P.enum`; `checkInstanceof` and `checkImplementsOperator` require a bare VARREF on the right), an enum-typed condition, or a float condition; otherwise an error naming the accepted types.
- **Common pattern**: validate the real construct fully (labels, exhaustiveness, case bodies in child scopes), merge moves (`finishBranchMerge(.., false)`), and only then lower the case match in place to an if / else-if / else chain: every case but the last gets a comparison, the last is a plain `else` (exhaustiveness has already guaranteed it is the only value left). The lowering happens after checking because match blocks may assert type information, so the checker must see the original construct. `matchTok` is mutated in place (`text = "if"`, `isCaseMatch = false`, sub/childs/destructOnExit/right taken from the first branch) because other references to the object must see the new shape; `emitIfChain` reads only `.sub/.childs/.right/.destructOnExit`, only `emitStatement`'s switch on `.text` needs "if". `conditionExpr` is reused (not cloned) in every case comparison: it is fully checked and never mutated again, and re-resolving it is idempotent.
- **Enum** (`checkEnumMatch`): no proof is recorded for the enum value itself (nothing would use it yet), but a `receiver.field` condition (conditionExpr is a "." node) records `enum_field_variants` for every case, granted for any such condition, which is what `@lock(match self.x : X)` struct-level and enum-style method qualifiers read. `default` must be the last case and stand alone (no `|`-chain); it is allowed only for an `@non_exhaustive` enum, where it is required unless every variant is named, and is unreachable (error) if every variant is already covered; its case variant list is the not-yet-covered variants. Unknown variant, duplicate coverage and missing variants are errors. Lowering builds `conditionExpr == Enum.Variant` per label (OR-combined with `||` for `A|B:`), type-checked through the ordinary `==` dispatch.
- **Float** (`checkFloatMatch`): `match f{ finite:.. infinite:.. nan:.. }`, exhaustive over the type's own state set (`floatStates`, or all three if unconstrained). No `default`. A state the type's modifier rules out is an error ("impossible here"), as are repeats in one `|`-chain and states already covered. Each case body gets a `float_state` proof for the condition's slot (like `alive`, a different guarantee: "not an unproven float", hence its own kind); the restriction it lifts does not apply in unsafe code. Lowering builds a compiler-internal `FLOAT_CHECK` operator node (never parsed, so its `resolvedType` is set by hand to `indeterminate_bool`, like `is_base`) whose right text is the alphabetically sorted chain ("finite|nan") built from a `TreeSet`, so the bytecode is canonical regardless of source order.
- **Interface `.enum`** (`checkEnumForMatch`): `match x implements Iface.enum{ Impl1:{..} Impl2:{..} }`. Labels are members of the synthesized `$enum_for_Iface` enum (`generateEnumForEnums`) = the implementers; the match must cover exactly that set, no `default`. `instanceof Owner.enum` is always an error (structs have no subclasses; an interface name gets a hint to use `implements`), an unknown interface or one without implementers is an error. A throwaway `x instanceof FirstMember` runs `checkInstanceof` once on x (alive proof, interface-typed value, `@untyped`) so its errors appear up front. Each single-label case gets an `instanceof` proof (always `instanceof`, even for the `implements` form: a label names a concrete implementer, so the case proves x is exactly that struct) and the usual `narrowInstanceofSlots` shadowing, so a synthesized dispatcher can write `c.foo(args)` inside the `A:` case and have it resolve as A's method. Lowering builds `x instanceof Label` nodes (INSTANCEOF opcode), OR-combined for `|` chains.

## Generic bounds

Covers: `validateGenericBounds`, `structImplementsInterface`, `interfaceExtendsOrIs`.

A generic bound (`func f<T: SomeInterface>(..)`) is enforced at each concrete instantiation site only, never as a structural check of the template body (monomorphize-then-typecheck never validates an unbound template). `validateGenericBounds` runs once, right after `collectDeclarations`, when every struct and impl is collected; `GenericsExpander` recorded what to check in `Token.pendingGenericBoundChecks` on each monomorphized declaration. `structImplementsInterface` is also the struct-to-interface upcast rule; it checks the struct's own `implementsNames` and the standalone `impl X for Y{..}` blocks (`implsByConcreteType`, a separate mechanism from an `implements` clause), each through `interfaceExtendsOrIs`, which follows interface `extends` transitively.

## Conditions

Covers: `requireBoolOrNumericCondition`.

An `if`/`elseif` condition must resolve to `bool` or a numeric type (any integer width/sign, `f32`, `char`), C-style "any scalar, zero is false". Everything else (struct, enum, array, pointer, range, dynarray, string, void, function pointer) is rejected; there is no truthy pointer or non-empty collection, and null checks have their own mechanism (`match Some(x)`). Only storage-less types qualify: a pointer to a bool/number is rejected. The condition is resolved with `insideShortCircuitEligiblePosition = true` (the one place it is seeded true), which is the top level where a `&&then` / `||then` chain is legal.

## For loop desugaring

Covers: `checkForLoop`.

- `for x in range{ body }` desugars into real AST nodes: `let $range = someRange`, `let x = $range.start`, a per-iteration condition `x in $range` (a real `in` node, type-checked by `checkIn`) and a step `x++` (real postfix `++`, `checkIncrement`), all stashed in `forTok.sub = [rangeAssign, loopVarAssign, conditionIn, increment]` for `BytecodeEmitter` (`emitForLoop`, a check-at-top loop). The `IN` opcode is byte-for-byte what an ordinary `in` expression emits, which keeps the number of distinct shapes the later stages must understand small. No logical NOT is needed: `x in $range` is already the keep-looping direction CMP/JMP expects.
- The hidden range variable is `$for_range_N` (`forVarCounter` makes it unique program-wide; `$` can never occur in a lexer identifier). The loop variable is `mut` u64-ish: `.start` is `indeterminate`, so wrapping it in `mut` is a legal indeterminate-to-mut transition (an imut-to-mut one would not be).
- Root must be `in` or `into`. `into` requires `for match` (a plain `for i into arr` is rejected as misleading; plain `for i in arr` is legal but proof-free).
- Sources: a range, a dynarray, or a fixed array (rewritten to `range(arr)`, `wrapFixedArrayAsRange`, like `checkIn`). A dynarray source starts the loop variable at literal 0 (no `.start`) and `$range` is bound as `mut ref <dynarray>` so the owns source is borrowed, not moved (the `ref` result is indeterminate and needs the `mut` wrapper to bind to a `let`). No proof about `dynArr[x]` is granted inside the body (it needs its own `match x in ..`; entries may be null and silently skipping them would be ambiguous). An `unsafe dynarray` source is banned (no compiler-known length): iterate by hand with `loop{}` in `unsafe`.
- `for match i in/into x{..}`: same bytecode, but the body scope also carries the `in` / `into` proof against the ORIGINAL range expression (not `$range`, because body indexing names the real source, e.g. `self.x2[i]`), in a fresh intermediate Scope so `forScope` is untouched.
- In every `for` form the loop variable and the source slot are immutable inside the body (`ownLoopImmutableSlots`); a fresh scope is wrapped even without for-match so the synthesized pieces, which legitimately reassign the variable, are unaffected.
- `for match Some(i) in/into x{..}` (needs `for match`; `i` must be a bare new variable): the loop body is wrapped in a synthetic `match Some(origin[i]){..}` statement (a normal `Some(..)` CALL node, `origin` = `boundsTargetExprOf(rangeExpr)`), so existing match checking and emission handle it with no new cases; the wrapper uses a `LINE` token (`Parser.wrapAsLine` shape).
- Loop moves are pre-scanned (`collectLoopMoves`) and the body is checked with `checkLinesAsLoopBody(.., isDynArraySource)`; `destructOnExit` is the natural-end list (per iteration).

## Struct return values (RVO)

Covers: `checkReturn`, the `return foo()` tail-forward, `checkCall` RVO gate.

- A function returning a struct by value builds the result in a hidden struct in the caller's frame (`$ret_dest`). A struct-returning call is legal only at three destinations: a `let` RHS, a bare-variable assignment RHS (target must be a plain `VARREF`, never `.`/`LOOKUP`), and a `return` expression. Anywhere else (argument, inside a larger expression) `checkCall` reports an error telling the user to bind it with `let` first.
- The position is communicated by the field `insideStructRvoDestinationPosition`. It is set by `checkAssign` (let: always true; reassignment: only for a `VARREF` target) and `checkReturn` (true when the function itself returns a struct by value). `resolveOperatorType` captures it once into `eligibleForRvoHere` and resets it, so only `checkCall` sees it. `mut`/`imut` wrappers re-arm it one level down, so `let p = mut newPoint()` still reaches the CALL.
- `return foo()` tail-forwarding: `checkCall` sets `isStructRvoCall` on the node only after confirming the callee returns a struct by value and the position was eligible. `checkReturn` therefore just tests the flag (after unwrapping `mut`/`imut`), which cannot be spoofed by an unrelated call. Mechanics: `BytecodeEmitter.emitStructRvoForwardCall` forwards the function's own `$ret_dest` into the callee.
- A struct-by-value `return` may be: a fresh struct literal (`INSTANTIATE`, e.g. `return Point{x:23,y:45}`), a readable value chain of exactly the same struct (bare variable, `.` field chain rooted in one, `LOOKUP` rooted in one, or any nesting: `return p`, `self.point`, `arr[i]`, `arr[i].point`, `self.arr[i]`), or a direct tail call. See `isReadableValueChain`; this is deliberately wider than `isAddressableLvalue` (the "can a real address be computed" question that `raw`/`auto` ask).
- No emitter change was needed for the value-chain case: `emitStructRvoReturn` is written against `expr.resolvedType` and a plain `emitExpr`, and `LOOKUP` is as size-generic as `PUSH`/`DOT`/`ASSIGN`.
- The copy is shallow and needs no extra move/destruct machinery: ownership tracking is flat. Only a top-level `owns`-storage slot is tracked for a move or `GT_DESTRUCT` (`markMovedIfOwned` and `scope.ownsDeclaredHere` gate on `"owns".equals(storage)`); nested `owns` members of a struct-by-value are handled by the inline-owning-struct machinery, not by RVO.
- The return statement is annotated with the function's declared return type (not the expression's), which matters for `null` returned from a pointer-typed function.

## Returning owns some

Covers: `checkReturn`, the `some` return rule.

- A function declared to return a `some` type may return an expression that is not `some` only if that expression is currently proven alive (an active "alive" pattern in `scope.activeMatchPatterns` for its slot, the same check `.` member access on an unproven pointer relies on). The type is then upgraded with `withSome(true)`.
- A bare `new` is never treated as `some`: `new` can return null because `malloc` can fail. The only sound way to satisfy a `some` return type is a real runtime `match Some(...)` proof.
- The slot named directly in the return expression is added to `fnEverMoved` and exempted from the destruct list (ownership passes to the caller). `destructOnExit` and `unlockOnExit` come from `collectOwnsToDestruct` / `collectLockReleasesToBoundary` over the whole function root scope.

## throw, try and catch

Covers: `checkThrow`, `checkTry`, `requireThrowsWrapping`, the catch parameter.

- `throw <string>` is safe code. The function must carry `@throws` (checked first so a missing decorator is never masked by another throw rule). The operand must be a `static imut string`; it must also be a string literal (templates are already reduced to one) or a bare variable, because `THROW string_id` takes one operand.
- `throw` is rejected inside the ghost-table decorator functions (`gt_init`, `gt_alive_check`, `gt_destruct`, `gt_register`, `gt_moved`, `gt_ref_id`, `gt_ref_resolve`): they have no `gt_routine` of their own, so the `THROW` would name a label that is never emitted. It is also rejected in `@pure` functions.
- `throw e` of a catch parameter is the one bare use of `e` that stays legal (`rethrowOperand`); any other bare use is the "caught error" error in the `VARREF` case (use `e.msg`, `e.stack_trace`).
- Unwinding is per throw site: `throwTok.destructOnExit` is exactly the `owns` locals alive at that point (`collectOwnsToDestruct(scope, functionRootScope, null)`, no preserved slot), and `unlockOnExit` releases every `match @lock` lock held (without that, a throw out of an OPEN case left the lock held). Each call to a throwing function gets the same lists (`op.destructOnExit`, `op.unlockOnExit`), used when the callee unwinds back into the call; the emitter only uses them when the program uses `throw` (`usesThrow`). Design: `BytecodeEmitter.emitThrow`.
- `try` wraps exactly one expression: a `CALL` (including the `dyn`/`resize`/`clone` builtins), a `new` expression, or a `par`/`await` call. Not `try foo().bar catch{}` or `try 1+foo() catch{}`. The wrapped node gets `insideTry = true`; the result type of the `try` is the wrapped call's type.
- Wrapping contract (`requireThrowsWrapping`, called from checkCall, checkLibraryCall, checkStaticMethodCall, checkImplMethodCall and the interface-dispatch site): a call to an `@throws` callee must be inside `try`/`?` (unless `coveredByThrowingNew`), and a `try` around a non-throwing callee is an error. `new`, `dyn`, `resize`, `clone` are always throw-capable, so only the "must be wrapped" direction applies; `checkNew`, `checkDynBuiltinCore` and `checkResizeBuiltin` read the flags themselves.
- Nested allocations (e.g. `new String{chars= new DynamicArray{...}}`) cannot get their own `try` (the grammar's try/catch consumes a whole line), so coverage is the context flag `insideThrowingAllocContext`, set for the whole descent of the wrapped expression and saved/restored. The emitter needs no change: `pendingTryCatchLabel` stays set through the nested `emitExpr`, so nested null checks land on the same outer catch label.
- The catch parameter is declared in a new `Scope` around the catch body with type `static imut string`, and registered in `activeCatchTries` (saved/restored for nested catches). `insideCatchBody` and `catchEnclosingLoopBoundary` are saved/restored around `checkLines` of the body, so a `continue` at any depth inside the catch is recognised and nested catches see the outer values.
- A catch body must be terminating: every path ends in `return`, `throw` or `continue` (`definitelyReturns`, the same conservative analysis used for "not every path returns"). A caught throw jumps straight into the catch block and never returns through the wrapped call's return path, so there is no point to resume at; `continue` is legal only where control can resume (the error message says: when this catch is itself inside an enclosing `try { ... }` block; the CLAUDE.md semantics say the next iteration of a user `for`/`loop`) (unclear which wording is current). Because of this no `tryTok.destructOnExit` is computed (the body never reaches a natural end; its own return/throw carries a complete list). See `BytecodeEmitter.emitHoistedCatchBlocks` and `emitContinue`.
- In expression position (`let x = try f() catch{..}`) `checkTry` is reached from `resolveExprTypeInner` with `insideLoop=false`; `resolveExprType` has no `insideLoop` parameter. A stray `break` in a catch reached that way is not rejected (known narrow gap).

## Expression type resolution

Covers: `resolveExprType`, `resolveExprTypeInner` (literal and `VARREF` cases), `resolveOperatorType` default cases.

- Literals: a string literal is `static imut string` and `some` (always present at compile time; `some` coerces one-way to plain). A `char` is indeterminate. An integer literal is indeterminate `u64` with `literalValue` as a `BigInteger`; one wider than 64 bits is an error (the lexer hands decimal text for every spelling). Built-in numeric limit constants (`u64Max`, `s8Min`, ...) carry `forcedLiteralType`. A float literal is indeterminate `f32` with `floatLiteral = true`.
- `VARREF` resolution order: ASM name (error: only usable as a bare statement); moved slot (error); local scope; global; const; function name.
  - A reference to a variable holding a literal-typed value strips the literal flags (`let x = mut 5` binds a plain `u64` slot whose value can change, so reads must not adapt to narrower slots).
  - A catch parameter used bare (other than `throw e`) is an error that points to `.msg`, `.stack_trace` or `throw e`.
  - Globals exist in `globals` before function bodies are checked, so use before declaration needs an explicit `declOrder` comparison against the function (or synthetic function for another global's initializer). A non-`@pub` global is visible only in its declaring file (`let`/`static` locals are exempt).
  - A `const` name is substituted: the `VARREF` token is mutated in place into the literal and resolved again, so the emitter has no const logic.
  - A bare function name (not followed by `(`) is a function pointer value with its own signature, decorators and calling convention; more than one overload is an error; `@event_loop` functions cannot be referenced.
- Reading a `ref some` local runs `ProofKills.refSomeRead` unless it is the assignment target; reading a static requires shared state or `unsafe` and, in `@pure`, no mutable static reads.
- `dup` and `and` reaching the generic dispatch are errors (`dup` is expanded earlier by `DupExpander`, `and` is walked by `checkMatchCondition`). `into` is legal only in `match`, `for match` and `@lock(...)` (those call `checkIn` directly); `fits` only as a match condition.

## Operator dispatch context flags

Covers: `resolveOperatorType`, `checkLogical`.

- `resolveOperatorType` is the single choke point for operator nodes. It captures two one-shot flags into locals and resets the fields before dispatch, so a stale `true` from an enclosing context cannot leak into unrelated operators:
  - `insideShortCircuitEligiblePosition` -> `eligibleHere`, passed only to `checkLogical`.
  - `insideStructRvoDestinationPosition` -> `eligibleForRvoHere`, passed only to `checkCall` (re-armed across `mut`/`imut`).
- `&&`/`||` are always eager (both operands evaluated, `BytecodeEmitter.emitLogical`); `&&then`/`||then` are the lazy variants. One type check serves both (operands bool-or-integer, indeterminate bool result); only legality differs. A then-variant is legal only at the top of an `if`/`elseif` condition: as its root operator or nested under further then-variants only. Not as a function argument, inside `!` or a comparison, as an operand of a plain `&&`/`||`, or inside `match`. Only a then-variant re-arms eligibility for its operands; a plain `&&`/`||` leaves it consumed.

## Ownership moves

Covers: `slotKeyOf`, `markMovedIfOwned`, `markMovedIfOwnedInner`, `requireNotMovedAlready`, `newDynDepth`.

- A slot is a bare variable name, an `a.b` member path or `x[i]` (grouping parens transparent). Anything else (call result, fresh literal, arithmetic) is not a slot: nothing to move from, never tracked. `x[i]` was added so a proof granted for a specific element (e.g. the `Some(...) in/into` sugar's element-alive proof) can be matched against a later real `x[i]`; both target and index must themselves be slots.
- `markMovedIfOwned` is called wherever a value is matched against a declared type (let inference, assignment, call argument against its parameter, struct-literal field). When the declared type is `owns`, the source slot is added to `scope.movedSlots` and `fnEverMoved`, and the token gets `isOwnershipMoveSource`. The mutability wrapper is transparent: `a = mut b`, `take(mut b)`, `let c = mut b` all move `b`.
- Operands of one call, array literal or `dyn([..])` are all checked before any is marked moved, so `f(a, a)` passes the read check. A slot already moved when its own move is recorded was moved by a sibling operand: error "moved more than once in the same expression" (`requireNotMovedAlready`).
- Inline owning structs (`isInlineOwningStruct`): copying one would leave two owners, so the source slot gives its owned members up (nulled at run time, `BytecodeEmitter.emitOwnershipMoveNullOut`; token gets `inlineOwnsStruct`). `deref(...)` of one, and reading one out of an indexed element (also `d[i].h`), are errors; use `clone`.
- `newDynDepth > 0` while the operands of `new`/`dyn` are checked: an owner moved in is freed if the allocation fails, so the move ends alive proofs (`ProofKills.kill`).
- A fresh `let` clears any stale moved flag (a loop body redeclaring the name after the loop pre-scan seeded it moved). A fresh assignment revives the target slot twice: before the left side is resolved (so the move check does not reject a legitimate revival) and again before the final move check (so `arr = resize(arr, ..)`, where resolving the RHS moves `arr`, is not left moved). `partlyMovedSlots` is cleared alongside.
- A `let` of an `owns` or inline owning type records the name in `scope.declScope().ownsDeclaredHere` in declaration order, which is what the scope drops at every exit; `func.ownsLocalTypes` records its type; a locked async handle is recorded in `fnHandleDecls`.
- `deref(p)` is a value (copy), never a place: it is rejected as the target of `=`, compound assignment, `++`/`--` and `swap` (`rejectDerefAsWriteTarget`). Write through a pointer with `.` member assignment on a proven-alive struct pointer, or `memcopy`.

## Match-proof invalidation

Covers: `invalidateMatchPatternsForWrite`, `exprKeyOf`, `proofKeyOf`, `lookupKeyOf`, `assumeKeyMode`.

- Called from every write: `=`, compound assignments, `++`/`--`, `swap`. It marks `Token.MatchPattern.invalidated` for any active proof whose `slotKey` (divisor of a nonzero proof, index of an `in`/`into` bounds proof, pointer of an alive proof) or `rightSlotKey` (the array of a bounds proof) is the written slot. Writing either side of a bounds pairing invalidates it. A proof on an assumed expression (key starting with `(`, e.g. `p+i`) dies when any variable in it is written (word-boundary regex match).
- `exprKeyOf` builds a canonical key for expressions over variables, integer literals, unary minus, `.`, `LOOKUP`, plain calls (name plus argument keys) and `+ - * / %`, always starting with `(` so it cannot collide with a slot key. Used only to record and look up facts vouched for with `assume match`; in `assumeKeyMode` (true while an `assume match` condition is checked) a proof may name an arbitrary expression. `lookupKeyOf` prefers the slot key, `exprHint` renders a key as source-like text for messages.

## Atomic write rules

Covers: `checkAssign` (atomic parts), `requireNotAtomicOrdinaryWriteTarget`.

- A direct atomic declaration (`let x = atomic '!'`) is legal only for a global or `let static` local, never a plain `let`. An expression that merely resolves to an atomic value (reading an existing atomic global) is silently stripped to a non-atomic local (`let myAtomicChar2 = myAtomicChar`).
- `=` into an already-atomic target is allowed only when the RHS has the shape `isSwapRhsAllowedShape` accepts for `swap`'s right operand: a bare variable, a literal or a bare `EnumName.Variant`. A computed expression is an error; use `swap`. An outright ban was too strong: the synthesized lock-release write in `checkLockMatchStatement` (`receiver.field = mut StateEnum.OPEN`) has exactly this shape and is safe (a fixed literal has no dependency on the lock's prior value).
- Compound assignment (`+= -= *= /= %=`) and `++`/`--` on an atomic target are rejected outright (`requireNotAtomicOrdinaryWriteTarget`): they decompose into a PUSH/op/ASSIGN sequence with a gap another thread can land in, while the bytecode type operand would still say "atomic". They are self-referencing by construction, so no variable-or-literal shape exists.
- A bare `EnumName.Variant` is always `imut` and would not coerce to a `mut` target through `typesCompatible`; `checkAssign` special-cases it (`isBareEnumVariantRight`), the same exception `checkInstantiate` (swap-field construction) and `checkSwapOperator` make.

## Mutability and const rules

Covers: `requireNotConst`, `requireNotLoopImmutable`, `requireMutable`, `requireStaticMutable`, `requireConcreteMutability`.

- A `let const` local (`Scope.isConstName`), a const parameter and a const struct member (`TypeInfo.isConst`) can never be assigned outside their declaration. A struct-literal initialisation (the "OTC pattern") is checked by `checkInstantiate` and never reaches this check.
- Inside a `for`/`for match` body, the loop variable and the trackable source expression are immutable (`Scope.ownLoopImmutableSlots`/`isLoopImmutable`); `arr[i] = ..` is untouched here (`requireLookupWriteAuthorized` is the separate "into" write gate).
- `requireMutable`: the target must be `mut`, and the walk repeats for every prefix of a dotted or indexed path (`my_struct.x = y` is rejected when `my_struct` is indeterminate or immutable). In a `@pure` function a target with pointer storage (`raw/owns/ref/auto/static`) anywhere in the chain is rejected, and `unsafe` gives no exemption (checked unconditionally). `LOOKUP` is walked only for that pointer check, recursing through the same call so `p.arr[0]` reaches `p`.
- A variable only accepts a concrete mutability (`mut` or `imut`). Indeterminate values (literals, struct/array literals, arithmetic/comparison/logical results; string literals excepted) must be given `mut`/`imut` first.
- A `static`/global scalar needs concrete mutability, either `mut` or `imut` (not only `mut`: the narrower reading blocked a concrete `imut` static and, since a string literal is always `imut`, any static holding a string literal). A struct-typed static is exempt because member declarations already dictate each field's mutability.

## Compile-time constants

Covers: `checkNoRuntimeConstructs`, `resolveConstValue`, `evaluateConstant*`, `resolveTemplateString`, `stringifyTemplateSegmentValue`, `formatConstFloat`.

- `const NAME EXPR`: wherever the name is referenced it is replaced by the literal it denotes. The right side is any literal or compile-time-resolvable expression. Consts may be forward-declared, so evaluation is lazy and memoized (`constResolvedValues`) with circular-definition detection (`constsBeingEvaluated`), the same shape as `flattenStruct`/`flattenInterface` for inheritance chains.
- `evaluateConstant` mirrors `resolveOperatorType`'s dispatch, so every operator already type-checked there gets constant folding without a parallel evaluator: literals, other consts, `mut`/`imut` (transparent), unary minus, `+ - * / %` (int via `long`, float via `double`, `/`/`%` by literal 0 is an error), `!`, `&&`, `||`, comparisons (numeric compared as `double`; non-numeric `==`/`!=` only between same-typed bool/char/string, compared by `literalValue`). Calls, variables and everything else are errors with specific messages. Floats are formatted with a decimal point and no redundant zeros/scientific notation (`formatConstFloat`).
- `static`/global initialisers (`checkNoRuntimeConstructs`) forbid any `CALL` (except `sizeof(T)`, a compile-time constant whose argument is a type) and `new` (a runtime allocation); variable references fail naturally because the initialiser is resolved in an empty `Scope`. Struct and enum names still resolve (they are looked up in TypeChecker's maps, not through `Scope`).
- A `let static` is only legal at the top of a function body (`staticApproved`); its declaration goes in `scope.declScope().staticNames`.
- Template literals: each `${...}` segment is evaluated by `evaluateConstant` (consts, `__LINE`, `__FILENAME`, arithmetic; variables and calls rejected as in a const RHS). Segments concatenate into one string and the node is mutated in place into a `STRING` token (`quoteDelimiter` backtick), so later stages never see a template. The Lexer wraps each `${..}` in a synthesized `(` group (not `{`), which is what reaches this stage. Segment values may be string, integer, char or bool; a float is rejected because the formatting convention (decimal places, trailing zeros, scientific notation) is unsettled.

## Let type bounds

Covers: `resolveAndValidateTypeBound`.

- `let:<FullType> name = expr`: the bound is always a complete type annotation (no partial-type merging), resolved by `resolveTypeAnnotationRaw` like any parameter or return type. The RHS must be: `null` against a pointer bound (`isPointerType`, i.e. owns/ref/raw, not auto/static; and never against a `some`-tagged bound, which this path checks by hand because it does not go through `typesCompatible`); an exact type match; or an implementer of an interface bound, with compatible storage and mutability. Literals adapt via `literalAdapts`/`adaptLiteral`. No other implicit casting (casting is explicit via `as`).
- The variable's declared type is the bound, so `requireStaticMutable` applies to it for a `let static`. Returns null when there is no bound so the caller falls through to its unbound logic.

## Division proofs

Covers: `requireProvenNonzeroDivisor`, `checkArithmetic`, `checkCompoundAssign`.

- Integer `/`, `%`, `/=`, `%=` need a divisor that is a nonzero literal, a live "nonzero" match proof for that exact slot (`match d != 0{..}` for unsigned, `match d > 0{..}` for signed: `!= 0` alone is not enough for signed because MIN / -1 overflows), or `assume match d != 0` in an `unsafe assume{` block. `unsafe` alone does not lift it.
- A literal `0` divisor is a hard error regardless of safety context. Float divisors are exempt (IEEE division by zero gives +-Infinity/NaN, no trap).
- Arithmetic between two float literals is itself a float literal (adapts as a whole to f32 or f64). Unary minus keeps a literal a literal: `-5` has value -5, default type `s64`, and adapts to any signed type that holds it; `-0.5` stays a float literal.
- `raw` pointer arithmetic is C-style: `p + n`, `n + p`, `p - n` move by n elements (`pointerArithKind` 1/2, `pointerScale` = pointee size, `pointerScaleStruct` for struct pointees); `p - q` of the same pointee type gives a signed `s64` element count (kind 3); two pointers cannot be added; any other operator keeps its numeric meaning. `p += n` / `p -= n` and `p++` scale likewise (a one-byte pointee keeps the ordinary path, byte-identical to before).
- `==`/`!=` also compare a pointer with `null` on either side; ordering comparisons do not. `normalizeRefComparison`: a nullable `ref` is an id and every other pointer an address, so an address compared with a nullable `ref` becomes an id (`GT_REF_ID`; equal objects have equal ids), and a `raw` pointer compared with one makes the id an address (`GT_REF_RESOLVE`). A `null` literal is 0 in both forms and needs nothing.

## Calls: dispatch, event loop, privacy, externs

Covers: `checkCall`, `checkExternCall`.

- Resolution order in `checkCall`: `sleep` keyword (resolved to whichever function carries `@sleep`, regardless of its name); `.` method calls; builtins; externs; functions by name. A bare call naming a struct resolves against that struct's constructors (`Parser.CONSTRUCTOR_NAME_PREFIX + name`); constructors are ordinary struct-returning `FuncInfo` overloads by then (see `collectFunc`). Overloads are tried in `orderByLiteralExactness` order.
- Event loop: neither `@tick` nor `@event_loop` needs a fixed name, so inside an `@event_loop` function body a literal `tick(..)` is redirected to whichever function is decorated `@tick`. The stdlib loop always writes `? tick(state)`; the wrap is kept only if that tick is `@throws`, so the two-way `@throws` rule still holds. `@event_loop` functions cannot be called or referenced anywhere. When `main` is `@with_tick`, only the `@event_loop` function may call `main` or the `@tick` function (checked against the candidate's identity, so the real name is caught too; `main`'s decorators are read from `functions` because `eventLoopFunc` is not set until `validateTickEventLoop` runs at the end of `check()`). `main` and `@tick` called from the event-loop body are also exempt from the private-function rule (singleton whole-program constructs).
- A non-`@pub` function is accessible only from its declaring file (a plain top-level function has no enclosing impl to check, unlike `checkImplMethodVisibility`).
- `@async` functions can only be called through `par`/`await`, and those only on `@async` functions. Passing a pointer, including nested in struct members, across `par`/`await` (or returning one from an `@async` function) needs `unsafe async`.
- After resolution: `markMovedIfOwned` per argument, `op.destructOnExit`/`unlockOnExit` (per-call-site lists used if the callee unwinds into this call), `@recursive` self-call checks, `requirePureCalleeIfPure`, and a `CallEdge` record. Calling the function from inside its own base-case match block is an error (it loses recursive privileges there).
- Extern calls (`checkExternCall`): declaring an extern needs no `unsafe`, every call site does (like `raw` construction and `call()`); banned in `@pure` (behavior can never be verified at compile time). Fixed parameters are checked like an ordinary call (arity and `acceptsAdaptingLiteral`); beyond them (only with a trailing `...`) any type and mutability is accepted, but the value must be concrete since no expected type exists to coerce an indeterminate value against. The call target is `info.linkName` (the real linked symbol; `@link_name` can override the name).

## Builtin calls

Covers: `checkBuiltinCall`, `checkSleepCall`, `checkSomeBuiltin`, `checkConvertBuiltin`, `checkInsecureRandBuiltin`, `checkSizeofBuiltin`, `checkCallBuiltin`, `checkBitsBuiltin`, `checkMemcopyBuiltin`, `checkDerefBuiltin`, `checkCloneBuiltin`.

- Builtins look like function calls but get their own instruction in the bytecode (unless otherwise specified). `checkBuiltinCall` dispatches on the reserved name; builtins never go through the user-function overload table.
- **`sleep(...)`**: a real Lexer keyword, so the callee is not an independently resolvable name. It always means "the function carrying `@sleep`", found through the `ghostTableFunctions` registry that `@par_call`/`@await_call` also share, and resolved to that function's real mangled name (not a hardcoded literal like the bytecode-level `GT_INIT` callees; see `forceGhostTableFunctionNames`). Argument checking mirrors `checkExternCall` (fixed arity, fixed types via `typesCompatible`/`acceptsAdaptingLiteral`; no overload resolution, since there is only one `@sleep` function). It is emitted as `SLEEP sleep_call duration`, not `CALL`; `op.isSleepCall` is the emission-side routing flag (`BytecodeEmitter.emitCallOrBuiltin`). Using `sleep` with no `@sleep` function is an error.
- **`Some(x)`**: generally available (like `instanceof`, `implements`, `in`), not only as a match condition; it replaced the old bare form `match x{...}`. Checked like any builtin and returns an ordinary `bool`; `checkMatchCondition` additionally records an "alive" proof when the shape `Some(x)` (x a bare trackable slot) is a match condition, the same two-layer split `in`/`instanceof` have. `op.someOnRef` is set for a nullable `ref` argument.
- **`wrap:<T>(x)` / `sat:<T>(x)`**: total integer conversions (no `unsafe`, cannot fail): `wrap` keeps the low bits, `sat` clamps to T's range; any integer width/signedness in, T (indeterminate mutability) out. `wrap:<f32|f64>(x)` converts floats (f64 to f32 rounds to nearest, f32 to f64 is exact; a float literal is adapted, otherwise `op.isFloatConvert`). `sat` evaluates its argument more than once in the emitted code, so the argument must be a plain variable, field chain or literal (optionally negated / `mut`/`imut`-wrapped; `isPureSimpleOperand`).
- **`insecure_rand()`**: returns a non-crypto-secure `u64`, bound to C `rand()`; its name carries the warning. It is not `unsafe` and IS allowed in `@pure`: `@pure` means side-effect free, not referentially transparent. Unlike a user `extern` (always `unsafe`, always banned in `@pure`, since the compiler cannot know what an external symbol does), this is a compiler builtin with a known side-effect-free implementation, so it is checked on its own path (never via `checkExternCall`) with neither restriction attempted. Takes no arguments. Banned in `@pure(rt)` (non-deterministic).
- **`sizeof`**: both forms: a bare (or storage-prefixed) type name, or an expression whose resolved type is used (`tryResolveAsTypeDescriptor` walks storage/mutability prefix operators down to a VARREF that is a known type; it is deliberately narrow: array-bracket and composite range syntax do not parse as expressions there). Mutability does not affect size; the result is a `u64` with indeterminate mutability. For an array, the size of its base element type. Sizes: any pointer = `POINTER_SIZE`; range = 16 bytes (two u64 bounds); primitive = `PRIMITIVE_SIZE`; struct = estimate 8 (hidden `___type` word) + member sizes (never below 8); the real size with padding is resolved later by `SizeofResolutionPass` from the symbolic `SIZEOF` (`op.sizeofStruct` is set via `sizedStructName` for struct and array-of-struct operands). Unknown types are an error.
- **`call(fp, args...)`**: variable argument count (function pointer, then the call's arguments), so it cannot use `collectSingleBuiltinArg`. Unsafe only (tag `call`). Everything is still checked: arity, each argument type (same `acceptsAdaptingLiteral`/`typesCompatible` as other call sites, including the decorator-subset rule) and the result type all come from the function-pointer value's recorded signature. Banned in `@pure` (the target's purity cannot be verified at compile time). Owns arguments are moved.
- **`bits_left/right/rotl/rotr/or/and/xor/not`**: the C `<<`, `>>`, `|` etc. equivalents. Integer types only (bitwise on a float is meaningless). Binary forms: both sides the same integer type, result that type, indeterminate mutability; an integer literal on one side adapts to the other side's type when it fits (`bits_and(x_u8, 255)`), two literals of different default types (`bits_and(5, -1)`) unify the same way, two typed operands must match. `bits_not(a)`: one argument, complement truncated to a's own width (`u8`: `bits_not(0) == 255`; signed: two's complement), result a's type.
- **`memcopy(raw u8, u64, any pointer)`**: copies the byte count from the source pointer to the destination; the destination must be `raw`, the count a plain `u64`, the source any pointer. The return type mirrors the destination's type (same "result is what was pointed to" shape as `clone`/`deref`). Restricted to `unsafe` (tag `memcopy`) explicitly, not implied by requiring a `raw` first argument: a `raw` value, once constructed, can be held and passed around from ordinary code; only constructing one is gated.
- **`deref(p)`**: the pointee's value with storage stripped (like any inline value), so it is usable with `.` member access directly (`checkDot`'s pointer restriction fires only when storage is non-null). Needs an alive proof (`auto`, `some`-tagged, inside `match Some(p)`, or `assume match Some(p)` in `unsafe assume`); for a `raw` pointer it additionally needs `unsafe deref`. Banned in `@pure(rt)` (reads through a pointer).
- **`clone(p)`**: any storage accepted; result is `owns some` with the pointee's base type and mutability (dynarray/array shape and alias kept). It allocates and registers like `new`: it can fail, needs `try`/`?` (`op.insideTry` or `insideThrowingAllocContext`) and sets `usesOwnsRefDynNew`/`usesThrow`. The source is read, so it has the same alive-proof rule as `deref`, plus `unsafe clone` for `raw`. Cloning a type that reaches a `@drop` resource is an error. Banned in `@pure(rt)`.

## len and range

Covers: `checkLenBuiltin`, `checkRangeBuiltin`.

- **`len(x)`** for an array or a *direct* string literal token is a compile-time constant (`op.builtinConstantValue`); a variable holding a string literal does not carry its length (same restriction as `[]` bounds checking). A safe dynarray's length is a run-time value: `builtinConstantValue` stays unset, and `BytecodeEmitter` reads that absence to emit a real `LEN`.
- **`len(unsafe_dynarray, terminator)`**: the 2-arg form scans for the terminator (an unsafe dynarray has no hidden length). Requires unsafe code (tag from `udynTag`); the first argument must be an unsafe dynarray; the terminator's type must equal the element base type (same check as `resize`'s fill). `builtinConstantValue` stays unset (real scan). The bare 1-arg form on an unsafe dynarray gets its own error rather than the generic "requires a string/array/dynarray" one.
- **`range(x)`**: `0..len(string|array|dynarray)` with the same length-knowability rules as `len`. A string literal / fixed array gives the type `range(0,N)` with bounds baked in (`BytecodeEmitter` emits two `PUSH` literals, no instruction). A safe dynarray gives the plain bounds-incomplete `range` (bounds are always two u64s, known or not) with `builtinConstantValue` unset. An unsafe dynarray is rejected (no hidden length and no terminator argument exists here).

## dyn and resize

Covers: `checkDynBuiltin`, `checkDynBuiltinCore`/`Inner`, `checkUnsafeDynWrapper`, `checkResizeBuiltin`/`Inner`.

- **`dyn([0,1,2,3])`** builds a fresh owns runtime-resizable array from an array literal; every element is given explicitly (no uninitialised field). It reuses `checkArrayLiteral` unchanged (uniform element type, null poisoning, owns-move tracking); `dup` is already expanded. `op.builtinConstantValue` carries the element count to `BytecodeEmitter` (the `NEW dynarray(T) count` line needs it). The element TypeInfo is taken from `fixedArrayType.arrayElementType`, not re-resolved.
- `dyn:<T>([])`: the typed empty dynarray; the only literal a type argument is accepted with is the empty one (exactly one element type, known type, element `mut T`). An empty literal without the type argument is an error.
- `dyn(text)` with a string gives a dynarray of `imut char` (`op.dynFromStringSource`), so String construction needs no `raw`/`unsafe`; the element type mirrors string `[]` access (always imut char).
- **Throwing**: the safe `dyn` allocates like `new` and needs the same try/catch (`op.insideTry`, or `insideThrowingAllocContext` when nested inside another `new`/`dyn`/`resize` operand); `usesThrow` is set unconditionally (the reserved `gt_routine_address`/`gt_error_message` slots are needed whenever a throwing `dyn` is checked). The `unsafe dyn` form is exempt (looser guarantees in unsafe mode). `newDynDepth` tracks nesting.
- **`unsafe dyn([..])`**: prefix-operator wrapper (promoted to a unary OPERATOR by `RpnConverter` like `new`/`await`/`par`). It must directly wrap a `dyn(...)` call. Unlike `checkAwait`, it cannot use the ordinary dispatch (the inner CALL must resolve to the unsafe dynarray type), so it calls `checkDynBuiltinCore(..., true)` and sets `op.left.resolvedType` by hand. Banned in `@pure`.
- **`resize(d, n, fill)`**: in-place resize of a `mut` dynarray; shrinking truncates, growing fills every new slot with `fill` (no uninitialised slots). Allowed in safe code. `fill` must match the element base type; `n` must be a plain `u64`. A direct `resize` inside a `for i in dynarrayExpr{..}` body is an error (`scope.insideDynArrayForLoopBody`; the indirect case is `checkDynArrayForLoopResizeSafety`'s reachability walk). Records `funcsCallingResizeDirectly`. After checking, `ProofKills.kill` ends alive proofs (the block may move or shrink).
- **Unsafe variant**: two arguments (a bare realloc; no fill, may leave memory uninitialised), requires unsafe code (tag from `udynTag`), cannot throw: `try` around it is an error (the same two-way contract `requireThrowsWrapping` enforces). The safe variant takes exactly three arguments and needs try/catch like `new`/`dyn`.
- **Ownership**: `resize` takes ownership of the dynarray and returns a new owns (a realloc can return a new pointer); both variants. The old binding is consumed via `markMovedIfOwned`, called by hand because `resize` bypasses the ordinary call/parameter machinery. Banned in `@pure(rt)` (allocation depends on heap state).

## Method calls

Covers: `checkMethodCall`, `checkGenericMethodCall`, `instantiateGenericMethod`, `checkInterfaceMethodDispatch`, `checkStaticMethodCall`, `checkImplMethodVisibility`, `markStructRvoMethodCall`.

- `receiver.methodName(args...)`: the receiver is used only to resolve which concrete type's impls to search; it is never injected as an argument. Whatever the impl's first parameter needs (typically `self`) is passed explicitly. Resolution is entirely compile time: each call is matched to one concrete existing function (`op.resolvedCallTarget`); no run-time dispatch.
- Dispatch order in `checkMethodCall`: (1) bare name that is not a variable but is a struct/enum: `TypeName.method(..)` static call (`checkStaticMethodCall`); it cannot go through `resolveExprType` (a bare type name is not an expression and would fail as "use of undeclared variable"); a generic receiver (`DynamicArray:<u64>.method`) arrives already monomorphized by the generics expander. (2) bare name that is a library: `checkLibraryCall`. (3) receiver resolved as an expression (not via `checkDot`); an interface-typed receiver goes to `checkInterfaceMethodDispatch`. (4) `method:<U>(..)` explicit generic args (left untouched by `GenericsExpander`, see its `walkAndProcess`) go to `checkGenericMethodCall`; such a method is never in `impl.methods` (`ImplInfo.genericMethodTemplates`). (5) ordinary overload search over the impls (`orderByLiteralExactness`, `argSatisfiesParam`).
- After a match: `retagLiteralArgs`, visibility, `resolvedCallTarget/Convention`, `requireThrowsWrapping`, owns moves, per-call-site unwind lists (below), self-recursion rules (`suspendsSelfRecursion`; `@recursive` return-site/proof checks), `requireMethodLockProofs`, `requirePureCalleeIfPure`, a `CallEdge`, then the struct-RVO check.
- A name that exists only as the other kind gives a specific error ("is a static method on X, not an instance method" and the mirror), instead of the generic "no method".
- **Visibility**: the outer, impl-level gate is checked first and unconditionally (a non-`@pub` impl is unreachable outside its file, whatever the method's own `isPublic`); then a private method is callable only from another func of the *same* impl block (`==` identity: a struct can have several impls, a bare `impl` and `impl InterfaceName for`, each a separate `ImplInfo`).
- **Method RVO**: a method returning a plain struct writes through a hidden destination pointer, so the call may only be a `let` RHS or a plain bare-variable assignment RHS (directly or under `mut`/`imut`/`try`/`?`); same rule and message as `checkCall` (see CLAUDE.md, "Struct returns use RVO").
- **Residual-generic method (`recv.method:<U>(..)`)**: only one generic template per name (no generic-method overloading). `instantiateGenericMethod` memoizes per `name<args>` key in `ImplInfo.genericMethodInstances`; checks type-parameter bounds (`structImplementsInterface`); clones with `deepCloneCheckedTree` (the template is already gathered/RPN/tree-built, unlike a `@default` method's raw body, so no fresh `RpnConverter`/`TreeBuilder` pass); substitutes `self` (diverted away in `collectImpl`) and the type parameters (`substituteGenericMethodParams`, the TypeChecker-side counterpart of `GenericsExpander.substituteParams`); builds the FuncInfo (forced `isPublic`, like `materializeDefaultMethod`; mangled name `Concrete[__Iface]_method__Args`); registers the instance BEFORE checking its body (guards a recursive self-instantiation and avoids a ConcurrentModificationException in `implInfo.methods`); appends the clone to `impl.declTok.childs` because BytecodeEmitter walks the impl root's childs.
- **Interface dispatch**: `c.foo(args)` on a bare interface type uses the dispatcher `generateOneInterfaceDispatcher` built for (interface, method), looked up by `interfaceDispatcherName`. A separate block, not folded into the impl loop, because the dispatcher is a plain top-level FuncInfo with no `ImplInfo`: visibility, self-recursion and lock-proof bookkeeping do not apply (compiler-internal, public, never self-recursive, never lock-decorated). Exactly one candidate, so plain arity/type matching. The error lists the reasons no dispatcher exists: no explicit `self`-typed parameter, `@lock`/`@unlock` decorated (not yet supported), or no `@gt_alive_check` function in scope (import the ghost-table stdlib).
- **Static calls** (`checkStaticMethodCall`): structurally identical to the instance path (same overload search and bookkeeping) except there is no receiver value; also runs `checkFsPolicyAtCall`.
- **Per-call-site unwind lists**: each call site records `op.destructOnExit = collectOwnsToDestruct(..)` and `op.unlockOnExit = collectLockReleasesToBoundary(..)`: if the callee (or anything it calls) throws and unwinds into this call, the caller needs to know exactly which owns locals and locks are live right here (the precision an ordinary `return` at this point has), not a whole-function conservative list. See `checkThrow`. `BytecodeEmitter` uses them only when the program uses `throw` (`checker.usesThrow()`); cheap to compute unconditionally.
- `buildFieldDot` builds a raw `receiver.field` node for `checkLockMatchStatement`, marked `isCompilerSynthesizedSwapAccess` so `checkDot`'s swap-field restriction exempts it (the same "compiler-mediated access is exempt" shape as `isCompilerSynthesizedLockCall`). `buildEnumVariantRef` builds `Enum.Variant`.

## match @lock lowering

Covers: `checkLockMatchStatement`.

- `match @lock EXPR{ OPEN:{..} CLOSED:{..} }` is the safe spin-lock entry point: exhaustive over the two-variant enum of the struct's `swap` field (OPEN and CLOSED mandatory, not `|`-chained, no duplicates), lowered to a loop using `ATOMIC_SWAP`. It is gathered as an ordinary case-match (`Parser.gatherLockStatement`, `isCaseMatch=true`): `stmt.sub.get(0)` is the receiver, `stmt.childs` one token per case. Banned in `@pure`. Receiver slot is added to `fnLockMatched`.
- Every piece is built as an ordinary Token tree and resolved through the ordinary machinery (`checkSwapOperator`, comparison, `checkAssign`, `checkDot` enum-variant branch), the same reuse precedent as `checkLockBlock`'s synthesized lock()/unlock(). `stmt` is mutated in place into a real `loop` only at the very end (`stmt.text="loop"`, `isLockSpinLoop`), after each piece was validated. Pieces: acquire `recv.field swap Enum.CLOSED`; condition `== Enum.OPEN` against the swap's snapshot result; release `recv.field = Enum.OPEN` (checked once, replayed at every OPEN-case exit; NOT wrapped in `mut`, because an enum-variant reference always resolves imut and `mut EXPR` never accepts an imut operand; `checkAssign` has the matching exception for a bare enum-variant literal into a concretely-`mut` enum slot, as do `checkSwapOperator`'s right operand and `checkInstantiate`'s swap-field construction).
- The OPEN body owes `releaseAssign` on every exit (natural end or user `return`/`break`) through `Scope.activeLockReleases`, which `checkReturn` and `break` already consult. Both case bodies are parented through one extra loop-boundary `Scope` (`loopBodyScope`) so a user `break` inside either targets this statement's own implicit spin loop. Inside the OPEN case the struct's `@lock(match self.<swap field> : OPEN)` proof is planted for the receiver (`enum_field_variants`, as `hasEnumFieldProof` expects), and `lockClosedLoopScope` is null (a `continue` while holding the lock is meaningless).
- The synthesized "got it, stop spinning" `break` is appended after the OPEN body (dead code if the body already ends in return/break). Its `destructOnExit` covers only owns locals declared inside the OPEN body (stop at the spin loop's boundary scope, like a user `break`); walking on to the enclosing function scope would destroy the matched handle before the lock release wrote through it. Its `unlockOnExit` includes `releaseAssign`.
- CLOSED case rules: moved-slot state of both branches is merged into the pre-state; every CLOSED path must end in `continue|break|return|throw` (`closedCaseTerminates`). In safe code a retrying CLOSED (`lockRetryContinuesSeen` rose) without `CLOSED:default(n)` or a registered policy is an error (a bare retry would spin without a limit); the `@gt_*` ghost-table functions (`isGhostTableFunction`) and compiler glue (`synthesizingGlueBody`) are exempt. A try-lock (no retrying path) gets `lockSpinBound = 1`.

## CLOSED:default substitution

Covers: `detectDefaultPolicyRef`, `substituteDefaultLockMatchPolicyIfPresent`, `DefaultPolicySubstitution`, `literalLimit`, `LOCK_SPIN_LIMIT`, `buildTriesIncrement`, `buildGiveUpCheck`.

- `Parser.gatherMatchCases` (raw-token level, `allowDefaultPolicyRef`) wraps the shorthand `CLOSED:default` / `CLOSED:default(args)` as one ordinary expression-statement line whose child is a bare VARREF `default` or a CALL whose left is VARREF `default`. `detectDefaultPolicyRef` finds that lone child on the tree-built body; an ordinary `{...}` body gives null and nothing is changed.
- **No registered policy** (built-in): `CLOSED:default(n)` retries up to n times (attempts 1..n), then `break`. Needs exactly one `u64` argument. Builds pre-loop `let mut $lm_tries = 0` and `let imut $lm_limit = <arg>`, and the body `$lm_tries++; if $lm_tries > $lm_limit{ break }; continue`. `spinBound` = the literal value of `n` (`literalLimit`: underscores, `0x`/`0b` allowed; -1 if not a literal) which `--audit`/`GasReport` reads.
- **Registered `impl default match @lock` policy**: validates the call's argument count/types against the policy parameters (the first parameter is always the automatic per-iteration "tries" counter, never supplied; every later parameter is a caller-supplied configuration value, positionally bound). Builds pre-loop `let` assigns: `$lm_tries = 0` plus one per configuration parameter, bound once before the loop under its real declared name (the cloned body refers to it by that name). The policy's raw parameter list/body is deep-cloned per use site (`deepCloneRaw`; the template's `break` has nothing to target until this loop exists) and run through `Parser.gatherStatementLines`, `RpnConverter`, `TreeBuilder`. The new CLOSED body is: `$lm_tries++`, `let <triesParamName> = imut $lm_tries`, the compiler-enforced give-up check, the cloned body, and an explicit `continue` unless the body already ends on every path (preserves "falling off the end retries"). The body is left unchecked here; the caller's `checkLinesInScope` checks it. Pre-loop assigns are checked when built (they live on `stmt.preLoopInit`, outside `closedCase`).
- **Give-up check**: the compiler, not the policy, enforces the bound: after the counter bump, `if $lm_tries > <limit>{ break }`. The limit is the policy's second parameter when it is a `u64` (`tries, limit`), else `LOCK_SPIN_LIMIT` (1_000_000_000). A policy that gives up earlier (`if tries >= limit{ break }`) still does; the body runs for attempts 1..limit. `spinBound` is the literal first call argument when the limit parameter exists, else `LOCK_SPIN_LIMIT`.

## Method lock proofs

Covers: `assumedLockPatterns`, `requireMethodLockProofs`, `hasEnumFieldProof`, `requireStructLockProof`, `checkOrBypass`.

- At a call to a method with `@lock(...)` decorators the call site must hold the matching proof ("this creates a requirement for this parent match at the call site"); checked once per call per `@lock` (a method may have several, each independent). Skipped inside `unsafe`. `argNodes` includes the receiver as its first element, matching `candidate.paramTypes`/`paramNames` (an instance method's first declared parameter is always the receiver, whatever it is named), so `paramNames.indexOf(name)` indexes `argNodes` directly.
- Inside the callee, "the condition of the parent match is assumed": `assumedLockPatterns` injects the required proofs into the function's root scope so its body needs no second `match`. Only for non-static impl methods; the receiver is `func.paramNames.get(0)`.
- Two clause forms: `@lock(match self.<field> : VARIANTS)` needs an `enum_field_variants` proof on the receiver slot (`hasEnumFieldProof`: an active, non-invalidated proof for `slot.field` whose proven variant set is contained in the required set). `@lock(match <param> in|within|into self.<field>)` needs a proof of kind `in`/`into` linking the argument slot (`boundsSlotKeyOf`, so a literal index is provable) to `receiver.field`. The written operator only affects the message ("within" must not suggest "in"). An `in`/`within` clause is satisfied by an `in` or `into` proof; an `into` clause needs an `into` proof (exact match: an `in`-proven site never satisfies `into`). `in`/`within` grant the read-only kind, `into` the write-capable one when assumed (`checkMatchCondition`'s `into` case).
- `Some(..)`-wrapped clause: additionally requires (call site) / grants (callee) the element-alive proof `self.field[param]` (kind `alive`), the same second proof `checkSomeIndexBoundsCondition` grants for the bare-match/for-match forms.
- **Struct-level `@lock(match self.x : X)`** (`requireStructLockProof`): the discriminant field is freely readable; every other member needs an active enum-field proof for this exact receiver slot, planted by `checkEnumMatch` only within a case whose variants are all covered by the struct's required set; `unsafe` bypasses; compiler glue (`synthesizingGlueBody`) is exempt. If the lock field is also the swap field, the error suggests `match @lock`.
- `checkOrBypass(scope, tag, check)`: runs a pure proof check; in unsafe context a failure is not an error but records that the enclosing block needed `tag`.

## Array literals

Covers: `checkArrayLiteral`, `collectCommaArgs`.

- `[0,1,2,3,4]` reuses the bottom-up resolution `(`/`[` get from `RpnConverter`/`TreeBuilder` (one comma-chain tree); `collectCommaArgs` flattens it. Every element must be the same base type. The array's base-type string embeds element type and length (`elementType[length]`, same "embed everything" approach as `range`), so two arrays are the same type only if both match, via the unmodified `sameBaseType`. At least one element is required. `dup` is already expanded by `DupExpander` (before generics expansion).
- **null**: if every element is null the literal has type `null[n]` (the poisoned case, valid). Next to a non-null element the element type comes from that element and null is accepted anywhere a pointer slot accepts it (same `isPointerType` check), except a `some`-tagged element type (third site of the "null cannot satisfy `some`" rule, besides `typesCompatible` and the bound-type `let` path). null next to a non-pointer element is an error.
- **Integer adaptation**: integer literals next to a typed (non-literal) integer element take its type when they fit (`[c, c + 1, 7]` with `c: u16` is `u16[3]`); an all-integer-literal array containing a negative literal settles on `s64` (each element retagged). Two typed elements of different types still mismatch. Nested all-integer-literal arrays (`[[1,2,3],[4,5,6]]`) record flattened `literalElements` so the whole literal adapts to a `T[n][m]` slot; float literals record `floatArrayLiteral`.
- Elements of `owns` storage or inline-owning structs are moved in (`markMovedIfOwned`). `TypeInfo.array` carries the real element type (storage included) as `arrayElementType`, so a later `[]` (`checkLookup`) can hand a pointer element back as a pointer.

## instanceof and implements
Covers: checkInstanceof, checkImplementsOperator, structImplements, hasAnyImplementer, warn.
- `ifaceValue instanceof StructName` is a runtime compare of the value's hidden `___type` class id with the named struct's id. The left side must be interface-typed (a struct-typed left side is an error, its type is static); the right side must name a known, non-`@untyped` struct. `@untyped` structs carry no class id and can never be the left side. Interfaces are absent from `structs`, so `isUntyped` returns false for them.
- `structValue implements InterfaceName` is statically decidable for a struct-typed left side. It is also legal on an interface-typed left side ("does the struct behind this value implement another interface"), a runtime question.
- Both operators use the same alive-proof gate as `.` access (`requiresAliveProof`): inline (no-storage), `auto`, or `some`-tagged values pass, otherwise a live `match Some(..)` proof is needed. It applies identically as an expression and as a match condition (checkMatchCondition dispatches here). `unsafe` does not bypass it (known quirk, deliberately not patched here).
- Warnings (not errors), because the program is still well-typed: `x instanceof S` where S does not implement x's interface; `x implements I` where no struct implements I anywhere, or where this struct does not implement it. `implsByConcreteType` is fully populated by `collectDeclarations` before body checking, so "no implementer" is a final whole-program fact. The optimizer lowers a provably false test to `PUSH false` silently; reporting belongs to the type checker. Always-true tests are never reported (a check may guard against a type damaged through a raw pointer in unsafe code).
- `warn(file,line,msg)` prints `[warning] file:line - msg` to stderr and checking continues; there is no warning collection or counting.

## Lookup (`[]`)
Covers: checkLookup, parseLiteralRangeBounds, isProvenInBounds, isProvenWritable, requireLookupWriteAuthorized, boundsSlotKeyOf.
- Default rule: a lookup is permitted only when the target length is known at compile time (array: part of the type; string: only a direct string literal) and the index is an integer literal within it. A variable index needs a live `match i in range(target)` proof for this exact (index, target) pair; the match already emitted the runtime check. A dynarray length is never compile-time known, so even a literal index needs the proof.
- A range-typed index is rejected ("slicing is no longer supported") before the knownLength error, so dynarray operands reach the clearer message.
- `op.isLookupProofReliant` is true unless the index is a literal into a type-known length. Writes (`requireLookupWriteAuthorized`, from checkAssign/checkCompoundAssign) need an `into` proof (superset of `in`) for the exact (index, target), e.g. `arr[i+1] = ..` does not qualify. Mutability is a separate check (`requireMutable`).
- Unsafe dynarray: `[]` requires `unsafe` (`udynTag`), has no bounds mechanism, never sets `isLookupProofReliant`, so writes need no proof (same precedent as raw pointers). Index must be an integer type.
- Result type: string element is `imut char`; dynarray/array elements take the container's mutability; a storage-bearing element type (owns/ref) is preserved. A fixed array only has a storage-bearing element TypeInfo when built from an array literal (`arrayElementType`); annotation-declared arrays fall back to the base-type string. In that fallback a `string` element is `static <mut> string`, and a `dynarray(..)` element is rebuilt with `TypeInfo.dynArray` (the inner text may carry a storage prefix such as `owns_Leaf`, split by `parseDynArrayElementText`).
- `boundsSlotKeyOf` extends `slotKeyOf` with `STRING_LITERAL:<text>` and `INT_LITERAL:<text>` keys (literals cannot be reassigned, so no invalidation); not folded into `slotKeyOf` because ownership tracking must not treat equal string literals as one slot.
- Range base-type strings: `range(2,5)` for literal bounds, `range(imut_x,5)` for variable bounds (`rangeBoundDescriptor`). `parseLiteralRangeBounds` returns bounds only if both parts are all digits (identifiers never start with a digit).

## as casts
Covers: resolveCastTargetBare, checkAs, isProvenFits.
- Legal shapes: alias relabel (storage and base type identical after resolving aliases; mutability untouched; sets `isAliasCast`), same-signedness integer widening (u8..u64 or s8..s64; `isSignedWideningCast` for signed), `x as f64` for an f32 (exact; a float literal just adapts to f64; `isFloatConvert`), and tightening under an active `match x fits T` proof (same width = relabel, narrower = `isTruncCast`, wider = SEXT/ZEXT by source signedness).
- Rejected: narrowing or equal-width without proof, cross-signedness, float/pointer casts; messages point at `match x fits T`, `wrap:<T>(x)`, `sat:<T>(x)`. Mutability change is the `mut`/`imut` prefix operator (`checkMutabilityOf`), not `as`.
- The right side is read off its token (a bare type name is not a declared variable). `resolveCastTargetBare` is lighter than `resolveTypeAnnotation` (no pointer validation); for aliases it prepends a synthetic `imut` if the expansion has no mutability modifier (needed by `resolveTypeAnnotationRaw`, never read by checkAs).
- A float operand is subject to the float-state gate (`requireProvenFloatState`).

## Proof lookups
Covers: requiresAliveProof, isProvenAlive, isProvenNonzero, isProvenFloatState, requireProvenFloatState, containsPointerAnywhere.
- `requiresAliveProof(t, expr, scope)`: true when the type has real storage, is not `auto` (inherently non-null), not `some`-tagged, and no active proof covers the slot. One shared helper so checkDot's range and struct sites cannot drift.
- `isProvenAlive` collects non-invalidated `alive` patterns for the slot key, reports them to `ProofKills.use`, and marks `refProofIsId` / `refProofKey` on the token for nullable-`ref` subjects. `match x{..}` does not change x's type; it only records the runtime check.
- Float gate: float "access" (the five arithmetic operators, six comparisons, unary minus, `as`) needs a known state: a type-level `floatStates` (any kind, not only finite), `floatLiteral`, an active `float_state` proof (recorded by any case in checkFloatMatch), a literal (also under `mut`/`imut` wrappers and negation; no NaN/Infinity literals exist), or `unsafe`. Passing or returning a float needs no proof.
- `containsPointerAnywhere`: storage directly, or recursively any struct member; terminates because struct cycles are already errors. Used to ban passing/returning pointers across async.

## Member access (`.`)
Covers: checkDot, checkStructMemberVisibility, requireSwapFieldAccessAuthorized.
- `.` is either `EnumName.Variant` (left is a bare name that is not a declared variable but is an enum; a declared local shadows it; a range-valued enum variant yields a literal-bounds `range(start,end)` value) or `instance.member` (left resolved as an expression, chains left-associative). `e.msg` / `e.stack_trace` on a catch parameter are handled first (`activeCatchTries`, stack_trace.md 3.6).
- `X.enum` outside a match condition is an error (checkCaseMatch handles the legal shape before dispatch).
- Range members: only `start` and `end` (type `indeterminate u64`, so checkForLoop's desugared variable can coerce to `mut`); pointer-typed range values still need the alive proof (non-null storage only comes from an annotation such as `raw range(0,5)`).
- Private members: a non-public member is usable only in an impl for that struct or an interface impl on it, or in the declaring file.
- A `swap`-tagged field is only touched through its own `match @lock` (reads and writes). Exempt: `unsafe atomic` and the compiler's own acquire/release (`Token.isCompilerSynthesizedSwapAccess`). Struct-literal construction is a separate path and needs no unsafe.

## Struct literals
Covers: checkInstantiate, checkSwapFieldNotConstructedClosed, isBareEnumVariantRefNode, checkOtcLockViolation.
- One true constructor (OTC): every member exactly once, no unknown member. A struct that declares constructors may only be built with a bare literal inside its own constructor bodies. Result mutability is `indeterminate`.
- Lock-field exception: a lock-field struct may omit every other member only when the literal provides exactly the lock field, it is declared `imut`, and its value is a raw bare `EnumName.Variant` that is a real variant NOT satisfying the lock (`lockVariants`); the other members are then unreadable anyway (`isLockViolationConstruct`).
- Swap field: the `mut` swap field cannot use the omission sugar; a literal `EnumName.CLOSED` value is rejected (a fresh mutex is never handed out held); non-literal values pass unchecked. `isBareEnumVariantRefNode` checks the raw expression because a variable of the same enum type resolves identically.

## Swap and atomic
Covers: checkAtomicWrapper, checkSwapOperator, isSwapRhsAllowedShape.
- `atomic x` tags a plain no-storage scalar (integer, bool, char) as atomic; mutability is preserved.
- `a swap b`: left must be a bare reference or `.` chain naming a concretely `mut` atomic value; yields a plain `indeterminate` snapshot of the old value; dedicated `ATOMIC_SWAP` (cannot be decomposed atomically). A bare `EnumName.Variant` right side is accepted despite being `imut` (same exception as swap-field construction).
- Right side must be a literal (number, string, char, bool, null, negative number), bare enum variant or bare variable. This is a syntax-honesty rule, not a soundness guarantee: computation sits on its own line so the syntax never suggests a non-atomic read-and-compute is part of the atomic write. Checked on the raw tree before type resolution.

## Storage constructors and new
Covers: checkNew, checkNewInner.
- Storage operators `owns x`/`ref x`/`auto x`/`raw x`/`static x` (also `auto(x)`): `auto` needs an addressable lvalue (variable or dot chain, not a temporary); `raw` is unrestricted; `static` applies only to string/char literals (the original text says owns/ref were always errors because no heap existed; that is superseded by `new`/`dyn`).
- `new T{..}` yields `owns some T` with the operand's own mutability. Operand must construct a value (struct/array literal, enum variant, primitive literal, constructor call); a bare variable or member chain is rejected. It always counts as throwing: must be covered by `insideThrowingAllocContext` (set by `checkTry` for the whole descent because a nested `new` cannot be given its own try); sets `usesThrow` and `usesOwnsRefDynNew`; the containing function needs `@throws` only if a catch re-throws. No `destructOnExit` is needed since the catch is local.
- A struct-RVO call (constructor or struct-returning function) is a legal `new` operand: `insideStructRvoDestinationPosition` is set, the CALL is marked `coveredByThrowingNew`, and BytecodeEmitter copies a hidden stack temp through the ordinary NEW/GT_REGISTER sequence.

## Async: await, par, handles
Covers: checkAwait, prepareAsyncCallSite, findTopLevelAsyncFuncInfo, ensureAsyncStateEnum, ensureAsyncGateEnum, getOrCreateAsyncHandleType.
- `await f(args)` must directly wrap a CALL, be in try/`?`, blocks and yields the callee return type; the CALL is marked `asyncCallKind="AWAIT"` so checkCall enforces the `@async` requirement (both directions) in one place; an await kills alive proofs (`ProofKills`).
- `prepareAsyncCallSite` finds the top-level `@async` FuncInfo (methods unsupported: no function-pointer value of a method), gets the handle type, records `asyncHandleStructName`/`asyncHandleCanonicalType`/`asyncTrampolineName`, synthesizes the memoized trampoline (`__trampoline_<f>`, `__par_fire_and_forget` for a void hidden handle reached by `par`, `__par_locked` for a value-returning `par` handle) and, for locked handles, the drop hook. A void hidden handle via `par` needs the self-destructing trampoline because the thread may still read it; void via `await` joins first and shares the ordinary trampoline. Sets `usesOwnsRefDynNew` (GT_INIT must run).
- `AsyncState` enum (PENDING, RUNNING, READY, `isNonExhaustive` so `default:` works) and `AsyncGate` (OPEN, CLOSED) are synthesized as EnumInfo plus a root token on `rootLinesRef` (`appendSynthesizedRootToken`), no import needed.
- Handle struct: name `AsyncHandle<hex hash of key>`; members `gate` (locked only; lock field, swap field, lockVariants OPEN), `state` (non-hidden), `value` (the parameter's exact type, `mut u64` for none), `threadId` (u64), `result` (non-hidden); returned as `owns some` (indeterminate) so `.state`/`:resolve()` need no match. `resolve()` returns `_self.result` (public; `@lock` on `gate` OPEN for locked handles). Key: `(result|void)|(param|none)[|par]`; hidden or `await` handles are plain structs.

## Compiler-generated enums and interface dispatchers
Covers: generateClassHierarchyEnums, generateEnumForEnums, registerEnumForEnum, generateInterfaceDispatchers, generateOneInterfaceDispatcher, buildDefaultLiteralFor, mutabilityWrap, interfaceDispatcherName.
- `Class`: one u64 variant per non-`@untyped` struct in declaration order (0..n-1); `StructInfo.classId` is set; no eligible struct = no enum; the name `Class` is reserved.
- `$enum_for_<Interface>`: variants are the implementing structs (values = Class ids); reached through `Owner.enum` only.
- Dispatcher `__iface_dispatch__<I>__<m>(p0..)`: body `match Some(p_self){ match p_self implements I.enum{ Impl:{ [return] p_self.m(p0, ..) } .. } }` plus `[return <default literal>]` for non-void, parameter types with `self` replaced by the interface name. `p_self` is the parameter whose declared type was `self`, so callers pass the receiver explicitly (`c.foo(c)`). Built as raw Token nodes (no resolvedType; the normal checkFunctionBody does the work).
- Skipped (checkMethodCall then reports a clear error): static methods, `@lock` methods (the synthesized call would need a lock proof), methods without a `self`-typed parameter, return types with no default literal (non-void: non-`some` pointer -> `null`, bool, integers, floats; wrapped in `mut`/`imut`). Whole pass skipped unless some function is `@gt_alive_check` (generated `match Some` emits GT_ALIVE_CHECK and would force the ghost-table stdlib on every program).

## Describing literal types
Covers: describeTypes, fittingTypes. "no overload matches" messages print an integer literal as `integer literal N (fits only u8, s16, ..)`.

## par / await and trampolines

Covers: `checkPar`, `checkParInner`, `synthesizeAsyncTrampoline`, `synthesizeAsyncDropHook`, `findCallNodeByCalleeName`, `markSynthesizedUnsafe`.

- `par f(..)` must directly wrap a call. For a void-returning `@async` function the `par` expression has type `void` (usable as a bare statement, no handle). For a value-returning one it has type `owns some AsyncHandle_<T>` (see `getOrCreateAsyncHandleType`).
- After the ordinary call dispatch, `op.left.resolvedType` (read by BytecodeEmitter for its PUSH_RET line) is overwritten with the `par` operator's own result type; the callee's real return type T was only needed to determine the handle type.
- `par` must be inside `try`/`?` (it can fail: handle allocation or thread start) and is banned in `@pure` functions; it ends alive proofs (`ProofKills`).
- Trampoline: `func __trampoline_<name>(argPtr: raw mut u8) raw mut u8` (pthread's `void*(void*)` shape). It unpacks the packed argument from the handle, calls the real `@async` function, writes result/state back (skipped for void functions: no `result`/`state` fields), returns `null`.
  - Built as real Caspien source text and run through Lexer/Parser/RpnConverter/TreeBuilder (not hand-assembled Token by Token like the trivial `getOrCreateAsyncHandleType` body), because the body is non-trivial (an `unsafe` block, typed `let`, `memcopy`, conditional member reads/writes). The snippet's Lexer gets the real `@async` function's declaring file, so the private-function file-visibility check never rejects the trampoline's call into it.
  - The one direct call into the `@async` function would normally be rejected ("can only be called through 'par' or 'await'"); `findCallNodeByCalleeName` finds that single CALL node and marks it `isTrampolineOwnCall` (a deliberate, narrow bypass).
  - Registration and body-checking happen eagerly inside the synthesis (`checkFunctionBody`), not via `check()`'s sweep: that sweep's worklist (`flattenRootLines`) is snapshotted up front, so a plain function added mid-sweep would never be visited.
  - The handle pointer is recovered from `argPtr` when the real function takes a packed argument, writes a result, or the trampoline self-destructs the handle. Two-step reinterpret: a plain `raw mut <Handle>` local initialised `null`, filled by `memcopy(raw handlePlain, mut 8, raw argPtr)`, then a `raw some mut` local bound from it (`null` cannot satisfy a `some` bound, so the `some` tag is applied only once a real value exists; no `match Some` proof, hence no `@gt_alive_check` dependency for every par/await program).
  - Locked handle with result: `let realResult = mut f(..)`, then `match @lock handlePtr{ OPEN:{ result = ..; state = AsyncState.READY } CLOSED:{ continue } }`, so result and state are published together; a reader holds the lock only briefly, so the unbounded retry is acceptable in compiler-written code. Unlocked: plain stores.
  - `selfDestructHidden` (fire-and-forget `par` of a void function): nobody else destructs the hidden handle, so the thread does it after the real function returns: `memcopy` the handle pointer into a `raw mut u8` and call `gt_destruct`. A function decorated `@gt_destruct` must exist (compile error otherwise). The memcopy is needed because `gt_destruct` takes `raw imut u8` and an ordinary Caspien-level call needs an exact base-type match (bytecode `GT_DESTRUCT` elsewhere bypasses this).
  - `synthesizingGlueBody` is true while a trampoline or drop hook is checked: trusted glue may touch a locked handle's members outside `match @lock` and retry the lock without a bound.
- Drop hook `@drop func __join_<Handle>(r: ref some mut <Handle>)`: joins the handle's thread (`pthread_join(tid, null)` when `threadId != 0`; 0 = never started) so the handle's memory never goes away under a running thread. Source text, trusted glue, `unsafe extern` block.
- `markSynthesizedUnsafe` sets `synthesizedUnsafe` on every `unsafe` node of compiler-written code, exempting it from the unsafe-tag rules.

## Address-of operators

Covers: `checkAddressOf`, `isAddressableLvalue`, `isReadableValueChain`, `checkMutabilityOf`.

- `raw`: only in unsafe code; the operand must be an addressable lvalue (a variable or a `.` chain rooted in one, parens transparent) or a string literal. A bare number/char/computed value has no memory location (same restriction as `auto`); a string literal is already static storage, so it is the one exception.
- `owns` prefix is rejected (use `new`). `ref` only from an existing `owns`-typed value (already heap-resident). `static` only of a string/char literal or a `let static`/global; `static` of a struct-typed variable is rejected (reached by its own name, under `match @lock` for swap-lock statics). `auto` needs an addressable lvalue, may not point at a static/global (shared memory, would escape its lock), and may not be applied to a variable that is itself a pointer (use the pointer, or `ref`).
- The result of `raw x`/`ref x`/`auto x`/`static x` is a fresh value: indeterminate mutability, needing `mut`/`imut` before binding with `let` (otherwise a pointer variable could never be `mut`, blocking reassignment and `++`). `ref x` of a nullable owner sets `refToId` (a nullable `ref` is an id, not an address).
- `isReadableValueChain` is a strict superset of `isAddressableLvalue`: it also accepts LOOKUP anywhere in a `.`/LOOKUP chain (`self.arr[i]`, `m[i][j]`, `arr[i][j].f`, `arr[i].f`). `isAddressableLvalue` asks "can a static address be computed" (ADDR_OF supports only statically-known offsets); this asks "is it a read of an existing value, not a fresh one". Used only by `checkReturn`'s struct-RVO restriction. Struct-sized element reads were already supported by `emitLookup`.
- Mutability lattice, prefix `mut`/`imut` (`let i = mut 0`): indeterminate coerces to mut or imut, mut to imut; never to indeterminate, and imut never to mut. So the prefix only rejects imut -> mut.

## Ranges and membership operators

Covers: `checkRange`, `rangeBoundDescriptor`, `checkIn`, `checkGuaranteedEnumMembership`, `checkWithin`, `wrapFixedArrayAsRange`, array/range type helpers.

- `a..b` has base type `range(<left>,<right>)`, bounds embedded in the type string. Operands must be plain `u64` and each a bare integer literal or bare variable (not a computed expression). Literal bound = its numeral (`12`); variable bound = `<mutability>_<name>` (e.g. `imut_my_start`, embeds the variable's name). Result mutability `imut`, so the canonical form is `imut_range(imut_my_start,imut_my_end)`.
- `in` accepts: u64 or range on the left; range or dynarray on the right; a fixed array on the right (rewritten to `range(arr)` by `wrapFixedArrayAsRange`, same bounds-proof key since `boundsTargetSlotOf` unwraps `range(X)`); a `string` on the right (left must be plain u64; runtime byte scan up to the NUL, `op.isStringMembershipCheck`, emitted as `IN_SCAN`); a bare guaranteed-enum name on the right (checked first). Result `indeterminate bool`. An `unsafe dynarray` on the right is rejected with its own message (no length to bound against). `in` compiles to the `IN` opcode.
- `u64 in EnumName`: true iff the u64 equals some variant's explicit discriminant. The enum must be guaranteed (`EnumInfo.explicitValues != null`: every variant has an explicit value, no partial mixing, enforced at `flattenEnum`); otherwise a dedicated error. `op.right` is not resolved as an expression; `op.right.resolvedType` is set to the enum name (the marker for `BytecodeEmitter`, with `Token.isGuaranteedEnumMembershipCheck`, and the literal operand pushed).
- `within`: same shape as `in` but range on both sides (no u64, no dynarray). Runtime meaning: the left range's bounds are inside the right's, excluding identical bounds (`1..2` within `0..3` is true, `0..3` within `0..3` is not). Compiles to `WITHIN`, never `IN`.
- Array base types are `elem[len]`, nestable (`u64[5][10]`); the length is part of the type, so `sameBaseType`/`typesCompatible` need no extra logic. `isStructByValueReturn`: storage-less struct (the RVO shape).

## Integer and float literal adaptation

Covers: `unifyLiteralOperands`, `retagLiteralArgs`, `orderByLiteralExactness`, `integerBounds`, `literalFits`, `literalAdapts`, `arrayLiteralAdapts`, `floatArrayLiteralAdapts`, `adaptLiteral`, `acceptsAdaptingLiteral`.

- An integer literal (or negated literal) satisfies any plain integer slot whose type holds its value, with a mutability its own satisfies; the slot decides the width. The caller must follow a successful match with `adaptLiteral` on the literal's expression.
- In a binary operator a literal on one side adapts to the other side's concrete integer type when it fits (`a + 1`, `a: u8`); operand mutability is ignored for arithmetic.
- Overloads: a candidate that fits with no literal adapting is preferred over one needing adaptation (`f(5)` picks `f(u64)` over `f(u8)`); stable otherwise.
- `adaptLiteral` retags through `mut`/`imut` wrappers, grouping parens, one unary minus (the NEG operand gets the same-width UNSIGNED type; a float operand the float type), all-literal float `+ - * /` trees, and array literals one dimension at a time (`u32[3][2]` -> `u32[3]`). A no-op unless the literal flag was set.
- An all-integer-literal array literal satisfies a same-dimension `T[n]` slot (T plain integer) when every element fits; likewise float array literals for `f32/f64[n]..`.

## Nullable ref conversions

Covers: `markRefConversion`.

A nullable `ref` is a 64-bit id; `ref some`, proven bindings and `owns` are addresses. An address-valued expression accepted by a nullable `ref` slot gets `refToId` (emitter: GT_REF_ID); a nullable `ref` accepted by a `raw` slot gets `refToRaw` (GT_REF_RESOLVE, null when dead). Called only for the finally chosen parameter/target, never for a rejected overload candidate.

## Type compatibility

Covers: `typesCompatible`, `argSatisfiesParam`, `mutabilityCompatible`, `storageCompatible`.

Directional: can `actual` be used where `expected` is required (assignment, return, argument, struct-literal member).
- `null` satisfies any pointer slot except a `some` one.
- A complete `range(a,b)` satisfies a bare `range` slot by value and by pointer, not the reverse (a bare range's bounds are unknown).
- A struct satisfies an interface-typed slot it implements (`structImplementsInterface`); not the reverse (needs a dispatch mechanism).
- Otherwise base types must match; a function-pointer actual must carry every decorator the expected one requires (decorators are not part of the signature string); `aliasName` must agree (nominal: `u8` and an alias of it do not satisfy each other).
- Non-pointer expected: storage plays no role. Pointer expected: actual must be a pointer (no implicit address-of); `some` coerces to non-`some`, not the reverse; storages must be exact, or anything -> `raw`, or `owns` -> `ref` (`storageCompatible`).
- Mutability: indeterminate -> mut/imut, mut -> imut; never into indeterminate, never imut -> mut. A Java-null mutability only occurs for the `null` literal type (already handled), so it is a defensive no-op.
- `argSatisfiesParam` (call arguments): extends `typesCompatible` so a `some` parameter (e.g. `ref some self`) also accepts a not-`some` argument that `isProvenAlive` via `match Some`; same idea as `checkReturn`'s rule for `some` return types. Without it no hand-written code could satisfy a `some` self. A null `argExpr` (synthesized argument) falls back to plain `typesCompatible`.

## Raw pointer arithmetic helpers

Covers: `pointerResultType`, `isRawPointerType`, `pointeeSize`, `pointeeStructName`, `requireEightByteInteger`.

`ptr +/- n` has the same raw pointer type with indeterminate mutability. Pointee size: `raw u64` 8, `raw u8` 1, `raw Struct` its size (symbolic `SIZEOF name` via `Token.pointerScaleStruct`), pointer-to-pointer 8, `void`/unknown 1 (as GNU C). The integer side must be `u64` or `s64` (narrower needs `as u64`).
