# CLAUDE.md -- LowerOrderGenerator (stage 3 of the Caspien toolchain)

Current state only. Root `CLAUDE.md` has cross-stage context.

## What it does
Input: the Optimizer's plain-text higher-order bytecode (HOB: type-annotated, named variables, `ARG`/`ALLOC`/`SIZEOF`-free). Output: low-order bytecode (LOB) for `Codegen`: types erased to byte sizes, names to frame offsets (`$off`) or globals (`&sym`), stack-machine mnemonics, optionally rewritten to "register form" (`R_*` lines). Package `caspien.lowerorder`, no code shared with other stages (own parser copies, which must stay identical across stages).
Run: `lowerordergenerator -i in.txt out.txt`. Needs `compiler.config` in the CWD (hard-required, fixed path; a copy sits in this folder): calling conventions + switches. It does not parse other stages' config keys (they are skipped by name in `CompilerConfig`; a new Optimizer/ASTGenerator key must be added to that skip list).

## Pipeline (`LowerOrderGenerator.generate`, fixed order, once each)
1. `MembershipLoweringPass`: `IN`/`WITHIN`/`INSTANCEOF`/`IMPLEMENTS` -> compares/loops. A `for` holder (`$for_range_N`) tests only `i < range.end`. Gates must accept both bounded `range(..)` and bare `range` types.
2. `CloneGenerationPass`: ownership-aware `CLONE`: `__clone_T` routines (phase 1 clones every owns leaf into a hidden local, a NULL source leaf stays null (not a failure), a failed clone is null-checked and `GT_REGISTER`ed; phase 2 pushes the fields and `NEW`s; the fail label `GT_DESTRUCT`s the locals and returns null) and a loop for dynarrays of owns pointers (new array filled with null, so a failure destructs it whole) ; inline owns-bearing elements use `__clone_value_T(dst, src)` (two stack words, `X86Backend.emitDropGlueCall` handles the pair; RVO-style store through `$ret_dest`, returns 1/0) and the new array is cut down to the made elements on failure. `CLONE_FILL arr type from` (emitted after a growing `resize`) turns the bitwise fill copies into clones. Flat safe-dynarray clones become `CLONE_DYN elemSize` in `AddressLoweringPass`. The caller (emitter) null-checks and registers the final result.
3. `DropGlueGenerationPass`: `__drop_T` routines; top-level owns-local drop is null-guarded. `GT_DESTRUCT_TAIL arr type startLocal` (shrinking `resize`) becomes the element-drop loop from index `startLocal`. `GT_DROP_ADDR T` (address of an inline owning struct on the stack, emitted before overwriting it through a pointer/index) becomes `CALL __drop_T`. A `GT_DESTRUCT` of a fixed array of owning structs (and a fixed-array struct member in `__drop_T`) is unrolled by `emitFixedArrayElementDrops` (address of each element via `ADDR`/`PUSH i`/`LOOKUP_LHS`, then `CALL __drop_T`). `AddressLoweringPass.resolveAddress` accepts a numeric segment into a fixed array (`x.hs.1.w`), which clone glue uses.
4. `ArgToAllocLoweringPass`: `ARG name type` -> `ALLOC` + load. Frame order: `gt_routine_address`, then `gt_error_message` (rbp-16, `GT_UNWIND MSG` depends on it), then params.
5. `AddressLoweringPass`: biggest pass. Names/types -> offsets/sizes (one frame slot per NAME: a repeated `ALLOC` of a name in a sibling scope reuses the slot when it is at least as big and aligned, else takes a bigger one -- before this a narrower later declaration shrank the slot and the earlier scope's wider stores overran its neighbours). Typed ops become `OP size` (signed compare/div: `SLT_INT` `SGT_INT` `SLT_EQ_INT` `SGT_EQ_INT` `SDIV_INT` `SMOD_INT`; signed right shift `SAR`; `BITS_AND/OR/XOR/NOT`, `SHL`, `SHR`, `TRUNC src dst`, `NEG_FLOAT`). `NEW size m8 m8 p4..` and stack struct-literal `ASSIGN` carry layout tokens (`m<bytes>`/`p<pad>`, `a<elem>x<n>` for narrow-element arrays; `LOOKUP_ARRAY` gets `t8`/`ra`); built by `splitValueUnits`/`layoutFromUnits` (operand-stack simulation; literal also accepted via `$ret_dest` RVO store, and for an `@untyped` struct -- no class-id push -- by `findStructLiteralAssigns`' `untypedAddr` rule; test `untyped_literal_test`). A `@drop` hook (`StructTable.dropHookOf`) is called from the generated `__drop_T` (`DropGlueGenerationPass`) before the members are dropped. `REGVAR name weight [f]` -> `REGHINT off size weight [f]`. `sizeOf` uses a struct name whole if `StructTable` knows it (generic `HashMapEntry_u64`). Never sees `SIZEOF`.
6. `StrengthReductionPass` (always): unsigned size-8 `x / 2^n` -> `SHR`, `x % 2^n` -> `BITS_AND 8`; needs a decimal `PUSH 8 K` right before the op; signed untouched.
7. `RangeCheckFusionPass` (always, stack form): the 14-line constant-bounds `match i in/into arr` test becomes direct unsigned compares on literals (bounds 0..2^31-1; temp slots must be unmentioned elsewhere in the function; `POP $r 16` stores first-pushed word at the lower address).
8. `RangeEndHintPass` (needs deferred-operands + variables-in-registers): splits the hidden 16-byte `for` range store, hints the end word.
9. `RangeWordSplitPass` (deferred-operands): 16-byte range constructions/copies -> two 8-byte moves + hints.
10. `RegisterFormPass` (deferred-operands): operand-stack model -> `R_*` lines (below).
10b. `LoopHoistPass.run` (`hoist-array-bases: on`, needs deferred + variables-in-registers; between RegisterFormPass and RegVarPromotionPass): per natural single-entry loop, a frame slot `$S` that is only READ inside the loop (`R_MOV 8 %t $S` starting a pointer access: followed by `R_LD 8 %t %t` or `R_LEA %t %t ..`; at least 2 such starts), never the target of any store/`ADDR`/unknown access overlapping its 8 bytes in the loop (`writeWidth`: an unknown mention at offset T counts as a store to everything at or above T) and not `ADDR_OF`/`R_ARGA`-exposed anywhere in the function (an exposure at T within 4 KiB below S counts) gets a hidden copy slot `$X` (appended below the frame: `ALLOC` +8 each, rounded to 16) filled before the loop header (`R_MOV 8 $X $S`), the in-loop reads point at `$X`, and a `REGHINT $X 8 weight` makes RegVarPromotionPass decide whether it gets a register (its usual rules). Outermost loops first. `LoopHoistPass.finish` (after RegVarPromotionPass, same instance) undoes every copy that stayed in memory (reads back to `$S`, copy line gone) and restores the frame size, then drops `R_MOV 8 %tA %vK` into `R_LD n %tA %tA` / `R_LEA %tA %tA ..` (-> `R_LD n %tA %vK` / `R_LEA %tA %vK ..`). Loops with calls are fine (a non-address-taken slot cannot change under a call; volatile r8-r10 are only given out by the promotion pass to call-free live ranges). Tests: `loop_hoist_test` (+ `.py` model, `loop_hoist_check.sh`), `loop_hoist_passes_check.sh` (hand-made LOB). Not done: struct-member dynarrays (`d.backing`) and copy forwarding through hidden inline slots (measured: little to gain, see root CLAUDE.md); the length word is handled by the fused memory compare (16.).
11. `RegVarPromotionPass` (always runs; strips `REGHINT`/`REGVAR`; promotes only with both switches): renames hinted slots to `%v`/`%x` registers.
    - Also promotes int slots filled by a call result (`PUSH_RET_INT` ... `ADDR..ASSIGN` pairs -> `R_GETRET`/`R_POPV`). `RegisterFormPass` has `fuseDivConst` (`DIV_INT`/`MOD_INT` n = 1/2/4/8 by a literal -> `R_DIVC DIV|MOD n`, the narrow forms zero-extend the dividend in `rfDivConst`; test `div_narrow_test`, unsigned reciprocal multiply, Codegen `rfDivConst`) and `fuseLookupDyn` scalar-field fusion for struct dynarray elements; `FloatIntrinsicPass` turns a libm `sqrt` call into `R_FSQRT` (sqrtsd).
12. `FloatTempPass` (float-temporaries-in-registers): float temp chains to `%y0..%y3`.
13. `BranchFusionPass` (always, no-op without register form): `R_BIN cmp 8` + `R_BRF` -> `R_BRC C 8 a b @L` (jump when NOT(a C b)); size 1/2/4 compares fuse too (`R_BRC C 1|2|4`: compares the low bytes; only when neither operand is a `$` frame slot or immediate, so the backend can use a sized register compare); `&&` of two compares -> two `R_BRC`.
14. `JumpCleanupPass` (always; up to 8 rounds): dead jump after jump, jump to next label, `R_BRC C ..@L1; JMP @L2; @L1:` -> inverse `R_BRC`. In stack form a `JMP` right after bare `CMP` is the conditional jump (never treat as unconditional, `followsCmp`). Labels never deleted.
15. `IndexedAccessPass` (always): `R_LEA %tX base %vK scale` (base = `&global`, `$frameSlot`, or a `%t`/`%v` register holding a pointer; scale 1/2/4/8, or ANY other stride (a struct element: 24, 56 ...) with a register or frame-slot base (never a global): the backend multiplies the index into `%r15`, `imulq $stride, %idx, %r15`, then `disp(%base,%r15,1)`; AoS nbody -19% executed instructions) + later `R_LD/R_ST` (or float `R_LDX/R_STX`) -> `R_LDI/R_STI` (int: access width == scale) / `R_LDXI/R_STXI` (float: scale = width 4 or 8; for a non-hardware stride the width is independent of the stride, and an integer width is 1/2/4/8). Neither the index nor a register base may be written between LEA and consumer; the lea temp must be dead after it. `MAX_GAP` 40; an `R_LEA` with a 6th token (displacement, e.g. the 16-byte safe dynarray header) is fused too: the displacement becomes the last token of `R_LDI/R_STI/R_LDXI/R_STXI`. Tests: `indexed_narrow_test`, `indexed_bases_test`.

16. `LengthCompareFusionPass` (`fuse-length-compare`, needs deferred): the safe-dynarray bounds check `R_LD 8 %tL %tB ; R_BRC C 8 %vI %tL @L` (the array length word) becomes one `R_BRCM C 8 %vI|$slot [%tB] @L` memory compare (form 2 also reuses the loaded base pointer for the element access); `deadAtTarget` guards the temps. Tests `length_fuse_test` (+ `_check.sh`, `length_fuse_passes_check.sh`).
17. `FieldDisplacementPass` (always, last): `R_LEA %t base #k scale [d]` (register base, immediate index; any positive scale, displacement k*scale+d) + `R_LD/R_ST/R_LDX/R_STX` -> `R_LDD n %tD base disp`, `R_STD n base disp src`, `R_LDXD`, `R_STXD` (widths 1/2/4/8, floats 4/8; base not written in between, lea temp dead after). Test `field_disp_test` (+ `_check.sh`).
18. `StaticFloatCachePass` (after FloatIntrinsic, before BranchFusion; needs `float-variables-in-registers`): read-only `f32/f64` statics read in a call-free loop are loaded once before it into `%z0..%z3` (xmm0-3, SysV only); a static the loop writes is never cached. `GlobalConstAddrPass` (after IndexedAccess): `R_LEA %t &W #k s` + `R_LD/R_ST/R_LDX/R_STX` -> access to `&W+N`. `DestForwardingPass` (last of all): `op -> %t; R_MOV 8 %v %t` writes `%v` directly; dead `R_MOV 8 %v <src>` removed when overwritten before read. Tests `static_cache_test`, `global_const_addr_test`, `dest_forward_test` (+ `_check.sh`, `*_passes_check.sh`). `ConditionalMovePass` (switch `conditional-move`, shipped off; one-arm / two-arm select of a register variable between registers or constants -> `R_CMOV C n a b %vK X [Y]` = `%vK = (a C b) ? X : Y`, Codegen `rfCmov`: cmp, `mov Y` (flags untouched), `cmovCC X`; sources never read memory; two arms only when their labels are used once; measured neutral: strings -3%, sorting +2% (data-dependent selects; candidate for `benchmarks/specific.json`), FULL has it on so the sweeps cover it; test `cmov_select_test`, generator `gen_cmov_select.py`) and `CopyForwardPass` (after DestForwarding, switch `copy-forward`; `R_MOV 8 %tX %vY` (Y in 0..5) whose temp is only READ in value positions (R_MOV/R_SETV source, R_BIN a/b for add/sub/mul/and/or/xor/shifts, R_ST/R_STD/R_STI source, R_LD/R_LDD/R_ST/R_STD address base, R_LEA base) before a redefinition / label / JMP, with no write to %vY and no call/branch in a 14-line window, has its reads replaced by %vY and the copy deleted; `R_MOV 8 %vK %vK` deleted; executed instructions -0..-6.5% (binarytrees, lru, knucleotide, sorting); test `copy_forward_test`, generator `gen_copy_forward.py`) run before `LoopRotationPass` (after DestForwarding, switch `loop-rotation`, shipped off, FULL on): a back-edge `JMP @H` to a header of up to 3 pure temp-writing lines + `R_BRC/R_BRCM` is replaced by copies of those lines + the inverted branch to a new label `@loop_rot_N` placed after the original header branch (one jump per iteration instead of two); only when the header's exit label follows. Test `loop_rotation_test` (generator `gen_loop_rotation.py`, Python models).

## Config switches (compiler.config top level, `on|off`, anything else is an error)
`deferred-operands` (default off in code; needs nothing), `variables-in-registers` (needs deferred), `float-variables-in-registers` (needs variables), `float-temporaries-in-registers` (needs deferred), `variables-in-alloc-functions` (needs variables), `variables-in-arg-registers` (needs variables; `%v6..%v9` = rsi, rdi, rdx, rcx, 4th `RegVarPromotionPass` constructor argument; only call-free ranges with no `ARGk`/`R_ARG*`/string/memcopy use of those registers inside, `Hint.argSafe`; test `arg_regs_passes_check.sh`), `fuse-length-compare` (needs deferred), `hoist-array-bases` (needs variables; both are also keys in the ASTGenerator's `CompilerConfig`, `CompilerCache.REG_KEYS`). Shipped `toolchain.config`: deferred on, variables on, float vars off, float temps off. With a switch off the output of that stage is byte-identical to not having it.

## Register-form essentials
- Model entries: K const, M frame-slot value (size 1/2/4/8), A address (`$off`/`&sym`), T temp (zero-extended, with value width). Operand syntax: `#imm`, `$off`, `&sym`, `%tN`.
- Temps `%t0..%t3` = rax, rbx, r11, r12. `r15` = backend scratch (`%s`). `%v0..%v9` = r13, r14, r12, r8, r9, r10, rsi, rdi, rdx, rcx (`RF_VAR_REGS`; the last four only with `variables-in-arg-registers`; rdx/rcx only in ranges without divides/variable shifts/`R_DIVC` etc.: `Hint.rdxOk/rcxOk`). Float: variables `%x0..%x5` (SysV xmm8-13, win64 xmm6-11), temps `%y0..%y3`, scratch xmm14/15 (win64 xmm4/5).
- r12 is both `%t3` and `%v2`: `%v2` only in functions without `%t3` and without `R13_R14_USERS` mnemonics (NEW*, CLONE, RESIZE*, DOT, LOOKUP_ARRAY, ASM_*). Such "blocked" functions get no r12-r14 variables but may use r8-r10, unless `variables-in-alloc-functions: on` (3rd constructor argument of `RegVarPromotionPass`): then they may use r12-r14 too and Codegen saves/restores the used ones around the scratch-using instructions (see Codegen/CLAUDE.md). Inline assembly still blocks. Tests `alloc_vars_test` (+ `.py`, `alloc_vars_check.sh`), `alloc_vars_passes_check.sh`.
- r8/r9/r10 are caller-saved: usable only for variables never live across a line whose mnemonic is outside `VOL_SAFE`; `ARGk` k>=2 bans r8/r9, `PUSH_RET_FLOAT`/`R_GETRETF` ban r10. Only on the over-subscribed (sharing) path.
- Line set: `R_MOV R_LD R_ST R_LEA(5 or 6 tokens, 6th=disp) R_BIN(ADD SUB MUL AND OR EQ.. BAND BOR BXOR SHL SHR SAR) R_UN(INC DEC NEG NOT BNOT) R_FBIN R_FCMP R_RMW R_ARG R_ARGA R_FARG R_RET R_RETF R_BRF R_BRC R_PUSH R_PUSHA R_SETV R_LDI R_STI R_LDXI R_STXI R_XVAR R_XTOG R_GTOX R_LDX R_STX R_POPX R_GETRETF R_FBINX R_XMOV R_XRELOAD R_XSPILL`.
- Fused handlers include: global scalar reads (`R_LD n %t &sym`, eager; declined if no free temp or `ATOMIC_SWAP` at +2), `LEN`, `LOOKUP_DYN(_LHS)` (value form only for element size 1/2/4/8, declined if next line starts with `LOOKUP`/`DOT`), `ZEXT`/`TRUNC`, `SHL/SHR/SAR/BITS_*` with variable counts, `x += c` (`R_RMW`).
- Invariants/gotchas:
  - Handlers must emit NOTHING before returning 0 (decline). Unknown mnemonics flush the model.
  - "Risky" regions (anything beyond plain 8-byte ints) roll back to original lines on an unfusable instruction with entries remembered, EXCEPT a faithful flush (`flushIsFaithful`: `CC_START`, mnemonics ending `_FLOAT`/`_INT`, bitwise family, with `plainWords()`).
  - Flushes under a live temp must use `R_PUSH`/`R_PUSHA` (original `PUSH` lines clobber rax/rbx). `findRunStart` in Codegen only knows PUSH/ATOMIC_PUSH/STACK_LOCK/nested NEW as construction-run members.
  - Narrow `R_BIN` results are NOT masked; only loads are zero-extended (`Entry.zx`); a relabel is legal only for a `zx` temp. Variable registers hold values zero-extended to 64 bits.
  - A new `R_*` instruction must be added to `RegVarPromotionPass.mentionOk`/`mentionOkX`/`VALUE_OPS` (default = ban: slot stays in memory), `FloatTempPass.consumerOk`/`KNOWN_R`, `JumpCleanupPass`/`IndexedAccessPass` `DEST`/`PURE_DEF` tables, and, for sharing, the def rules (defs are only `R_ST` op2, `R_MOV` to slot, float `ADDR..ASSIGN` pair). A mnemonic that writes a slot but is not a def makes register sharing unsound.
  - Register sharing (`shareRegisters`/`colour`) runs only when candidates exceed registers; backward liveness; call-like lines have edges to every label referenced by a non-jump line (catch pads); `NO_FALLTHROUGH` = RET RET_FLOAT R_RET R_RETF GT_UNWIND EXIT EXIT_THREAD FUNC_END. One `R_XVAR` per float register; `@catch_` labels get `R_XRELOAD`.

## Build and test
Build (from this folder): `javac -d out $(find src/main/java -name '*.java')`. Root `Compiler` runs all four stages (`java Compiler -i x.caspien outname`); never compile two programs at once in one tree.
Hand-made LOB check scripts live in `/home/claude/caspien/tests/`, run from the project root, need `LowerOrderGenerator/out` built, env `LOB_CP=<classpath>` runs against a mutant build: `lob_passes_check.sh` (JumpCleanup/IndexedAccess), `rangecheck_check.sh`, `regform_globals_check.sh`, `regform_dyn_check.sh`, `regvars_share_check.sh`, `regvars_volatile_check.sh` (also RangeEndHint), `floatindex_check.sh`. Runtime tests are `tests/*.caspien` (PASS/FAIL lines; compare output across configs: everything on, shipped, register-form only, everything off), e.g. `regform*_test`, `regvars_*_test`, `floattemps_test`, `range_split_test`, `bits_ops*_test`. `tests/callee_saved_probe.sh` checks callee-saved preservation (Linux, gcc).

## Known open gaps
- There are no Intel/MASM forms any more (the target was removed); windows_gnu is run under Wine.
- Stack-form residues: more than 4 live temps falls back, narrow M flush rolls back; loop `within` test is a full strict-subrange check; a few `POP` lines remain unfused (4 in stdlib_test).
- Loop range START is not promoted: measured (hand-patched asm), slower, not worth it.
- `FloatTempPass.coalesceIntoVariables`: a run `%y = a op b; %y = %y op c; ...; %xD = %y op d` is rewritten to write `%xD` directly (the producer may read `%xD` as its first operand; a commutative `%y = %y op %xD` is flipped to `%xD = %xD op %y`; the producer must not read `%y`; `%y` must be dead after). `BranchFusionPass` also fuses `R_FCMP + R_BRF` into `R_BRC op Fn`. `RegisterFormPass.fuseLookupPtrRead`: `LOOKUP_ARRAY n` (two tokens, n = 1/2/4/8) over a pointer base (unsafe dynarray, string) becomes `R_LEA` + `R_LD` (not when the next line is `DOT` or a `LOOKUP_ARRAY ... t8`); `LOOKUP_ARRAY n ; PUSH_FIELDNAME off w ; DOT w` (a scalar field of a struct element of any size n behind a pointer) becomes `R_LEA %t base idx n off ; R_LD w` (test `udyn_field_read_test`). `ROTL`/`ROTR size` (bits_rotl/bits_rotr) lower like `SHL` and become `R_BIN ROTL|ROTR size dst a b` (immediate or register count). Tests `float_direct_check.sh`, `float_branch_check.sh`, `udyn_read_check.sh` (the benchmark sweep only checks PASS lines: compare benchmark outputs old vs new when touching float or lookup code).

- `DropGlueGenerationPass` resolves a `GT_DESTRUCT name` type from `ALLOC` AND `ARG` lines (it runs BEFORE `ArgToAllocLoweringPass`; before 7 Oct a parameter's destruct was a bare free, its owns members/elements leaked). Test `param_drop_test`.
