# CLAUDE.md -- Codegen (stage 4): current state only

Low-order bytecode (text, from LowerOrderGenerator) -> x86-64 assembly text. Config-driven target. All code: `src/main/java/caspien/codegen/X86Backend.java` (~6500 lines); `codegen.config` read from cwd.
Unknown mnemonics are NOT errors: they emit `# TODO(codegen): ...` in the asm (often a silently wrong program). Always grep the generated .s for `TODO(codegen)`, and rebuild `Codegen/out` after editing (a stale class emits TODO for new `R_*` lines).

## Build / run / test
- Build: `cd Codegen && javac -d out $(find src/main/java -name '*.java')`. Standalone: `java -cp out caspien.codegen.Main -i in.lob out.s`.
- Whole toolchain: root `javac Compiler.java`; `java Compiler -i prog.caspien output/prog` (`--asm`, `--lob`, `--hob` stop early; intermediates in `output/.build/`, asm is `4_codegen.s`). Settings come from root `toolchain.config`, copied into every stage; edit only that file. The repo ships `windows_gnu`/`win64`; for Linux set `target linux` (`===codegen.config===`) and `default: sysv_x64` (`===compiler.config===`).
- Tests (root `tests/`): programs `tests/*.caspien` print PASS/FAIL lines; shell checks `tests/*_check.sh`. Callee-saved ABI: `tests/callee_saved_probe.sh` (Linux, needs gcc; sentinels in rbx,r12-r15 survive plain/throwing calls; also runs `tests/check_callee_saved.py <file.s>`, a structural save/restore checker, usable on windows_gnu asm too). Sweeps compare output across configs (everything on, shipped, register-form only, everything off). Compile ONE program at a time per compiler tree (shared scratch files).

## Targets
- `linux`: AT&T, SysV (rdi,rsi,rdx,rcx,r8,r9; xmm0-7; `%al` = xmm count for varargs). The only fully execution-verified target.
- `windows_gnu`: AT&T, win64 ABI (rcx,rdx,r8,r9; 32-byte shadow space), mingw-w64. Executed under Wine 9 (3 Oct, all optimizer configs, 111 programs: output equals Linux). Never name a generated symbol `__main`: the mingw CRT calls it before `main` (the user's main is emitted as `__caspien_main`; `tests/no_crt_main_symbol_check.sh`).
- The MASM/Intel `windows` target was REMOVED on purpose (3 Oct; the owner builds Windows programs with gcc/mingw-w64 and does not want Microsoft-toolchain support). `target windows` is now a config error. All output is GAS AT&T syntax.
- One ABI flag: `isWinAbi()` = win64 ABI (the `windows_gnu` target). Use `argReg(i)` for argument registers, never ad-hoc target tests.

## Execution model
Stack form: bytecode push/pop = real `push`/`pop`; no abstract value stack. Register form (`R_*`, from RegisterFormPass) is layered on top. Struct/array literal construction runs are packed by `precomputeConstructionOffsets`/`assignConstructionBlock`/`emitAssignRepack`/`emitNewRepack` (layout tokens `m<n>` member, `p<n>` padding, `a<elem>x<n>` array, added by LowerOrderGenerator).
Block layout of a >8-byte value on the stack: word k (bytes 8k..8k+7) at rsp+(T-1-k)*8, natural byte order inside a word. All element/field extraction (`LOOKUP_ARRAY`, `DOT`, `extractWordsFromReversedBlock` with `shrd`) depends on it. Odd sizes 3/5/6/7 have no x86 move: `storeOddSize`/`storePiece`/`rotReg`. `lastValueBlockSize`/`pendingBlockSize` pass the block size from a push to the following `DOT`/`LOOKUP` (set by `PUSH`, `DEREF`, `LOOKUP_DYN` value form, pointer-base `LOOKUP_ARRAY`). A `DOT` on a value of at most 8 bytes (tag <= 0: a small struct in one word, e.g. `d[i].a0` of an unsafe dynarray of a 3-byte struct) is a shift + mask (it used to push a placeholder 0). `rfSetIndex` shares the stride multiply `imulq $stride, %idx, %r15` between neighbouring indexed accesses (`strideKeySink/Idx/Scale`, invalidated in `raw()` by any line that is not a whitelisted move/arithmetic whose destination is not r15 or an alias of the index register, by labels, and by call-buffer appends; AoS nbody -5% instructions, `stride_index_check.sh`). A tag survives one 8-byte `PUSH` (the index), not two (`pushedWordWithTag`): `PUSH 4 z; PUSH 8 d; PUSH 8 i; LOOKUP_ARRAY` used to treat the pointer `d` as an in-register small array. Test `small_struct_dot_test` (wrong with all switches off, passes in every config).
Frame: `FUNC_START` pushes rbp; one `ALLOC` per function (rounded to 16). `gt_routine_address` is ALWAYS rbp-8 and `gt_error_message` rbp-16 (in throw programs); parameters follow; the callee-saved save area is added BELOW the locals.
Calls: `emitAlignedCall` keeps rsp 16-aligned at `call`. The alignment slot is reserved BEFORE arguments are pushed (sized for stack-passed bytes, `alignPadFor`: rsp must be 0 mod 16 before `call`); the pre-alignment rsp is saved in a stack slot (`8(%rsp)`), never in a register (callees clobber r13). Stack-passed args: first one at the lowest address (`reverseStackArgWords`); they are discarded after the call. `CC_START`/`CC_END` bracket a call and own an output buffer; nested calls push/pop the enclosing call's already-loaded argument registers (`loadedArgRegsStack`, `noteArgRegLoaded`; xmm0 result stash in r10, `floatResultInR10`). `CALL __drop_*` outside a bracket uses `emitDropGlueCall`.
Variadic: `PROMOTE_F32_TO_F64` (scratch `rfXmmA()`), `VARARGS_XMM_COUNT` sets SysV `%al`, `DUP_TOP` duplicates a float vararg into the int register for win64.
Struct-by-value PARAMETERS are broken (PUSH ARGn takes one register whatever the size); the front end rejects them, so unreachable.

## Register partition
rax/rbx/r11/r12 = temps `%t0..%t3`; r15 = `%s` scratch (`RF_SCRATCH`); r10 = INVOKE target, float-result stash, blocked-function repack; r13/r14 = scratch in `NEW*`, `CLONE`, `RESIZE*`, wide `DOT`, `LOOKUP_ARRAY`, `emitShiftCore` stash. Variable registers `RF_VAR_REGS = {r13,r14,r12,r8,r9,r10,rsi,rdi,rdx,rcx}` = `%v0..%v9` (rsi/rdi/rdx/rcx only given out by the promotion pass under `variables-in-arg-registers`, in call-free ranges; `finishCalleeSaved` also saves them on win64); `%v2`=r12 only if the function never uses `%t3`; r8-r10 are caller-saved (promotion pass only gives them to values not live across any call, and bans r8/r9 when an `ARGk`, k>=2, appears, r10 with a float stash). New 5 Oct: `ROTL`/`ROTR` (stack form and `rfRotate`: `rol/ror` on the sized sub-register, count modulo the width, variable count through `%cl` with rcx saved); `%z0..%z3` = xmm0-3 (static cache, `rfIsXvar`/`xvReg`); `sym+N(%rip)` operands (`globalRipOperand`); `x*2.0` -> add (`rfTimesTwoOperand`); `rfMulByBigConst` (3-operand imul); `rfDivConst` simple unsigned magic path (`divMagicSimple`, old fix-up form as fallback). Invariant: a `%v` or `%t` register holds its value zero-extended to 64 bits. 7 Oct: `R_SETV n<8` from a register is ONE instruction (`movl`/`movzwl`/`movzbl` into the 32-bit destination); `R_BIN BAND 8 d a #0xFF|0xFFFF|0xFFFFFFFF` with a != d is one `movzbl/movzwl/movl`; `rfLea` with a non-power-of-two scale is a 3-operand `imulq $scale, idx, %r15`; stack-form `DIV_INT/MOD_INT` of size <= 4 uses `divl`; `R_CMOV` = `rfCmov` (`rfBrc`/`rfBrcNarrow` with a null label return the false-jump cc, `rfTrueSuffix` turns it into the cmov condition; the immediate moves use `rfMovImmKeepFlags`, never `xor`). A run-time 32-bit-divide fast path for wide `divq` was measured and REJECTED (lru +7%, sorting +12% in paired runs: the operands are mostly above 2^32). Shift guards (`cmp $64/sbb/and`) cost 22% of knucleotide's executed instructions but its counts (`64 - bits`, `2*k`) are run-time values no range analysis proves; no benchmark but knucleotide has one on a hot path, so range-based guard removal was NOT built. The scratch users (`RF_R13_R14_USERS`: NEW*, CLONE*, RESIZE*, DOT, LOOKUP_ARRAY) are bracketed by `@@V1314S@@`/`@@V1314R@@` marks (`emitLine` wrapper); `finishCalleeSaved` turns them into `movq %r13|%r14|%r12, slot` / reload for exactly the registers the function keeps a `%v0..%v2` variable in (`rfVarMask`; extra frame slots appended to the callee-saved area) and deletes them otherwise (text then identical to before). Inline assembly (`ASM_START`) still sets `rfClobberSeen`: `FUNC_END` throws if such a function keeps `%v0..%v2`. Test `alloc_vars_check.sh`.
Float: variable regs `%x0..%x5` (SysV xmm8-13, win64 xmm6-11); temps `%y0..%y3` (SysV xmm4-7, win64 xmm12-15); scratch SysV xmm14/15, win64 xmm4/5. SysV has no callee-saved xmm, so every call spills/reloads all xvars (`xvSpillAll/xvReloadAll`; `R_XRELOAD` after `@catch_` labels, `R_XSPILL` (= xvSpillAll) before a direct jump to one); win64 xmm6-15 are callee-saved.
Callee-saved: `finishCalleeSaved` at `FUNC_END` scans the function text for rbx, r12-r15 (win64 also rdi, rsi, xmm6-15), grows the `ALLOC` by a save area, saves after the prologue, and turns every `@@CSR@@` mark (emitted by `emitFunctionEpilogue` and `GT_UNWIND`) into the restores. r8-r10 need no save. Never use a callee-saved register in generated code without going through this (the text scan handles it automatically).

## Mnemonic groups -> X86Backend `case`s
- Frame/data: `FUNC_START/END`, `ALLOC`, `ALLOC_STATIC`, `GLOBAL` (alias inits folded into the ROOT global's block; a nested member `b.0.x` aliases `b` at an absolute offset, fixed 7 Oct: static arrays of structs / structs holding structs used to be emitted zeroed with stray `b_0_x` symbols; test `static_aggregate_test`; float init as IEEE bits), `STRING`, `STRUCT_PADDING`, labels, `ASM_START/END`.
- Stack form: `PUSH` (slot, literal incl. unsigned >2^63, char, `null`, string id, global, function name via `declaredFunctionNames`, `ARGn`/`FARGn`), `ADDR`, `ASSIGN`, `ATOMIC_PUSH/ASSIGN/SWAP`, `POP`, `DUP_TOP`, `STACK_LOCK`; `*_INT` arithmetic and compares (unsigned), `SDIV_INT/SMOD_INT/SLT*/SGT*` (sign-extend; divisor -1 guarded), `*_FLOAT` (f32 and f64 by size), `FLOAT_CHECK`, `NEG/NEG_FLOAT/INC/DEC*`, `AND/OR/NOT`, `BITS_AND/OR/XOR/NOT`, `SHL/SHR/SAR` (`emitShiftCore`), `SEXT/ZEXT/TRUNC/FCONV`.
- Shift rule (all forms): count is unsigned of its own width; count >= width gives 0 (SAR: sign fill); no hardware masking (`cmp $64; sbb; and` for SHL/SHR, clamp to 63 for SAR; constant counts folded at compile time; rcx saved by push/pop).
- Memory/aggregates: `NEW`, `NEW_DYN/NEW_UDYN/NEW_FROM_STRING`, `RESIZE/URESIZE` (fill is elemSize bytes; wide fill via `emitResizeWideFillCopy`; safe `RESIZE` honours the header's capacity word: fits -> only the length is rewritten (no realloc, ghost table untouched), grows to max(newCount, 2*cap), reallocs down to exactly newCount when under cap/4; `CLONE_DYN` sets the copy's capacity = length), `CLONE`, `DEREF`, `ADDR_OF`, `LEN`, `LOOKUP_ARRAY[_LHS]`, `LOOKUP_DYN[_LHS]`, `DOT[_LHS]`, `PUSH_FIELDNAME`, `MEMCOPY`.
- `MEMCOPY` with a literal size of 1-64 bytes is emitted as unrolled moves (`memcopyConstantSize`); larger or variable sizes call `memcpy`.
- Calls/control: `CALL`, `INVOKE`, `EXTERN`/call, `CC_START/END`, `PUSH_RET_INT/FLOAT`, `RET/RET_FLOAT`, `JMP`, `CMP`, `PUSH_LABEL`, `YIELD` (`sched_yield`), `SLEEP name type` (pop arg, call named `@sleep` function, push result).
- Ghost table / unwinding: `GT_INIT/GT_REGISTER/GT_ALIVE_CHECK/GT_DESTRUCT` call fixed literal symbols `gt_init`, `gt_register`, `gt_alive_check`, `gt_destruct`; `RESIZE/URESIZE` keep the old block start on the stack and call `gt_moved(old)` + `gt_register(new)` if the block moved; unsafe `NEW_UDYN`/`NEW_FROM_USTRING`/`URESIZE` are headerless (pointer = malloc'd block, registered directly via `emitGtCall`, min 1 byte) (front end forces those names); `GT_REGISTER` keeps the pointer on the stack across the call; when `gt_register` returns false (table could not grow) it `free`s the pointer and leaves null in its place (the emitter's null check then takes the OOM path). `GT_DESTRUCT $off` reads a frame slot, `GT_DESTRUCT_ADDR` pops an address and dereferences once. `THROW` is a no-op marker. `GT_UNWIND [MSG]`: epilogue, discard return address, load the CALLER's `-8(%rbp)` and jump; `MSG` first copies this frame's rbp-16 into the caller's rbp-16. `EXIT` = `exit(1)`, `EXIT_THREAD` = `pthread_exit(NULL)`.
- Register form: `R_MOV/BIN/UN/BRF/BRC/PUSH/PUSHA/LD/ST/LEA/RMW/SETV/ARG/ARGA/FARG/RET/RETF`; indexed access (global, frame-slot or register base: `disp(%base,%idx,scale)`) `R_LDI/R_STI` (ints) and `R_LDXI/R_STXI` (floats, scale = width), a stride that is not 1/2/4/8 is allowed for a non-global base (`rfSetIndex`: `imulq $stride, %idx, %r15`, then `disp(%base,%r15,1)`; widths 1/2/4/8 ints, 4/8 floats), each with an optional last token = extra displacement (`R_LDI n %tD base idx scale [disp]`, `R_STI n base idx scale src [disp]`, same for the float forms); displacement forms `R_LDD n %tD base disp`, `R_STD n base disp src`, `R_LDXD n %x base disp`, `R_STXD n base disp %x` (`disp(%base)`, from FieldDisplacementPass); `R_BRCM C n a|$slot [%tB] @L` = compare against the memory word `(%tB)` (safe dynarray length) + inverse jump; float `R_FBIN/FBINX/FCMP/XTOG/GTOX/LDX/STX/POPX/GETRETF/XVAR/XRELOAD/XMOV`. `R_BIN` ops: arithmetic, compares, BAND/BOR/BXOR, SHL/SHR/SAR. `R_BRC` emits cmp + the INVERSE-condition jump (immediate first operand is swapped with the condition mirrored; two slots go via r15). `R_LEA %t base idx scale [disp]` (SAFE dynarray header is 16 bytes: `[len][cap][elems]`; unsafe has none). Narrow loads zero-extend, narrow stores truncate, narrow `R_BIN` ADD/SUB/MUL results are NOT masked in the register. Float immediates come from a read-only pool (`.LFC<k>`, `.rodata`/`.rdata`, zero via `xorps`).

## Known gaps and traps
- windows_gnu runs under Wine (3 Oct); keep it that way (`tests/wine_check.sh`).
- Struct-by-value parameters (above). `PUSH n ARGk` reads the whole register at entry; `argReg(idx)` falls back to `rax` out of range.
- Original `PUSH` lines use rax/rbx as scratch, so a flush under a live temp must use `R_PUSH/R_PUSHA`. Inside a construction run, fields are stored below the current rsp: never `push`, `rep movsb` (rdi/rsi/rcx) or call helpers that touch the stack there (`pushBlockFromFrameConstructionAware` copies via rax).
- `findRunStart` only knows PUSH/ATOMIC_PUSH/STACK_LOCK/nested NEW as construction-run members.
- `rcx` may hold an already-loaded 4th argument (SysV): any code using `%cl` must save/restore it. `%xmm0` is both float arg0 and the float return register.
- Every catch landing (label containing `catch_`) is followed by `RSP_MARK`, which `finishCalleeSaved` turns into `leaq -frame(%rbp), %rsp` (frame = sum of ALLOCs + callee-saved area): an unwind skips the call site's own rsp restore, which used to leak 16-24 bytes per caught throw (`tests/catch_continue_stack_test`).
- `LOOKUP_ARRAY` of a fixed array of exactly 8 bytes carries a `t8` token (arrays under 8 bytes are tagged `ra`); `u32[2]`/`u8[8]` indexing re-checked on 3 Oct, works.
- Scratch hazard: arguments are popped into their ABI registers as soon as each is computed, so any instruction that can run mid-argument-list (`LOOKUP_ARRAY`, `DOT`, repack helpers, `assignConstructionBlock`) must NOT touch rdi/rsi/rdx/rcx/r8/r9 (or xmm arg regs) without saving them. Use r13/r14/r15 (never argument registers) as scratch.
- A void function that falls into `FUNC_END` without a `RET` must still zero `rax` (else `printf`'s return leaks out as the exit code); `FUNC_END` does this, keep it.
- Variadic calls: only true varargs get `PROMOTE_F32_TO_F64` (not the fixed prefix); SysV needs `%al` = float registers used (`VARARGS_XMM_COUNT`, also on the stack-overflow call path); win64 needs a register-passed float vararg duplicated into the integer register (`DUP_TOP`).
- Overlapping block copies (wide `DOT`/`LOOKUP_ARRAY` extraction shrinking a block in place) must copy in the direction that does not overwrite unread source words; the shrink is by whole words.
- Stack-passed arguments: the function reads the first at `16(%rbp)` (+32 shadow on win64); both banks overflow (int past 6/4 registers, float past 8/4) and each stack word is 8 bytes whatever the type.
- `R_BRC C n a b @L` with n = 1/2/4 (`rfBrcNarrow`) emits `cmpb/cmpw/cmpl` on the sized register names (immediates truncated to n bytes) + the inverse jump; n = 8 is the 64-bit form. `R_BIN MUL` by a literal: `rfMulByConst` (2^k `shl`; 3/5/9 `lea`; 2^k+-1 via `r15` copy + shl + add/sub; anything else `imul`). `jcc-padding on|off` (codegen.config, shipped off) is validated here but used by `Compiler.java`, which adds `as -mbranches-within-32B-boundaries` (`gcc -Wa,` on windows_gnu; probed once, ignored with a warning if the assembler lacks it); it pads jmp/jcc only, not call/ret. Tests `narrow_branch_check.sh`, `mul_const_check.sh`, `jcc_padding_check.sh`.
- Globals are one RIP-relative operand (`mov sym(%rip), %r`, `movsd sym(%rip), %xmm`; indexed/address-of globals still `leaq`). `movImmToReg` uses `movl $imm, %r32` for 0..0xFFFFFFFF; `x & 0xFFFFFFFF` is `movl %e, %e`. `R_BRC op F4|F8 a b @L` = float compare (`ucomis*`) + one `j<cc>` (same flags as the setcc form, so NaN behaves as before). Tests `global_access_check.sh`, `const32_check.sh`, `float_branch_check.sh`.
- `avx on|off` (codegen section, shipped off; `CodegenConfig.avx`, `X86Backend.avx`): `R_FBINX` emits VEX 3-operand scalar ops (`vmulsd b, a, d`), no `movaps` copy of the first operand. Executed instructions mandelbrot -20%, nbody -7.8%, spectralnorm -7%, but wall time is NOT better (nbody 0..+5% over 8 code-alignment shifts: the moves were free at rename and the loop is latency-bound), so FULL has it off. Sweep with it on (allon/aggressive, 239 programs) passed 7 Oct. Needs AVX (Sandy Bridge+).
- `bmi2 on|off` (codegen section of `toolchain.config`, shipped off; `CodegenConfig.bmi2`): variable SHL/SHR use `shlx/shrx` + the same `cmp $64; sbb; and` saturation, count in `%r15` (register form) or `%rbx` (stack form), no `%rcx` save/restore. Needs a BMI2 CPU. SAR is unchanged. `benchmarks/nbody/bench.py` `FULL` turns it on. Test `shift_bmi2_check.sh` (both settings vs a Python model).
