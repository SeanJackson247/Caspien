# CLAUDE.md -- Codegen (stage 4): current state only

Low-order bytecode (text, from LowerOrderGenerator) -> x86-64 assembly text. Config-driven target. All code: `src/main/java/caspien/codegen/X86Backend.java` (~6500 lines); `codegen.config` read from cwd.
Unknown mnemonics are NOT errors: they emit `# TODO(codegen): ...` in the asm (often a silently wrong program). Always grep the generated .s for `TODO(codegen)`, and rebuild `Codegen/out` after editing (a stale class emits TODO for new `R_*` lines).

## Build / run / test
- Build: `cd Codegen && javac -d out $(find src/main/java -name '*.java')`. Standalone: `java -cp out caspien.codegen.Main -i in.lob out.s`.
- Whole toolchain: root `javac Compiler.java`; `java Compiler -i prog.caspien output/prog` (`--asm`, `--lob`, `--hob` stop early; intermediates in `output/.build/`, asm is `4_codegen.s`). Settings come from root `toolchain.config`, copied into every stage; edit only that file. The repo ships `windows_gnu`/`win64`; for Linux set `target linux` (`===codegen.config===`) and `default: sysv_x64` (`===compiler.config===`).
- Tests (root `tests/`): programs `tests/*.caspien` print PASS/FAIL lines; shell checks `tests/*_check.sh`. Callee-saved ABI: `tests/callee_saved_probe.sh` (Linux, needs gcc; sentinels in rbx,r12-r15 survive plain/throwing calls; also runs `tests/check_callee_saved.py <file.s>`, a structural save/restore checker, usable on windows_gnu asm too). Sweeps compare output across configs (everything on, shipped, register-form only, everything off). Compile ONE program at a time per compiler tree (shared scratch files).

## Targets
- `linux`: AT&T, SysV (rdi,rsi,rdx,rcx,r8,r9; xmm0-7; `%al` = xmm count for varargs). The only fully execution-verified target.
- `windows_gnu`: AT&T, win64 ABI (rcx,rdx,r8,r9; 32-byte shadow space), mingw-w64. Assembles/links; run under Wine in older rounds, recent register-form/bitwise/pool work NOT run.
- `windows` (MASM/Intel): `isWindows()` true ONLY here. Structurally present, never assembled with MASM; emitted text mixes NASM/MASM operand syntax; every Intel form is unexecuted. The float pool, `R_LDI/STI/LDXI/STXI` etc. have no/unexecuted Intel form.
- Two flags: `isWindows()` = syntax (MASM only); `isWinAbi()` = win64 ABI (both Windows targets). Use `argReg(i)` for argument registers, never ad-hoc `isWindows()` (that bug hit windows_gnu before).

## Execution model
Stack form: bytecode push/pop = real `push`/`pop`; no abstract value stack. Register form (`R_*`, from RegisterFormPass) is layered on top. Struct/array literal construction runs are packed by `precomputeConstructionOffsets`/`assignConstructionBlock`/`emitAssignRepack`/`emitNewRepack` (layout tokens `m<n>` member, `p<n>` padding, `a<elem>x<n>` array, added by LowerOrderGenerator).
Block layout of a >8-byte value on the stack: word k (bytes 8k..8k+7) at rsp+(T-1-k)*8, natural byte order inside a word. All element/field extraction (`LOOKUP_ARRAY`, `DOT`, `extractWordsFromReversedBlock` with `shrd`) depends on it. Odd sizes 3/5/6/7 have no x86 move: `storeOddSize`/`storePiece`/`rotReg`. `lastValueBlockSize`/`pendingBlockSize` pass the block size from a push to the following `DOT`/`LOOKUP` (set by `PUSH`, `DEREF`, `LOOKUP_DYN` value form, pointer-base `LOOKUP_ARRAY`).
Frame: `FUNC_START` pushes rbp; one `ALLOC` per function (rounded to 16). `gt_routine_address` is ALWAYS rbp-8 and `gt_error_message` rbp-16 (in throw programs); parameters follow; the callee-saved save area is added BELOW the locals.
Calls: `emitAlignedCall` keeps rsp 16-aligned at `call`. The alignment slot is reserved BEFORE arguments are pushed (sized for stack-passed bytes, `alignPadFor`: rsp must be 0 mod 16 before `call`); the pre-alignment rsp is saved in a stack slot (`8(%rsp)`), never in a register (callees clobber r13). Stack-passed args: first one at the lowest address (`reverseStackArgWords`); they are discarded after the call. `CC_START`/`CC_END` bracket a call and own an output buffer; nested calls push/pop the enclosing call's already-loaded argument registers (`loadedArgRegsStack`, `noteArgRegLoaded`; xmm0 result stash in r10, `floatResultInR10`). `CALL __drop_*` outside a bracket uses `emitDropGlueCall`.
Variadic: `PROMOTE_F32_TO_F64` (scratch `rfXmmA()`), `VARARGS_XMM_COUNT` sets SysV `%al`, `DUP_TOP` duplicates a float vararg into the int register for win64.
Struct-by-value PARAMETERS are broken (PUSH ARGn takes one register whatever the size); the front end rejects them, so unreachable.

## Register partition
rax/rbx/r11/r12 = temps `%t0..%t3`; r15 = `%s` scratch (`RF_SCRATCH`); r10 = INVOKE target, float-result stash, blocked-function repack; r13/r14 = scratch in `NEW*`, `CLONE`, `RESIZE*`, wide `DOT`, `LOOKUP_ARRAY`, `emitShiftCore` stash. Variable registers `RF_VAR_REGS = {r13,r14,r12,r8,r9,r10}` = `%v0..%v5`; `%v2`=r12 only if the function never uses `%t3`; r8-r10 are caller-saved (promotion pass only gives them to values not live across any call, and bans r8/r9 when an `ARGk`, k>=2, appears, r10 with a float stash). Invariant: a `%v` or `%t` register holds its value zero-extended to 64 bits. `FUNC_END` throws if a function keeps `%v0/%v1` and also uses r13/r14 as scratch (`rfClobberSeen`).
Float: variable regs `%x0..%x5` (SysV xmm8-13, win64 xmm6-11); temps `%y0..%y3` (SysV xmm4-7, win64 xmm12-15); scratch SysV xmm14/15, win64 xmm4/5. SysV has no callee-saved xmm, so every call spills/reloads all xvars (`xvSpillAll/xvReloadAll`; `R_XRELOAD` after `@catch_` labels); win64 xmm6-15 are callee-saved.
Callee-saved: `finishCalleeSaved` at `FUNC_END` scans the function text for rbx, r12-r15 (win64 also rdi, rsi, xmm6-15), grows the `ALLOC` by a save area, saves after the prologue, and turns every `@@CSR@@` mark (emitted by `emitFunctionEpilogue` and `GT_UNWIND`) into the restores. r8-r10 need no save. Never use a callee-saved register in generated code without going through this (the text scan handles it automatically).

## Mnemonic groups -> X86Backend `case`s
- Frame/data: `FUNC_START/END`, `ALLOC`, `ALLOC_STATIC`, `GLOBAL` (alias inits folded into parent block; float init as IEEE bits), `STRING`, `STRUCT_PADDING`, labels, `ASM_START/END`.
- Stack form: `PUSH` (slot, literal incl. unsigned >2^63, char, `null`, string id, global, function name via `declaredFunctionNames`, `ARGn`/`FARGn`), `ADDR`, `ASSIGN`, `ATOMIC_PUSH/ASSIGN/SWAP`, `POP`, `DUP_TOP`, `STACK_LOCK`; `*_INT` arithmetic and compares (unsigned), `SDIV_INT/SMOD_INT/SLT*/SGT*` (sign-extend; divisor -1 guarded), `*_FLOAT` (f32 and f64 by size), `FLOAT_CHECK`, `NEG/NEG_FLOAT/INC/DEC*`, `AND/OR/NOT`, `BITS_AND/OR/XOR/NOT`, `SHL/SHR/SAR` (`emitShiftCore`), `SEXT/ZEXT/TRUNC/FCONV`.
- Shift rule (all forms): count is unsigned of its own width; count >= width gives 0 (SAR: sign fill); no hardware masking (`cmp $64; sbb; and` for SHL/SHR, clamp to 63 for SAR; constant counts folded at compile time; rcx saved by push/pop).
- Memory/aggregates: `NEW`, `NEW_DYN/NEW_UDYN/NEW_FROM_STRING`, `RESIZE/URESIZE` (fill is elemSize bytes; wide fill via `emitResizeWideFillCopy`), `CLONE`, `DEREF`, `ADDR_OF`, `LEN`, `LOOKUP_ARRAY[_LHS]`, `LOOKUP_DYN[_LHS]`, `DOT[_LHS]`, `PUSH_FIELDNAME`, `MEMCOPY`.
- Calls/control: `CALL`, `INVOKE`, `EXTERN`/call, `CC_START/END`, `PUSH_RET_INT/FLOAT`, `RET/RET_FLOAT`, `JMP`, `CMP`, `PUSH_LABEL`, `YIELD` (`sched_yield`), `SLEEP name type` (pop arg, call named `@sleep` function, push result).
- Ghost table / unwinding: `GT_INIT/GT_REGISTER/GT_ALIVE_CHECK/GT_DESTRUCT` call fixed literal symbols `gt_init`, `gt_register`, `gt_alive_check`, `gt_destruct` (front end forces those names); `GT_REGISTER` keeps the pointer on the stack across the call. `GT_DESTRUCT $off` reads a frame slot, `GT_DESTRUCT_ADDR` pops an address and dereferences once. `THROW` is a no-op marker. `GT_UNWIND [MSG]`: epilogue, discard return address, load the CALLER's `-8(%rbp)` and jump; `MSG` first copies this frame's rbp-16 into the caller's rbp-16. `EXIT` = `exit(1)`, `EXIT_THREAD` = `pthread_exit(NULL)`.
- Register form: `R_MOV/BIN/UN/BRF/BRC/PUSH/PUSHA/LD/ST/LEA/RMW/SETV/ARG/ARGA/FARG/RET/RETF`; indexed global access `R_LDI/R_STI` (ints) and `R_LDXI/R_STXI` (floats, scale = width); float `R_FBIN/FBINX/FCMP/XTOG/GTOX/LDX/STX/POPX/GETRETF/XVAR/XRELOAD/XMOV`. `R_BIN` ops: arithmetic, compares, BAND/BOR/BXOR, SHL/SHR/SAR. `R_BRC` emits cmp + the INVERSE-condition jump (immediate first operand is swapped with the condition mirrored; two slots go via r15). `R_LEA %t base idx scale [disp]` (dynarray header is 16 bytes: `[len][cap][elems]`). Narrow loads zero-extend, narrow stores truncate, narrow `R_BIN` ADD/SUB/MUL results are NOT masked in the register. Float immediates come from a read-only pool (`.LFC<k>`, `.rodata`/`.rdata`, AT&T targets only, zero via `xorps`; MASM keeps `movabs`+`movq`).

## Known gaps and traps
- MASM target unverified/probably not assemblable; windows_gnu not run since the register-form, bitwise, float-pool and indexed-access work.
- Struct-by-value parameters (above). `PUSH n ARGk` reads the whole register at entry; `argReg(idx)` falls back to `rax` out of range.
- Original `PUSH` lines use rax/rbx as scratch, so a flush under a live temp must use `R_PUSH/R_PUSHA`. Inside a construction run, fields are stored below the current rsp: never `push`, `rep movsb` (rdi/rsi/rcx) or call helpers that touch the stack there (`pushBlockFromFrameConstructionAware` copies via rax).
- `findRunStart` only knows PUSH/ATOMIC_PUSH/STACK_LOCK/nested NEW as construction-run members.
- `rcx` may hold an already-loaded 4th argument (SysV): any code using `%cl` must save/restore it. `%xmm0` is both float arg0 and the float return register.
- A catch ending in `continue` leaks one operand-stack word per throw (accepted). Float variable registers are refused at a `@catch_` entry by the inliner (reload only comes from home slots).
- `LOOKUP_ARRAY` of a fixed array of exactly 8 bytes is a known crash (`PUSH 8` looks like a pointer); arrays under 8 bytes are tagged (`ra`, `t8`) and work.
- Scratch hazard: arguments are popped into their ABI registers as soon as each is computed, so any instruction that can run mid-argument-list (`LOOKUP_ARRAY`, `DOT`, repack helpers, `assignConstructionBlock`) must NOT touch rdi/rsi/rdx/rcx/r8/r9 (or xmm arg regs) without saving them. Use r13/r14/r15 (never argument registers) as scratch.
- A void function that falls into `FUNC_END` without a `RET` must still zero `rax` (else `printf`'s return leaks out as the exit code); `FUNC_END` does this, keep it.
- Variadic calls: only true varargs get `PROMOTE_F32_TO_F64` (not the fixed prefix); SysV needs `%al` = float registers used (`VARARGS_XMM_COUNT`, also on the stack-overflow call path); win64 needs a register-passed float vararg duplicated into the integer register (`DUP_TOP`).
- Overlapping block copies (wide `DOT`/`LOOKUP_ARRAY` extraction shrinking a block in place) must copy in the direction that does not overwrite unread source words; the shrink is by whole words.
- Stack-passed arguments: the function reads the first at `16(%rbp)` (+32 shadow on win64); both banks overflow (int past 6/4 registers, float past 8/4) and each stack word is 8 bytes whatever the type.
