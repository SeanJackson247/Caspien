# CLAUDE.md -- BytecodeParser (shared bytecode representation)

Package `caspien.bytecode` (`BytecodeToken`, `BytecodeStatement`, `BytecodeProgram`, `BytecodeParser`, `BytecodeSerializer`, `Text`), used by `ASTGenerator/` (builds a `BytecodeProgram`; `Main` serializes), `Optimizer/`, `LowerOrderGenerator/` and `Codegen/` (`Main` parses the LOB once, the backend walks the `BytecodeStatement`s); `README.md` has the rules. Sources only: each stage compiles `../BytecodeParser/src/main/java` into its own `out/` (rebuild all four after a change here). Imports no stage. Per stage only the entry class calls parser/serializer (`Optimizer`, `LowerOrder`; `Main` in ASTGenerator and Codegen); passes build generated lines with `BytecodeStatement.fromText`. `BytecodeProgram`/`BytecodeStatement` are wrappers that own a private list (composition): `size/get/set/add/addAll/remove/removeIf/indexOf/sort/stream`, `slice(from,to)` = COPY, `removeRange`, `asList()` = live `List` view for List-typed APIs; there is no `subList` (a copy would silently break `subList(..).clear()`). The format carries HOB and LOB alike. Check: `tests/bytecode_phases_check.sh`.

`Text` (15 Oct): the hand-written replacements for every `java.util.regex` / `String.split` / `replaceAll` / `matches` use in the compiler (no regex anywhere in the Java: isDigits, splitArrayType, containsWord, split, splitSpace, stripSuffixAtEnd ...; each method says the pattern it replaces). Root `Compiler*.java` are compiled alone, so they use the trimmed copy `CompilerText.java`. Check: `tests/text_helpers_check.sh` (fuzzes every helper against the real regex).
